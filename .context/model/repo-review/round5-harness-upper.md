## Scanner false positives and false negatives

1. **`one-way-deps` counts spec and fixture imports as module dependencies** (all 25 hits). `cdd_guidance/practices/clean_engineering/model/graph_reading.py:52` adds `module.dependencies` for every file, `*_spec.py` and `fixtures/` included. The names fact (:106-109) skips test code, but the `dependsOn` edges do not. `rules/practice_wide_rules.py:30` then reports cycles of 8 to 47 modules (graph ↔ guidance / agent_tools / installation / mcp; guidance ↔ agent_bdd / bdd / clean_engineering / sample_tool / split_tool; guidance_actions ↔ sketch / document / generate). None is a production import: no lower harness module imports harness/guidance or harness/graph, and harness production imports nothing from cdd_guidance, space, or tools with an import statement.
2. **The same scanner misses the real dependency.** Harness reaches cdd_guidance through `importlib.import_module` strings and paths (H1), and the import reader does not see them. This is a false negative.
3. **`_examples` and `fixtures` folders are scanned as production.** `harness/graph/skipped_folders.py:11-34` skips neither. This causes the cycle hits in `harness/graph/_examples/input/src/*` and the `state-change-returns-record-or-named-failure` hits on `_examples/*.ts`. `is_test_code` (`cdd_guidance/practices/clean_engineering/model/rules_shared/typed_and_comments.py:17-18`) does not treat `fixtures/` as test code.
4. **The per-file rules judge spec files.** `never-swallow-exceptions` and `use-exceptions-properly` (harness/chat/chat_spec.py `_check_in_repeatedly`) and `errors-out-of-existence` (harness/graph/graph_spec.py `tree_named`) never call `is_test_code`.
5. **`deep-module` false negative** (`rules/practice_wide_rules.py:90` and `:117`). Fixture classes count in harness/guidance's denominator (36 rather than 24). `_importers_by_name` sees only importers inside the validated paths, so harness/guidance measured 12 of 36 (33%) when the true figure is 15 of 24 (62%, M14). On a path-scoped validate the measure cannot see the callers that make a class public.
6. **`eliminate-duplication` matches only identical bodies** (`model/rules_shared/operation_checks.py:298-310`, the `body_fingerprint` equality). It misses the near copies in M6 and M10.
7. **`use-explicit-dependencies` flags constructing `Path`** (`operation_checks.py:97-104`, 8 hits: ApproachPage, Brand, FidelityTemplate, CatalogProject, DesignCanvas, CanvasVersions, CddDiagnosticFixtures, ProbeArguments). `Path` is a value, not a collaborator.
8. **`prefer-instance-operations` flags factories**: `CatalogPractice.load_all`, `Utility.load_all`, `LifecycleAction.load_all`, `ProjectApproach.for_project`, `Source.whole_file`, `Violation.at_node`, `GuidanceCollection.child` (the factory `MarkdownCollection.from_markdown` calls), and `CanvasVersions.in_session_folder`. The rule exempts `load`/`loadXxx`, but the scanner's static-factory name list in `operation_checks.py` does not accept snake_case `load_*`.
9. **`use-intention-revealing-names` flags `value` in Python property setters** (8 in guidance.py, plus graph.py, model_node.py, and rule.py). The setter exemption (`operation_checks.py:84-86`) does not fire for Python `@x.setter`.
10. **`never-swallow-exceptions` / `use-exceptions-properly` on the diagnostics probes** (`agent_tools_probe.py:141,179`; `guidance_probe.py:87,97,110`). A probe's job is to turn any failure into a red `ProbeOutcome` that names it, so it records the failure rather than swallowing it. The catalog template JavaScript (`catalog-foundry-skill-nav.js`, `catalog-nav.js`, `catalog-monaco.js`: 19 hits) falls back when browser storage or a URL parse throws, which is the documented browser-storage pattern.
11. **`errors-out-of-existence` on `Graph.practice`, `practice_of`, `_held_practice`, and `PracticeCatalogue.practice_class`.** A misspelt practice key is a broken call, so raising the named `UnknownPractice` is correct. The same holds for `FidelityGuidance.new_report_path` (`FidelityWithoutSessionError`).
