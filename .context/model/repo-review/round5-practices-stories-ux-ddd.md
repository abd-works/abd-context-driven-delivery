## The two questions asked

**Does each format adapter use the one domain model?**
- **Stories: yes.** Every format copies the canonical map into its own subclass. Markdown, JSON, sketch, draw.io and Miro use `type(self)(story_map)`, and the code formats use `_copy_of`. The old suffix switches on `StoryModel` are gone (`StoryModel.load`, `_story_map_file`, `story_test_type`). `Stories` now picks the adapter from `formats` (`stories.py:195-207`).
- **UX: yes.** Every format is a `UxMap` subclass that converts through `UxMap.copy_of` (`ux_map.py:80`) into its own node types (`screen_type`, `region_type` and so on). `HtmlUxMap` now subclasses `JsonUxMap`. `cli_state` moved onto `DrawioUxMap`.
- **DDD: not at the class level.** The sketch, markdown and draw.io maps all share one map model. But that model is the *markdown* map: `DrawIOBoundedContextMap` and `SketchDddModel` subclass `MarkdownBoundedContextMap`, and the base `BoundedContextMap` cannot save anything. Python, TypeScript and the draw.io class view still go through a copy:
  - `class_model()` builds a new `CleanEngineeringModel` and new `Module` objects, and `ClassCard.code_class` clones each card into a plain `OoadClass`.
  - `read_class_model()` and `_code_card` clone them back.
  - `clean_engineering_bridge.py` is deleted, but its job now lives in these methods. See H1 and M1.

**Is anything duplicated left after DDD's draw.io moved onto Clean Engineering's diagram classes?** The rewrite is real.
- `DrawIOAggregateModel`, `_DiagramWriter`, `ContextLayout`, `_ContextMapReader`, `_AggregateViewReader`, `DrawnDiagram` and the `arrow_style`/`DiagramCard` borrowing are all gone, and no live code names them.
- The map draws through `DrawIOCleanEngineeringModel` and `DrawIOModule`, and integration labels ride on Clean Engineering's own `dependency_labels`.
- What is left:
  - **The class view converts the map twice per render.** The map is copied into a plain class model (`class_model()`), then Clean Engineering's draw.io copies that again into its own classes (H1).
  - **A module's kind is written as its purpose text and read back by string compare** (M3).
  - **The member cap is set twice:** a one-attribute subclass and a constant both limit the members to 10 (L1).
  - **Module nesting is spelled with "/" in names.** This is a known skip.
  - **The class model the draw.io format holds is used only as a renderer** (L7).
