## What would make this area's next round cheaper

1. **Do not pass the metrics gate by moving logic off the object.** The round-8 fix kept class sizes down by writing new logic as module functions handed one class's state (ten new ones, R9-8) and by handing the class name down four layers instead of letting the `Operation` know its owner (R9-3). The gate cannot see either, and both are the guardrail's "parameters the object could hold". A fix brief should ask, for each new function, "whose state does it read?", and put it there.
2. **When a mixin reads a whole source, give the read its own part.** `GraphReading` and the markdown card document both keep one read's state in dicts passed between methods and in private fields of other objects (R9-1, R9-4); the graph hotfix added another whole-graph pass to the same mixin (R9-2). A per-read object made once per read would hold those dicts, and new passes would land on it.
