## Analysis

### Symptom
Agents that should invoke `/{context-tool}.{fidelity}`, `/action`, or `/utility` via the deployed slash/skill catalog instead fall into a rediscovery loop: grepping for `PYTHONPATH`, remanifesting from `@toolset-manifest` headers / `python -m tools manifest …`, reading toolset `.py` to learn the invoke path, and inventing request files. The happy path (pipe the YAML fence to stdin → `run -` → follow response) exists but is not strong enough as the *only* obvious path.

### Intended contract
1. Open only the slash command / skill (deployed catalog).
2. Treat that file as the catalog — it already contains the filled YAML fence.
3. Pipe the fence to stdin via `.\tools.ps1 run -` (Windows; sets venv + PYTHONPATH) or equivalent.
4. Follow `response.instructions` from the run result.
5. Do **not** remanifest, write `_req.yaml`, grep PYTHONPATH, or read implementation source for invoke instructions.

## Diagnosis

### Category
**BOTH** — prompt/template gaps layered on published-protocol / generator code that still advertises remanifest and incomplete invoke stanzas.

### Root cause hypothesis
The agent-facing catalog text generated by `primitives/harness/bodies.py` is an incomplete encoding of the intended contract:
1. Bodies emit `python -m tools run -` but not `.\tools.ps1 run -`, so Windows env failures push agents to rediscover PYTHONPATH / venv.
2. Bodies omit "Follow response.instructions" (present on source headers), so agents invent behavior or open `.py`.
3. Guidance AskQuestion points at `context_tools/actions` on disk.
4. Published toolset manifests still ship `read_manifest` / `request.yaml` invoke wording, contradicting "do not remanifest / do not write a request file."
5. Agent-bdd helper `run_manifest_from_header` reinforces remanifest-from-source for product-like flows.

Together these make the manifest→invoke seam discoverable as *one* option among several, not the only enforced path — so agents fall back to archaeology (the #45 disaster mode).

### Why not prompt-only
Fixing CliAgent launch-report copy (#44-era framing) cannot repair harness body generation or published `read_manifest` protocol. Generator + signature builder must change.

### Why not code-only
Even with a perfect runner, slash/skill prose that omits tools.ps1 / follow-instructions / still points at source trees will keep agents rediscovering.

### Diagnose tool
Not used — cause is unambiguous from bodies.py vs deployed commands vs catalog manifests vs module-context contract.
