# Where the defective code came from — release 1.2 (2026-11-22)

## Summary

- 133 of the 156 defect files were traced to the function they name, and from there to 77 commits. For each function, `git blame -w -M -C` was run on its lines as they stood before testing began (the parent of `78c8d0321`), and the commit that wrote most of those lines is taken as the commit that produced the defective code.
- 57 of the 77 commits were matched to the Claude Code chat that made them, by finding the commit's identifier in a chat transcript within 30 minutes of the commit. The transcripts record every guidance call with its arguments and every sub-agent launch, so they are the main evidence. 20 commits have no matching chat.
- The largest single source is the refactoring rounds: 21 commits holding 40 of the traced defects were written in three chats that sent sub-agents to fix Clean Engineering findings. The sub-agents' guidance calls were `validate` at Clean Engineering modules, model and code; they called no `generate` and named no Stories or BDD fidelity.
- 14 commits (24 defects) were made within 12 hours of a `generate` call at Stories scenarios or acceptance tests in the same chat; 12 of them (19 defects) in feature chats, 2 in the fix session. 2 commits (6 defects) follow a call that named BDD development. BDD behavior, BDD realization and UX front-end code were not named in any call in the 12 hours before any sampled commit.
- 11 commits (20 defects) were made in chats with no `generate` and no `validate` call in the 12 hours before: plain chat coding. They hold most of the `concurrency` and `raw-error` defects (the record of test runs, ticket names, closing a ticket).
- No sampled defective function is shown to have been written by `render`. Render to a code format was called before 2 commits, on other files.
- Tests were usually present: 54 of 77 commits also changed a spec in the same module, 27 a story test or scenario file, 22 a heavy spec. Only 11 commits changed no test for the area. What those tests checked was not read.
- The TDD supplement did not exist for 47 of the 77 commits (it was added 2026-11-15 20:41 UTC). Its rule `flow-chosen-before-code` was added 2026-11-16 17:59 UTC; 18 sampled commits came after it, and no TDD slug was named in a guidance call in the 12 hours before any sampled commit.
- Session logs were kept in git from 2026-11-04 until commit `f2add13bf` (2026-11-18) deleted them; they were read from that commit's parent. Most of their `tool generate.generate` lines do not keep the guidance argument, so the chat transcripts were used to say which fidelity a call named.
- Nothing before 2026-10-26 can be tied to a chat: 6 commits (8 defects). The schema, rule and offered-format lines behind most `rule-template-mismatch` and `undeclared-output` defects are also that old (commit `1652d526b`, 2026-10-19).

## How the evidence was read

- **Introducing commit.** The commit that wrote most lines of the named function as it stood when it was tested. For a function reshaped by a refactoring round this is the refactoring commit, not the first commit that ever held the function; where the two differ the older behaviour may have been carried through unchanged, which blame cannot tell apart.
- **Chat.** The chat whose transcript shows the commit's identifier within 30 minutes of the commit's time. Transcripts are in `C:\Users\jeffa\.claude\projects\`, one folder per checkout, with each sub-agent's transcript in a `subagents` folder under its lead chat.
- **Guidance calls.** Calls to the cdd server's `generate`, `validate`, `render` and practice instruction tools, and skills of the same names, made by the lead chat or its sub-agents in the 12 hours before the commit. This says what the chat was doing, not that the call was about the defective file. The stricter measure, a `validate` call whose paths name the defective file within 24 hours, is given separately.
- **Who wrote the file.** Edit and Write calls on the defective file in the 24 hours before the commit, in the lead chat's transcript or in a sub-agent's.
- **Test added with it.** Whether the same commit changed a spec in the same module (`*_spec.py`, `*.spec.ts`), a story test or scenario file (`story_tests/**`, `*_story.test.*`, `*.story.*`), or a heavy spec (`*_heavy_spec.py`).
