## How a failure gets into session.err, and how a Fix button gets onto the screen

**session.err is written in one place.** [harness/mcp/mcp_server.py:884-902](C:\dev\abd-cdd-release-1-2-fixes\harness\mcp\mcp_server.py#L884) wraps every MCP tool call in `except BaseException: self._log_failure(call, failure); raise`. `_log_failure` asks the call for its session and calls `Session.log_failure` ([space/session/session.py:633](C:\dev\abd-cdd-release-1-2-fixes\space\session\session.py#L633)), which appends the trace through `SessionLog.append_trace` ([space/session/session_log.py:283](C:\dev\abd-cdd-release-1-2-fixes\space\session\session_log.py#L283)) and writes an `error <tool> session.err <line>` line to session.log. The failure is then raised again, so the MCP caller gets an error result. Every entry in all three files came through this path (top frame `_answer_between_restarts`). So nothing in session.err was swallowed; the question for each entry is who the MCP caller was and what it did with the error result.

**A Fix button appears only when a UI caller decides to show one.** Nothing turns an MCP error into a button on its own:

- The chat bar's failure line ([harness/chat-ui/pane/hooks/error-display/failure-view.tsx](C:\dev\abd-cdd-release-1-2-fixes\harness\chat-ui\pane\hooks\error-display\failure-view.tsx)) shows whatever `showFailure` / `shownAsFailure` ([failure-client.ts:62-71](C:\dev\abd-cdd-release-1-2-fixes\harness\chat-ui\pane\hooks\error-display\failure-client.ts#L62)) put in the `cdd-board/failure` atom, plus the prompt queue mod's own latest failure ([tools/prompt_queue/hooks/queue/prompt-queue.ts:845-849](C:\dev\abd-cdd-release-1-2-fixes\tools\prompt_queue\hooks\queue\prompt-queue.ts#L845)). - The Files app keeps its own Fix buttons through `FilesNotices.fail` ([harness/files_app/app/files/files-notices.ts:29-35](C:\dev\abd-cdd-release-1-2-fixes\harness\files_app\app\files\files-notices.ts#L29)), shows each distinct failure text once, and also sends it to the chat bar when the page was opened with a chat.
- **The agent's own tool calls never raise a button.** The error goes back to the agent as the tool result. `postToolUseFailure` is a known hook event ([harness/hooks/hooks.py:62](C:\dev\abd-cdd-release-1-2-fixes\harness\hooks\hooks.py#L62)) but no handler listens to it, and the chat bar does not read session.log's `error` lines.

### Two defects in how session.err itself is written

- **session.log points at the wrong session.err line when two failures land at once.** `append_trace` counts the file's lines, then appends, with no lock ([session_log.py:289-294](C:\dev\abd-cdd-release-1-2-fixes\space\session\session_log.py#L289)). At 21:00:02, session.log line 330 points `session.guidance_selection` at session.err line 128, which holds the `ticket.root_files` trace; the real entry starts at line 151. It also re-reads the whole 2 MB file to count lines on every failure, which made the 828-trace flood slower than it needed to be.
- **A failure goes unrecorded when the call has no session, or the session's checkout is gone.** `_log_failure` does nothing when `call.session` is None ([mcp_server.py:899-902](C:\dev\abd-cdd-release-1-2-fixes\harness\mcp\mcp_server.py#L899)). `append_trace` returns 0 without writing when the checkout is gone ([session_log.py:285-286](C:\dev\abd-cdd-release-1-2-fixes\space\session\session_log.py#L285)), and the log line then points at line 0. In both cases the failure is still raised, but no trace is kept anywhere.

## Recommended fixes, most valuable first

1. **Show the health report's real failure with a Fix button.** In `askServer`, keep "tools missing" for a server that does not know `server-health.report`, and for a tool that ran and raised, call `shownAsFailure` with the server's message. Today a corrupt test record tells the person to reinstall, which cannot fix it.
2. **Write the test-run record so a power loss cannot zero it.** Flush and `fsync` the file written beside it before `os.replace`. Then delete or repair `C:\Users\jeffa\.cdd\dev\test-runs.json`, which is all NUL bytes now and fails every health read.
3. **Give the agent's own tool failures a Fix button when they are defects, not refusals.** Register a `postToolUseFailure` hook, or have the chat bar read new `error` lines in session.log, and show a failure when the exception is not one of the named refusals (`PromptNotQueued`, `GuidanceTurnedOff`, `UnknownRule`, `UnknownGuidance`, `*NotFound*`). Raw `FileNotFoundError`, `PermissionError`, `RepoConnectError`, and worker crashes should reach the person; today they reach only the agent.
4. **Stop the Files app from retrying a permanent refusal, and resolve its session in the right project.** Stop the guidance follow loop after `SessionNotFoundError` or `TicketNotFoundError`, and make the Files server's calls name the project the page was opened on. That removes 834 of the 884 traces and the 2 MB of noise.
5. **Make session.err pointers trustworthy.** Take a lock around counting lines and appending in `append_trace`, and keep the line count rather than re-reading the file. When the call has no session or the checkout is gone, write the trace to the server's own log, so no failure goes unrecorded.
