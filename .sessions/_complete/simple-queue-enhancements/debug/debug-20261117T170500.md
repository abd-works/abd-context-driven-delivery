# Prompt queue cannot reach prompt-queue tools: `install.py --pin-runtime` on the dev lane never points the worktree's chats at the dev lane

## Failure

```
The queue did not change: prompt-queue: $.mcp.call: no connected MCP tool "prompt-queue.show" on a server named "plugin:cdd:cdd"
Context: Calling prompt-queue.show on the cdd server, tried as cdd then plugin:cdd:cdd
```

Shown in the prompt queue's box above the chat bar, in the chat working in `C:\dev\abd-cdd-simple-queue-enhancement`. Seen before and after `/reload-plugins`, and again after the dev lane was repinned to this branch. Its Fix button (new on this branch) started this debug.

## Cause (as found)

- The queue mod (`tools/prompt_queue/hooks/queue/prompt-queue.ts`, `SERVERS = ['cdd', 'plugin:cdd:cdd']`) calls `prompt-queue.*` on a server named `cdd` first, then on `plugin:cdd:cdd`.
- `plugin:cdd:cdd` is the user-level cdd plugin, the stable lane (`~/.cdd`, port 47800, pinned to main `c7a3b2b57`). Main has no `tools/prompt_queue/prompt_queue.py` (`~/.cdd/runtime/tools/prompt_queue/prompt_queue.py` does not exist), so its tool list has no `prompt-queue.*`, and Claude Code refuses the call client-side.
- The dev lane (`~/.cdd/dev`, port 47801, pid 22408) serves this branch at `48a462bcf` and does have `tools/prompt_queue/prompt_queue.py`.
- A chat reaches the dev lane's own tool list only through a `cdd` entry in the worktree's `.mcp.json`, written by `McpInstallation._write_dev_lane_entry` (`harness/mcp/mcp_server.py:151`). That runs only in a full install (`_write_claude_plugin`). `python scripts/install.py --ide Claude --pin-runtime` takes `_switch_server_only` (`scripts/install.py:131`), which never writes it. **This worktree has no `.mcp.json`**, so the chat holds no `cdd` server and the call falls back to the stable lane.
