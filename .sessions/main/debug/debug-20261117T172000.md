# Prompt queue on main calls prompt-queue.show, which main's cdd server does not have

## Failure

```
The queue did not change: prompt-queue: $.mcp.call: no connected MCP tool "prompt-queue.show" on a server named "plugin:cdd:cdd"
Context: Calling prompt-queue.show on the cdd server, tried as cdd then plugin:cdd:cdd
```

Shown in the prompt queue above the chat bar in the main checkout's chat, after the stable lane was repinned to main at 20a564869.

## Cause

- The queue mod on main (`tools/prompt_queue/hooks/queue/prompt-queue.ts`) now keeps the queue on the server: it calls `prompt-queue.*` on `cdd`, then `plugin:cdd:cdd`.
- The server half, `tools/prompt_queue/prompt_queue.py` with its specs, exists only on the `file-manager` branch (84 commits ahead of main) and on `simple-queue-enhancements` (88 ahead), which merged file-manager in. Main has no `tools/prompt_queue/*.py`.
- So the stable lane, pinned to main, publishes no `prompt-queue.*` tool, and Claude Code refuses the call before it reaches the server.
- The same failure in the worktree chat is reported in `.sessions/simple-queue-enhancements/debug/debug-20261117T170500.md`. There the cause was the dev-lane `.mcp.json` entry, fixed on that branch in 3ce6f8f4e. Main's chat uses the stable lane, so it needs the server half on main.

## Session

- Session main, branch main, HEAD 20a564869 (level with origin/main).
- Stable lane `~/.cdd/runtime.json`: pinned, main, 20a564869, cdd server pid 30092.
- OS: Windows 11 Home 10.0.26200.

## Fix options

1. Merge `simple-queue-enhancements` (which holds file-manager) into main, then repin the stable lane.
2. Merge only `file-manager` into main, then repin.
Either one brings other sessions' unreleased work to main, so it needs the person's choice.
