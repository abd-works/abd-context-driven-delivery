# Handoff — One way to show every failure: tools/error_display and the chat bar's failure line (2026-11-14)

## Outcome
The user asked that every failure in the chat bar, an app that does not open and every exception the mod now swallows, be shown the same way: what failed, the context it failed in, and a Fix button that sends both to the chat. This session started that work and parked it as a patch, `.sessions/main/error-display-wip.patch`, so main stays clean. The next session opens its own ticket, branch, and worktree (`ticket.activate`), applies the patch there, and finishes it. Along the way the session found why the Kanban app "did not start": the running chat had an old chat bar loaded (old cached mod version), and after `/reload-plugins` the `app.open` call was refused by a declined permission prompt, so nothing ran.

## Key Learnings
The corrections document (`.sessions/_backlog/corrections.md`) holds only a note and no session block; these are the user's standing rules for this work:
- validate-chat-bar-before-publishing: `claude plugin validate .` in `harness/chat-ui/pane` before publishing; a refused module hides the whole chat bar.
- atoms-stay-in-their-file and no import loops: the failure atom lives in `error-display/failure-client.ts`, which imports nothing local, so any file can show a failure.
- contract-comes-from-the-adapter: the failure shape is generated from `tools/error_display/failure.py`; change the Python and install again, never hand-edit it.
- never-stash; ticket work in its own worktree via `ticket.activate`; quick checks only before shipping a visible fix; longer runs in a background subagent; short status.
