## Findings

| Question | Answer | Evidence |
|---|---|---|
| Host locally? | Yes | Tested with a small Python server on 127.0.0.1:8777 |
| Open in the Claude Browser pane? | Yes; pages can be read, clicked and measured. `.claude/launch.json` with a `url` adds it to the Dev servers menu | Page tested; `launch.json` from the docs only |
| Put commands into chat? | Not from a page alone. A small mod polls the server through `$.http.fetch` on `$.clock.every`, then calls `$.prompt.submit` or `$.prompt.fill` | Tested in real Claude Code 2.1.309, headless, from a terminal tab |
| Reach the MCP server Claude runs? | No: each chat holds a private stdio copy. An ordinary program can start its own copy | Tested from Python with the `mcp` SDK: 117 tools, `board.show` returned the real board |

Trial chain: Browser pane button -> local server -> mod -> `$.prompt.submit` -> new turn. Button pressed at about 13 seconds, turn finished by 14.0 seconds. The mod also posted its session id, so the board can target a specific chat.

## Recommended design

- React front end built from the canvas HTML.
- Express server holding one cdd MCP connection. Each board action calls the same tool the chat uses. Drop lowdb, because `.sessions/` is already the store.
- Thin mod of about 15 lines that registers the chat and passes commands in. `$.prompt.fill` when the user should review before sending.
- Python domain unchanged.
- Keep the story signatures; run the surface layer against the real DOM with Playwright or the Browser tools.
- Drop most of the 3,164-line pane, plus `harness/kanban/desktop_pane.py` and `desktop_pane.ps1`.
