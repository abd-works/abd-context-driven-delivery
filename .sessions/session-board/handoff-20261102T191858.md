# Handoff: seeing the session board from Remote Control

## Where it stands

All the build work is finished and described in `.sessions/session-board/handoff-20261102T171025.md`. Read that first. This handoff adds only what happened while the user tried to look at the board. Nothing in the code changed. `session-board` is not merged to `main`.

## What the user hit

The session runs locally on the PC `5080-PEC`, but the user reaches it through Remote Control. The Browser pane is unavailable in a Remote Control view, so opening the board there showed "Browser isn't available in remote control sessions". The user has not yet seen the real board.

The board server listens on `127.0.0.1:8778` and refuses any other Host, because its buttons commit, push, and type into a live chat. `127.0.0.1` only works in a browser on that PC. Tailscale, cloudflared, and ngrok are not installed.

## What was tried

- Sent a picture of the live board, and published a private snapshot page: https://claude.ai/artifact/GmrHZrSRyxdVq81HcuxWXi. It is a picture, so it does not update and nothing on it can be clicked.
- Tried twice to start a read-only proxy on `0.0.0.0:8779` that forwards only GET and HEAD. The auto mode permission classifier denied both as exposing a local service. Do not try a third time or route around it. The user decides whether to allow this.
- The proxy was never started or tested. Its script is `board-read-only.cjs` in this session's scratchpad, a temporary folder, so copy it somewhere lasting if it is wanted. Its `node` command has to be run by the user on the PC, after which `http://192.168.86.23:8779` should work on the home network. Windows Firewall already allows inbound `node.exe` on the Public profile.
