# generate.md — Instructions for generating output

Execute all three parts in order. Visibly strike off each item so the user can confirm every step was performed.

`rules/` always refers to the `rules/` sub-folder of the capability being generated.

## Part 1 — Read rules

- [ ] Read every file in `rules/` **in full** — no skimming, no summarising from memory, no skipping sections.
- [ ] Read all examples in `rules/<rule>/examples/pass/` and `rules/<rule>/examples/fail/` for every rule.

## Part 2 — Generate

- [ ] Follow every rule when generating output. Guide generation with all read rules.
- [ ] Review every **DO**, **DO NOT**, and example (pass/fail) in each rule — apply it line by line.
- [ ] Do not improvise structure a rule forbids or skip a constraint a rule requires.

## Part 3 — Validate output

Follow **both steps** in `reference/validating-output.md` exactly.
