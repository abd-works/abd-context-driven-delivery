Agentic tools that bring the best of agile product, delivery, and engineering practices into the age of AI.

Install

  1. Clone this repository into the project workspace, or as a sibling checkout the agent can see.
  2. In chat, run /install. That writes skills, rules, MCP, and hooks into the IDE path (.cursor for Cursor).

Open catalog/index.html for the board of practices, stages, and actions.

Basic usage

Name a practice and a action and optionally a format. The action is what to do. The practice is which view of the work.

/stories-map /generate /miro {{context}}  ← write the scenario files for that slice

/clean-engineering-code /generate /python {{context}}  <- write software craftmanship level code 

/ddd-tactical-building-block /validate {{context}}  <-- validate ddd elements pass all practice guidance rules

Iteratively sketch using multiple views

/stories /domain-driven-design /sketch  ← sketch the journey and the domain together, in short passes

Stages

Work moves through three stages. Stay on the current stage until that view agrees, then go deeper on one slice.

  • Discovery — outcome, journey, and architecture, still cheap to change.

Use the Discoverer agent to run discovery.

  • Specification — one increment: scenarios, domain behavior, and the experience.

Use the Specification agent to run specification.

  • Implementation — tests, touchpoints, and the solution on the target stack.

Use the Implementation agent to run implementation.

Practices

Tools that refine context in stages, according to a particular perspective.

  • Stories — actors, systems, and the interactions that deliver the solution.
    Use story-map, scenarios, acceptance-tests.
  • Domain-driven design — the business concepts and the boundaries that protect them.
    Use bounded-context, building-blocks, tactics.
  • Clean engineering — modules, contracts, and the code that can be generated and checked.
    Use modules, model, code.
  • Behavior-driven development — behavior tests written in the language of the domain.
    Use behavior, development.
  • User experience — how people move through and act on the solution.
    Use ia, mockup, front-end-code.

Actions

  • /partition — split context into an index and verbatim segments for each practice.
  • /document — document current state, without adding best practices or correcting it.
  • /sketch — grill in short passes and sketch only what each answer unlocked.
  • /grill — interview the plan against files you have read.
  • /generate — write the artifacts for a practice at its current stage.
  • /validate — check artifacts against the practice rules.
  • /satisfy — validate, apply the fixes, and validate again.
  • /render — convert generated content into another format.
  • /repair — open a repair on a practice and instruct the fix.
  • /iterate — revise the deliverable in small agreed slices.
