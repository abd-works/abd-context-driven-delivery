# cdd_guidance/patterns
A *pattern* is the extra guidance and rules for one kind of solution, laid over the practices: *LernDomainDriven* and *MernDomainDriven* build a domain-module TypeScript stack (lowdb or MongoDB, Express, React, Node) on an already-designed slice, both through *DomainDrivenStack*, whose guidance has the agent write the acceptance tests first with Stories and then the code they drive; *CddWebDomainAccess* is how code outside Python reaches the CDD domain through MCP tools and a generated language adapter; *CddClaudeMod* is a Claude Code mod that is a view of the CDD domain. Each is a *PracticeGuidance*, so its instructions install as a skill (`patterns-lern-domain-driven`, `patterns-mern-domain-driven`, `patterns-cdd-web-domain-access`, `patterns-cdd-claude-mod`).
Each pattern's guidance makes its *GraphOverlay* once and keeps it as `graph_overlay` (`LernOverlay` and `WebDomainAccessOverlay` in each pattern's `graph_overlay.py`; CDD Claude mod adds no nodes and keeps the base *GraphOverlay*); the overlay holds its pattern, asks the graph for the practices it adds to by their class (`graph.practices.loaded(Ddd)`), records the facts its rules read and gives the rules it adds to a practice, kept under `{pattern}/practices/{practice}/rules/`; `graph.set_overlays` turns a pattern on for a working copy. An overlay reads each file once into a file object whose operations are the facts its rules read — LERN's *TierFile* (and *AggregateFolder* for the facts about an aggregate's whole folder) in `lern_domain_driven/tier_facts.py`, web domain access's *AccessFile* in `cdd_web_domain_access/access_facts.py`. Each holds one Clean Engineering *SourceText* (`practices/clean_engineering/model/operation_metrics.py`) for its file, whose `line_of` and `hits` give the line each match starts on, so every fact a pattern records names its line and the file's text is wrapped once.

- **Purpose:** Add the guidance and the graph rules one kind of solution needs on top of the practices, without changing a practice.
- **Seam (terms):** each pattern's instructions (`lern-domain-driven`, `mern-domain-driven`, `cdd-web-domain-access`, `cdd-claude-mod`); each pattern's *GraphOverlay*, kept as `graph_overlay`; *DomainDrivenStack* for a new stack pattern
- **Dependencies (one-way):** `cdd_guidance/practices/clean_engineering` (*SourceText*, to read facts), `harness/agent_tools`, `harness/guidance` (*PracticeGuidance*), `harness/graph` (*GraphOverlay*, *PracticeGraphRule*). harness/graph's *PatternOverlays* makes each applied pattern once per process from the module its folder names, and the graph asks it for its overlay, so a pattern imports nothing of space or tools.

## Constraint

Add a new pattern as its own folder with a *PracticeGuidance* class and, when it checks code, a `graph_overlay.py` whose *GraphOverlay* the pattern makes once as `graph_overlay`; put a rule for a practice under `{pattern}/practices/{practice}/rules/`, never in the practice, so turning a pattern off removes its rules.
