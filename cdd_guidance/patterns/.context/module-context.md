# cdd_guidance/patterns
A *pattern* is the extra guidance and rules for one kind of solution, laid over the practices: *LernDomainDriven* and *MernDomainDriven* build a domain-module TypeScript stack (lowdb or MongoDB, Express, React, Node) on an already-designed slice, both through *DomainDrivenStack*, whose guidance has the agent write the acceptance tests first with Stories and then the code they drive; *CddWebDomainAccess* is how code outside Python reaches the CDD domain through MCP tools and a generated language adapter; *CddClaudeMod* is a Claude Code mod that is a view of the CDD domain. Each is a *PracticeGuidance*, so its instructions install as a skill (`patterns-lern-domain-driven`, `patterns-mern-domain-driven`, `patterns-cdd-web-domain-access`, `patterns-cdd-claude-mod`).
Each pattern that checks code adds a *GraphOverlay* in its own `graph_overlay.py` (`LernOverlay`, `WebDomainAccessOverlay`, `ClaudeModOverlay`), which records the facts its rules read and registers the rules it adds to a practice, kept under `{pattern}/practices/{practice}/rules/`; `graph.set_overlays` turns a pattern on for a working copy. Facts are read through Clean Engineering's *SourceText* (`practices/clean_engineering/model/operation_metrics.py`), whose `line_of` and `hits` give the line each match starts on, so every fact a pattern records names its line.

- **Purpose:** Add the guidance and the graph rules one kind of solution needs on top of the practices, without changing a practice.
- **Seam (terms):** each pattern's instructions (`lern-domain-driven`, `mern-domain-driven`, `cdd-web-domain-access`, `cdd-claude-mod`); each pattern's *GraphOverlay*, found by its folder name; *DomainDrivenStack* for a new stack pattern
- **Dependencies (one-way):** `cdd_guidance/practices/clean_engineering` (*SourceText*, to read facts), `harness/agent_tools`, `harness/guidance` (*PracticeGuidance*), `harness/graph` (*GraphOverlay*, *GraphPractices*, *PracticeGraphRule*). harness/graph finds an overlay by importing `cdd_guidance.patterns.{pattern}.graph_overlay`, so no module imports a pattern by name and a pattern imports nothing of space or tools.

## Constraint

Add a new pattern as its own folder with a *PracticeGuidance* class and, when it checks code, a `graph_overlay.py` that registers its *GraphOverlay*; put a rule for a practice under `{pattern}/practices/{practice}/rules/`, never in the practice, so turning a pattern off removes its rules.
