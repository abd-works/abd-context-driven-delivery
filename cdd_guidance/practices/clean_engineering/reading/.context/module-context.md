# cdd_guidance/practices/clean_engineering/reading
*GraphReading* is how Clean Engineering takes part in the knowledge graph: it reads a working copy's production code and model documents into class, module, operation, and property nodes, links each call to the member it reaches, and records the facts the practice's graph rules compare. It is the practice's `reading_type`, a *PracticeReading* of harness/graph.

Each production file keeps the classes it imports, re-exports, or reaches as `module.Class`, each with the module it names it from (*ClassReference*, read by *ScriptImports* alike for every file, read now or outside an edited-file scope); *ImportedClasses* resolves each to the one class definition it names, following a package's `__init__.py` or a script's `index.ts` that re-exports it, and reading a script's import of a generated language adapter (`@cdd/...`) as the Python module it is generated from, and *PublicRoutes* adds the classes the framework's registries hold and the toolsets the installer publishes. After each read it records, in `compared_facts.py` (*ComparedFacts*, made by the graph reading, with `folder_facts.py`, `module_exposure.py`, `class_facts.py`, and `operation_facts.py`), every fact that compares a node with the rest of the graph — a folder's import cycles, a module's subtree class definitions and the public ones with the route that reaches each (named, registered, or published) and its operations, public, private, and on its public classes (the seam methods `deep-module` judges, at most 35% of the module's methods; the class counts are context), a class's copies, forwarding target, extended domain, and built collaborator, an operation's copied body — so each rule only reads a node's facts and compares them with its limit.

- **Purpose:** Keep the reading and the facts the rules read apart from the class model, so the model every format and three other practices import carries only the classes, and the reading's dependencies run one way: reading, then formats, then model.
- **Seam (terms):** GraphReading, CodeRead, CodeIndex, DESCRIBED_FACT, PRODUCTION_FACT, CardLines, ClassGraph, ImportedClasses, ComparedFacts
- **Dependencies (one-way):** `cdd_guidance/practices/clean_engineering/model` and its format packages (the class model the reading parses code and model documents into), `harness/graph` (*PracticeReading*, the nodes and edges it records), `harness/agent_tools` (progress). Nothing in `model/` imports this package; the practice (`clean_engineering.py`) names *GraphReading* as its `reading_type`, and the rules package, BDD, and DDD read its facts.

## Constraint

A fact a rule compares is recorded here, on the node it describes, once per read; a rule only reads a node's facts and compares them with its limit. Code in `model/` never imports this package, so a format adapter never loads the graph reading.
