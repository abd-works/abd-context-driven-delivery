# cdd_guidance/practices/clean_engineering/reading
*GraphReading* is how Clean Engineering takes part in the knowledge graph: it reads a working copy's production code and model documents into class, module, operation, and property nodes, links each call to the member it reaches, and records the facts the practice's graph rules compare. *CodeIndex.file* answers a *CodeFile*, the one seam every practice asks to resolve a name a file's code writes: the class or module function it declares, imports, or finds beside itself, and the members a *CodeSpan* of its code calls and reads (`members_called_in`). Clean Engineering asks it for each operation's and property's body, and BDD for each observation and its setups, so an `invokes` edge means the same member whichever practice draws it. It is the practice's `reading_type`, a *PracticeReading* of harness/graph.

A span's receivers are typed only by what the code says (*Typed*: one object of a class, a tuple, a collection, a mapping, or a script object's named fields): a parameter's, a member's, or a local's type hint; the class a local is built from; and, where the code writes no hint, what the operation's `return` statements answer, what the constructor or a field's own initializer assigns, what a module assigns a module variable, and what a function the file declares inside a block or a script function's signature returns (*MemberAnswers*, held by the index and read once per read). A chain is followed through each call's answer and each item it takes; an inherited operation that answers its own class answers the receiver's class; a class is found through a package's `__init__.py` or `index.ts` that passes it on; a type hint of `Any` stops the reading. A local whose class the code does not say, or whose class neither declares nor inherits the member, reaches the one member of that name the file's reach declares, and that `invokes` edge keeps that it was joined by a guess (`joined`), weaker evidence than a receiver's class; it reaches nothing when two classes declare it. A chain of three or more parts on a local of no known class, such as a spec's untyped fixture (`fixture.board.column("Backlog").cards`), goes on from that guessed member through what it answers or holds, and each member it reaches after it is joined by the same guess; the classes it runs through are not recorded as reached, since the code never says them. A chain whose first name is an object from outside the code read, a built-in or a name imported from a standard or third-party module, and an operator applied to one (`root / "hooks.json"`), does not go on past its first member, since no class of the code is such an object. Such a call of an operation some class declares, which the read cannot join, is counted on its class by why its receiver has no class (*ReceiverCauses*, *UnjoinedCalls*, `receiver_causes.py`): an object from outside the code read, a built-in, a literal, or a name imported from a module outside it (`unresolved_calls_on_outside_objects`); a value no type says, an untyped parameter, `Any`, or a function or field with no hint (`unresolved_calls_on_untyped_values`); and any other, such as a hint naming a class no file declares (`unresolved_calls_otherwise`), so a rule can tell a call the reading cannot see from one the code does not make.

Between the classes of the code the read records each class it extends (`baseClass`); the class each field holds, private or public, typed by its hint or by what its constructor or initializer assigns it, as a composition when the class's own code builds it, an aggregation when it is handed many, and an association when it is handed one (*FieldLinks*; a relationship a person wrote on a property stands); and each other class its members create, call, read, or name as a value (`dependsOn`). A `dependsOn` edge keeps how the class reaches the other (`reached`: created on each call, created in the constructor, looked up by name, held as a field, handed in as a parameter, reached through another object, a module's object, named as a value, as an isinstance check, a list, a call it is handed to, or a metaclass names the class, never a type hint, or created with the class, as a class attribute's initializer builds it) and the members it reaches it through (`through`), as *CodeFile.reach_of* reads each span (*SpanReach*). A getter's node spans its whole body, and a private getter is read as an operation, so what a getter calls and raises is read. A call on an item of a list the code writes joins the operation of each class the items are, and a call on an item of a collection typed with a base joins the operation each class extending the base overrides. A class that declares every member of a Python protocol of two or more members satisfies it (`realizes`), and a call through the protocol joins the operation of each class that satisfies it, as a call on an item of a collection of a base joins each override; a class taken from a list of classes joins the operation each of them declares. A class's attributes, with a hint or without one, count among the members a protocol asks for. A call or a read on the object itself (`self`, `this`) also joins the member each class extending it overrides; a union of classes (`Brakes | Lights`) types a value as one of them; a field is typed by what any operation of its class or of a class it extends, at any depth, assigns it, a helper the constructor calls among them; a parameter named `cls` with a hint is that hint's class; and the expressions a triple-quoted f-string interpolates are read as code. A class that specialises a generic base (`class ToolShelf(Shelving["Spanner"])`) fills in the base's type parameters, those its `Generic[...]` or `Protocol[...]` base lists, so what an operation of the base answers, and what iterating it or taking an item of it gives, is the class the specialising class names. A property that has a setter is read as what its getter answers, a comprehension's loop is read like any other and a comprehension builds a list of what its expression is, a loop that takes two names takes the parts of what it walks by position, and a mapping's `items()` and `values()` are what a loop over them takes, as is a copy `list(...)` or `sorted(...)` makes, and its `get` answers one of its values; an `isinstance` or `instanceof` check narrows a local the code typed no other way, or typed as a class the named one extends, to the class it names; a hint that passes a generic class of the code type arguments, `ClassRegistry[PracticeGuidance]` on a field or a parameter, types an object that carries them, so what its operations and properties answer in a type parameter is that argument; a call of a value of one class builds it, as `self.practice_class(name)()` and a local holding a class, `kind()`, do; `super()` in a class reaches, in the method resolution order (C3) of that class and of each class extending it, the first class after it that declares the member, so a mixin's `super()` reaches the class each class mixing it in puts next; a mixin's `self` reads a field the class mixing it in keeps; a call of a field answers what the field holds, as `formats_type: type[PracticeFormats]` builds a `PracticeFormats`; and a script's interface or object type alias types the fields it names (`interface LoadState { status: LoadStatus }`). A function a module the file imports declares is joined through the module's name, called or read (`name_facts.opening_of(text)`, `polish.wax` passed on), and a module function the code names as a value, handed to a call (`ThrottledReporter(_report_line)`), is joined too, and so is a module function a chain opens with, `foldAt.bind(null, editor)`. A call after a spread (`...changeMarks()`) is read like any other, and so is the code inside a template string's `${...}`. A script's element (`<Boundary>`) calls the function component it names, or builds the class component on each render and calls its `render`. Uses written outside any member are joined too (*StatementLinks*, `statement_links.py`): a module's own statements, an `if __name__ == "__main__":` block and a class declared inside an `if` among them, as made by the folder that holds the file (`invokes` from the folder, `dependsOn` reached through `module statements`), and a class's own statements, its attributes' initializers (created with the class) and its metaclass (named as a value), as made by the class. These edges are right on the classes read at the code fidelity; until one thing is one node, a class a model document describes is a node of its own and keeps only the relationships its document writes.

Each production file keeps the classes it imports, re-exports, or reaches as `module.Class`, each with the module it names it from (*ClassReference*, read by *ScriptImports* alike for every file, read now or outside an edited-file scope); *ImportedClasses* resolves each to the one class definition it names, following a package's `__init__.py` or a script's `index.ts` that re-exports it, and reading a script's import of a generated language adapter (`@cdd/...`) as the Python module it is generated from, and *PublicRoutes* adds the classes the framework's registries hold and the toolsets the installer publishes. After each read it records, in `compared_facts.py` (*ComparedFacts*, made by the graph reading, with `folder_facts.py`, `module_exposure.py`, `class_facts.py`, and `operation_facts.py`), every fact that compares a node with the rest of the graph — a folder's import cycles, a module's subtree class definitions and the public ones with the route that reaches each (named, registered, or published) and its operations, public, private, and on its public classes (the seam methods `deep-module` judges, at most 35% of the module's methods; the class counts are context), a class's copies, forwarding target, extended domain, and built collaborator, an operation's copied body — so each rule only reads a node's facts and compares them with its limit.

The facts the rules of scope all read are recorded the same way, once per read over the whole practice: on each class the classes it builds on each call from strings or dicts or looks up by name (`dependencies_to_own`, *DependenciesToOwn*) and the parameter every one of its operations takes (`taken_by_every_operation`); on each operation the operations in other files whose bodies match it once each body's own names are set aside (`same_body_elsewhere`, *SameBodies*), the parameter it starts handing down unchanged and each operation it passes (`hands_down`, *HandedDownParameters*), and the operations of other classes that name its target with another answering verb (`verbs_for_one_target`, *VerbsForOneTarget*); on each folder the collections of its files that name the classes another file's collection names (`second_registries`, *SecondRegistries*); and on each module what its card says that its code does not (`card_drift`, *CardDrift*), from the seam terms and dependencies its card names (`card_seam_terms`, `card_dependencies`). Each names an operation as *qualified_name* does, `Class.operation`.

- **Purpose:** Keep the reading and the facts the rules read apart from the class model, so the model every format and three other practices import carries only the classes, and the reading's dependencies run one way: reading, then formats, then model.
- **Seam (terms):** GraphReading, CodeRead, CodeIndex, CodeFile, CodeSpan, SpanReach, Typed, MemberAnswers, REACHED_FACT, THROUGH_FACT, JOINED_FACT, UNRESOLVED_CALLS_FACTS, PRODUCTION_FACT, CardLines, ProductionClasses, ProductionClass, ComparedFact, ImportedClasses, ComparedFacts, qualified_name, DEPENDENCIES_TO_OWN, SAME_BODY_ELSEWHERE, HANDS_DOWN, TAKEN_BY_EVERY_OPERATION, SECOND_REGISTRIES, VERBS_FOR_ONE_TARGET, CARD_DRIFT
- **Dependencies (one-way):** `cdd_guidance/practices/clean_engineering/model` and its format packages (the class model the reading parses code and model documents into), `harness/graph` (*PracticeReading*, the nodes and edges it records), `harness/agent_tools` (progress), `cdd_guidance/practices/source_code` (*ClassReference*, *ScriptImports*, *ProjectTestCode*: what a file imports and which files are test code), `harness/guidance` (*PracticeGuidance*, the practice a reading is made for, and `PRACTICE_CATALOGUE` and `ACTION_CATALOGUE`, whose registered classes are public), `harness/whiteboard` (*UnreadableBoard*, a board file the reading cannot read), `cdd_guidance/practices/clean_engineering/measures` (*CheckedCodeMeasures*, which the reading keeps for the files a read names, and `read_facts.py`'s fact names and helpers, `DESCRIBED_FACT`, `IMPORTED_MODULES_FACT`, `is_under`, `parameters_of`, which the reading records and reads by). Nothing in `model/` imports this package; the practice (`clean_engineering.py`) names *GraphReading* as its `reading_type`, and the rules package, BDD, and DDD read its facts.

## Constraint

A fact a rule compares is recorded here, on the node it describes, once per read; a rule only reads a node's facts and compares them with its limit. Code in `model/` never imports this package, so a format adapter never loads the graph reading.
