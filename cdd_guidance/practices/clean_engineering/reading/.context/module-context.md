# cdd_guidance/practices/clean_engineering/reading
*GraphReading* is how Clean Engineering takes part in the knowledge graph: it reads a working copy's production code and model documents into class, module, operation, and property nodes, links each call to the member it reaches, and records the facts the practice's graph rules compare. *CodeIndex.file* answers a *CodeFile*, the one seam every practice asks to resolve a name a file's code writes: the class or module function it declares, imports, or finds beside itself, and the members a *CodeSpan* of its code calls and reads (`members_called_in`). Clean Engineering asks it for each operation's and property's body, and BDD for each observation and its setups, so an `invokes` edge means the same member whichever practice draws it. It is the practice's `reading_type`, a *PracticeReading* of harness/graph.

A span's receivers are typed only by what the code says (*Typed*: one object of a class, a tuple, a collection, a mapping, or a script object's named fields): a parameter's, a member's, or a local's type hint; the class a local is built from; and, where the code writes no hint, what the operation's `return` statements answer, what the constructor or a field's own initializer assigns, what a module assigns a module variable, and what a function the file declares inside a block or a script function's signature returns (*MemberAnswers*, held by the index and read once per read). A chain is followed through each call's answer and each item it takes; an inherited operation that answers its own class answers the receiver's class; a class is found through a package's `__init__.py` or `index.ts` that passes it on; a type hint of `Any` stops the reading. A local whose class the code does not say, or whose class neither declares nor inherits the member, reaches the one member of that name the file's reach declares, and that `invokes` edge keeps that it was joined by a guess (`joined`), weaker evidence than a receiver's class; it reaches nothing when two classes declare it. Such a call of an operation some class declares, which the read cannot join, is counted on its class by why its receiver has no class (*ReceiverCauses*, *UnjoinedCalls*, `receiver_causes.py`): an object from outside the code read, a built-in, a literal, or a name imported from a module outside it (`unresolved_calls_on_outside_objects`); a value no type says, an untyped parameter, `Any`, or a function or field with no hint (`unresolved_calls_on_untyped_values`); and any other, such as a hint naming a class no file declares (`unresolved_calls_otherwise`), so a rule can tell a call the reading cannot see from one the code does not make.

Between the classes of the code the read records each class it extends (`baseClass`); the class each field holds, private or public, typed by its hint or by what its constructor or initializer assigns it, as a composition when the class's own code builds it, an aggregation when it is handed many, and an association when it is handed one (*FieldLinks*; a relationship a person wrote on a property stands); and each other class its members create, call, read, or name as a value (`dependsOn`). A `dependsOn` edge keeps how the class reaches the other (`reached`: created on each call, created in the constructor, looked up by name, held as a field, handed in as a parameter, reached through another object, a module's object, or named as a value, as an isinstance check, a list, or a call it is handed to names the class, never a type hint) and the members it reaches it through (`through`), as *CodeFile.reach_of* reads each span (*SpanReach*). These edges are right on the classes read at the code fidelity; until one thing is one node, a class a model document describes is a node of its own and keeps only the relationships its document writes.

Each production file keeps the classes it imports, re-exports, or reaches as `module.Class`, each with the module it names it from (*ClassReference*, read by *ScriptImports* alike for every file, read now or outside an edited-file scope); *ImportedClasses* resolves each to the one class definition it names, following a package's `__init__.py` or a script's `index.ts` that re-exports it, and reading a script's import of a generated language adapter (`@cdd/...`) as the Python module it is generated from, and *PublicRoutes* adds the classes the framework's registries hold and the toolsets the installer publishes. After each read it records, in `compared_facts.py` (*ComparedFacts*, made by the graph reading, with `folder_facts.py`, `module_exposure.py`, `class_facts.py`, and `operation_facts.py`), every fact that compares a node with the rest of the graph — a folder's import cycles, a module's subtree class definitions and the public ones with the route that reaches each (named, registered, or published) and its operations, public, private, and on its public classes (the seam methods `deep-module` judges, at most 35% of the module's methods; the class counts are context), a class's copies, forwarding target, extended domain, and built collaborator, an operation's copied body — so each rule only reads a node's facts and compares them with its limit.

- **Purpose:** Keep the reading and the facts the rules read apart from the class model, so the model every format and three other practices import carries only the classes, and the reading's dependencies run one way: reading, then formats, then model.
- **Seam (terms):** GraphReading, CodeRead, CodeIndex, CodeFile, CodeSpan, SpanReach, Typed, MemberAnswers, DESCRIBED_FACT, REACHED_FACT, THROUGH_FACT, JOINED_FACT, UNRESOLVED_CALLS_FACTS, PRODUCTION_FACT, CardLines, ProductionClasses, ProductionClass, ComparedFact, ImportedClasses, ComparedFacts
- **Dependencies (one-way):** `cdd_guidance/practices/clean_engineering/model` and its format packages (the class model the reading parses code and model documents into), `harness/graph` (*PracticeReading*, the nodes and edges it records), `harness/agent_tools` (progress). Nothing in `model/` imports this package; the practice (`clean_engineering.py`) names *GraphReading* as its `reading_type`, and the rules package, BDD, and DDD read its facts.

## Constraint

A fact a rule compares is recorded here, on the node it describes, once per read; a rule only reads a node's facts and compares them with its limit. Code in `model/` never imports this package, so a format adapter never loads the graph reading.
