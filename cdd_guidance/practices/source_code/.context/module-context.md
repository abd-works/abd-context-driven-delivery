# cdd_guidance/practices/source_code
Source code as several practices read it. *CodeBody* is an operation's body as it was read, in its *CodeLanguage* (`PYTHON`, `TYPESCRIPT`, `JAVASCRIPT`): rendered in the same language it comes back as written, rendered in another it is translated statement by statement (*BodyTranslation*, `statement_translation.py`, between Python and TypeScript or JavaScript, both read into Python's syntax tree), and only a statement outside the subset both hold comes back commented out under a note naming its language (*TranslatedBody.untranslated*), above a statement that fails until someone writes it. *BracketStructure* says which bracket closes which in a brace-language span, and `split_top_level` splits a parameter list at its top-level commas. *CallGraph* is the `-> callee` arrows a document writes under a member. *ScriptImports* reads the classes a file imports, each a *ClassReference* with the module it names it from. *SourceText* is a span of source measured for the rules, with the parts it holds, *SpanFailures* and *SpanCollaborators*; it is one *MeasuredBody*, the measures every operation's body answers whichever way its parser read it. *ProjectTestCode* is the one answer to which files of a project are test code, specs, or examples: by their names (*TestFileName*), by the files the project's `.context/config.json` names under `test_code`, and, for a `test_*.py` file outside a folder of tests, by the test functions it declares. Each practice's part in the graph holds it (*HoldsProjectTestCode*, made from the folder its graph reads), and every reader and rule asks it there.

It has the same standing as `sketch_document`: shared by practices, not a practice.

- **Purpose:** Let Stories, BDD, DDD, the patterns, and space/session read code without loading Clean Engineering's class model, so a brace is parsed by one reader and a test file is named by one rule.
- **Seam (terms):** CodeBody, CodeLanguage, BodyTranslation, TranslatedBody, CodeSpelling, BraceCall, WrittenBlock, InsideLines, PYTHON, TYPESCRIPT, JAVASCRIPT, CODE_LANGUAGES, BracketStructure, split_top_level, CallGraph, CallGraphEntry, parse_arrow_line, ScriptImports, ClassReference, STAR, imported_files, MeasuredBody, SourceText, SpanFailures, SpanCollaborators, TestFileName, ProjectTestCode, HoldsProjectTestCode. Callers import them from the package (`from cdd_guidance.practices.source_code import CodeBody`); `WrittenKey` is the type alias of a written block's key in `code_body.py`.
- **Dependencies (one-way):** harness/graph (*Graph*, *Node*, and `scanned_files`, which `code_reach.py` walks), harness/installation (*ContextConfig*, the project's `.context/config.json`, whose `test_code` names the project's test files).

Nothing here imports a practice or a pattern.

## Constraint

Code here reads text; it knows no practice's nodes and holds no rule. A measure a rule compares is written here only when more than one practice reads it; Clean Engineering's own measures stay in its `model/operation_metrics.py`.
