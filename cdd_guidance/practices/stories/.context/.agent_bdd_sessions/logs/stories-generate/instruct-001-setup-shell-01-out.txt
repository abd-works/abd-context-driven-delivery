---
type: stories
capabilities:

- agent
signature:
  instructions: '# Instructions'
  read_manifest:
    kind: meta
    instructions: Get the latest manifest (this document).
    cmd: python -m tools manifest context_tools.stories.stories:Stories
    returns: manifest
  invoke:
    kind: meta
    instructions: Run one tool or action on a toolset instance.
    cmd: python -m tools run <request.yaml|->
  new:
    kind: constructor
    instructions: Create a toolset instance.
    parameters:
      fidelity: str
      format: str | None
      path: str | None
      session: str | None
      workspace: str | None
  close_session:
    kind: tool
    parameters:
      outcome: str
      handoff: str
    returns: str
  create_session:
    kind: tool
    parameters:
      name: str
      goal: str
      fidelities: str
      contexts: str
      path: str
    returns: str
  ensure_session:
    kind: tool
    parameters:
      name: str
      goal: str
      fidelities: str
      contexts: str
      path: str
    returns: str
  read_context_index:
    kind: tool
    returns: str
  record_context_root:
    kind: tool
    parameters:
      root: str
      note: str
    returns: str
  scan:
    kind: tool
    parameters:
      paths: list[str]
    returns: str
  transform:
    kind: tool
    instructions: "Parse content from source_format into the canonical StoryMap, then\
      \ render into target_format.\n        All formatters are peer channels. Sideways\
      \ format move at the same fidelity.\n        At acceptance_tests fidelity: after\
      \ transforming story artifacts, call ce().transform() or ce().generate() to\
      \ produce matching production class code alongside the spec output."
    parameters:
      source_format: str
      target_format: str
      content: str
    returns: dict
  verify_segment_completeness:
    kind: tool
    instructions: Run named-entry completeness on a ``*-segment.md`` chunk.
    parameters:
      segment_path: str
      expected_names: str
      min_body_chars: int
      index_path: str
    returns: str
  write_to_fix:
    kind: tool
    instructions: Append one entry to ``{session.folder}/to-fix.log``.
    parameters:
      artifact: str
      rule: str
      wrong: str
      original: str
      improved: str
      status: str
      when: str
    returns: str
  active:
    kind: resource
    type: Session
  mode:
    kind: resource
    type: str
  add_generate_header_to_generated:
    kind: action
    tools: []
    instructions: Prepend the following block verbatim as the very first lines of
      the file you are writing - before any imports, before any code.
    returns: str
  document:
    kind: action
    tools:
    - generate_output
    - add_generate_header_to_generated
    instructions: '# Document


      Take the persona of a **neutral observer** — describe what exists, do not prescribe
      what should exist.


      1. Follow **`session_guidance`**. Observe and write under the session layout.

      2. Read the **contexts** to understand the vocabulary and structure of the domain.

      3. Fill the **template** scaffold with observed content — describe current state
      only.

      4. Do not apply, suggest, or imply rules or best practices in the generated
      output.

      5. Call **`scan`** and append all violations to the document as-is — flag them,
      do not correct them.

      6. Save the artifact under the session layout from `session_guidance`.'
    parameters:
      paths: list[str]
    returns: str
  generate:
    kind: action
    tools: []
    instructions: "Generate story artifacts at the current fidelity.\n        At story_map\
      \ fidelity: write the story map and thin-slice only.\n        At scenarios fidelity:\
      \ write main-flow scenarios (single or multiple per story) with optional variations;\
      \ use ExampleFactory fakes where available.\n        At acceptance_tests fidelity:\
      \ write *_spec and *_spec.{tier} acceptance test files. When spec files are\
      \ written, call ce().generate() to produce or update the matching production\
      \ class implementations and wire any supporting code changes."
    returns: str
  generate_output:
    kind: action
    tools: []
    returns: str
  grill:
    kind: action
    tools:
    - generate
    instructions: Grill then generate - pure grill loop, then the host generate body.
    returns: str
  iterate:
    kind: action
    tools: []
    instructions: "Iterate then generate - grill + formal generate/validate/one-fix\
      \ ticks.\n        At acceptance_tests fidelity: after each spec cycle, call\
      \ ce().iterate() to wire the minimum production code until GREEN.\n        If\
      \ the same acceptance scenario is still RED after 2 consecutive fix attempts\
      \ — stop guessing. Call diagnostic().diagnose() before a third fix (tier wiring,\
      \ stale Story constant, vocabulary drift, or transform that fixed the map while\
      \ the leaf still fails)."
    returns: str
  log_fix:
    kind: action
    tools:
    - write_to_fix
    instructions: "# Log fix\n\nWhen the user says **to fix** (or equivalent), treat\
      \ it as failure: the agent\ndid not do it right. **Correct immediately**, then\
      \ append one entry to the\ncurrent sprint’s `to-fix.log` via action `log_fix`\
      \ (calls tool `write_to_fix`):\n\n```yaml\ntool: write_to_fix\narguments:\n\
      \  artifact: <path or node that was wrong>\n  rule: <exact failed rule — scanner\
      \ slug or (process) name>\n  wrong: <one line — what was done wrong>\n  original:\
      \ |\n    <faulty output>\n  improved: |\n    <corrected output>\n  status: fixed\n\
      ```\n\n## Where\n\nWrite under the **current session** folder only:\n\n`{session.folder}/to-fix.log`\n\
      \n(e.g. `{path}/.context/sessions/{name}/to-fix.log`). Requires a named sprint\n\
      (`create_session` / constructor `session=`). Do not log into a divergent folder.\n\
      \n## Entry shape\n\nMatch existing sprint entries. Each block:\n\n| Field |\
      \ Content |\n|-------|---------|\n| `when` | ISO date (tool fills today if omitted)\
      \ |\n| `artifact` | Path and/or map node |\n| `rule` | Exact failed rule |\n\
      | `wrong` | One-liner |\n| `original` | Faulty output (YAML `\\|` block) |\n\
      | `improved` | Corrected output (YAML `\\|` block) |\n| `status` | Usually `fixed`\
      \ after the correction |\n\n## Rules\n\n- Fix first, then log — never log a\
      \ planned fix without applying it.\n- `wrong` stays one line; put detail in\
      \ `original` / `improved`.\n- Prefer an exact rule id (`branch-on-mechanical-uniqueness`)\
      \ or a clear\n  `(process) …` name when no scanner slug exists.\n- Call `write_to_fix`\
      \ (via action `log_fix`) once per failure; do not batch unrelated defects.\n"
    parameters:
      artifact: str
      rule: str
      wrong: str
      original: str
      improved: str
      status: str
    returns: str
  partition:
    kind: action
    tools: []
    parameters:
      context: str
      mode: str
      out_root: str | None
    returns: str
  repair:
    kind: action
    tools:
    - scan
    instructions: "# Repair\n\nIterate until **validate** passes on `{{asset}}`. The\
      \ violation signal is:\n\n```\n{{violation}}\n```\n\nThat text may be a scanner\
      \ report, a user complaint, or both together. The loop\nfixes **why the generator\
      \ produced the violation** — not the artifact in isolation.\nNever proceed without\
      \ a verifiable error signal from **scan** or **validate**.\n\nRead the **`active`**\
      \ resource first. `{{asset}}` and repaired outputs live under\nthat root (docs\
      \ → `{session.path}/.context/`; code → `{session.path}/{module}/`). Do not\n\
      repair into a divergent folder.\n\nRun this loop inline in the current session.\n\
      \n---\n\n## When scan is clean but the violation is a user complaint\n\nThe\
      \ tools do not see the problem yet. Edit the relevant scanner under\n`scanners/`\
      \ or `formats/{format}/scanners/` until **scan** reports a failure on\n`{{asset}}`\
      \ that matches the complaint. Re-run **scan** after each scanner edit.\n\nDo\
      \ not proceed to root-cause analysis until **scan** fails on `{{asset}}`.\n\n\
      ---\n\n## 1. Open an example folder\n\nCreate a descriptive folder under the\
      \ domain examples tree and copy the broken\noutput before any fixes:\n\n```\n\
      <domain>/examples/<descriptive-folder>/\n  faultyAsset          ← copy of {{asset}}\
      \ when there is one file\n  faultyAssets/        ← when more than one file (same\
      \ layout as {{asset}})\n  runs/1/run.md\n```\n\nUse a folder name that describes\
      \ the violation class (e.g.\n`inheritance-crosses-class`). If that folder already\
      \ exists from a prior session,\npick a new descriptive name or suffix (`-2`,\
      \ `-3`, …).\n\nWhen `{{asset}}` is multiple files, use `faultyAssets/` instead\
      \ of a single\n`faultyAsset` file. Mirror the same paths inside that folder.\n\
      \n---\n\n## 2. Write run.md\n\nCreate `runs/<n>/run.md` for each attempt. Include,\
      \ for every definitive\nviolation:\n\n| Field | Content |\n|-------|---------|\n\
      | Rule | context slug |\n| Location | file, section, or element |\n| Violated\
      \ element | the specific thing that failed |\n| Scanner / check | the scanner\
      \ that detected it |\n| Root cause | why the generator produced it |\n| Fix\
      \ applied | what changed to resolve it |\n\nNon-blocking warnings may be listed\
      \ separately but do not block the loop.\n\n---\n\n## 3. Root cause\n\nUse **contexts**,\
      \ **examples**, and **template** to determine why the generator\nproduced the\
      \ violation. Review context bullets, worked samples, and file shape.\n\n---\n\
      \n## 4. Fix the generator\n\nApply a **surgical** change to the generator —\
      \ contexts, examples, template,\naction prose, or scanners — so the violation\
      \ does not recur. Touch only what\nroot cause implicates; do not rebuild from\
      \ spec.\n\nRe-run **generate** (or the steps that produced `{{asset}}`) and\
      \ write the output\nback to `{{asset}}`. Do not hand-edit `{{asset}}` to greenwash\
      \ the scanners while\nleaving the generator broken.\n\nIf the domain has `reference/repair-tips.md`,\
      \ read it before writing fix code.\nSave every generator change in `runs/<n>/run.md`.\n\
      \n---\n\n## 5. Validate and repeat\n\nRun **validate** on `{{asset}}` after\
      \ regenerating from the fixed generator. The\nreport names the failing scanner\
      \ when scan finds violations.\n\nIf violations remain, increment to `runs/<n+1>/run.md`\
      \ and repeat from **Step 2**.\n\n---\n\n## 6. Capture the pass fixture — once\
      \ validate passes\n\nSave the final clean output beside the original failure:\n\
      \n```\n<domain>/examples/<descriptive-folder>/\n  faultyAsset          ← or\
      \ faultyAssets/ when more than one file\n  repairedAsset        ← or repairedAssets/\
      \ when more than one file\n```\n\nOnly the **original failure** and **final\
      \ clean output after generator fix** are\nkept as fixtures. Delete `runs/` when\
      \ the repair is done — working notes only\nduring the loop.\n\n---\n\n## 7.\
      \ Run regression across repair history\n\nRe-run **scan** on every captured\
      \ example pair under\n`<domain>/examples/*/`:\n\n- Every `faultyAsset` or file\
      \ under `faultyAssets/` must still **violate**\n- Every `repairedAsset` or file\
      \ under `repairedAssets/` must still be **clean**\n\nThe folder structure is\
      \ the registry — no separate cases file.\n\n---\n\n# Validate\n\nTake the persona\
      \ of a **critical judge** — do not edit the artifact.\n\n1. Follow **`session_guidance`**.\
      \ Scope judgment to artifacts under `session.path` / the session layout.\n2.\
      \ Use **contexts** as the rubric — report pass/fail per named context and named\
      \ rule with brief evidence.\n3. Call **`scan`** on the session-rooted paths\
      \ under review.\n4. Do not fix. Report failures for fixing, then **validate**\
      \ again when ready.\n\n---\n"
    parameters:
      asset: str
      violation: str
    returns: str
  satisfy:
    kind: action
    tools: []
    instructions: "Find and fix every problem in the story artifacts under the session\
      \ root.\n        If the same acceptance scenario is still RED after 2 consecutive\
      \ fix attempts — stop guessing. Call diagnostic().diagnose() before a third\
      \ fix (tier wiring, stale Story constant, vocabulary drift, or transform that\
      \ fixed the map while the leaf still fails)."
    returns: str
  sketch:
    kind: action
    tools:
    - generate
    instructions: Sketch then generate - grill + sketch cadence, then the host generate
      body.
    returns: str
  validate:
    kind: action
    tools: []
    instructions: '# Validate


      Take the persona of a **critical judge** — do not edit the artifact.


      1. Follow **`session_guidance`**. Scope judgment to artifacts under `session.path`
      / the session layout.

      2. Use **contexts** as the rubric — report pass/fail per named context and named
      rule with brief evidence.

      3. Call **`scan`** on the session-rooted paths under review.

      4. Do not fix. Report failures for fixing, then **validate** again when ready.


      ---'
    returns: str
