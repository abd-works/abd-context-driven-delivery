# Story UI editor (`cdd_guidance/practices/stories/app`)

- **Purpose:** the page a person edits a Stories file in, beside the chat: the story map as epics, sub-epics, stories and scenarios, edited in place. Moved here from its own repository (`C:/dev/story-ui`, 2026-11-12) to sit beside the Stories practice whose model it edits, as the Graph app sits in `harness/graph/app`.
- **Seam (terms):** `StoryMapClient` (extends the generated `StoryModelClientGenerated`), `StoryMapApi` (the page's `CddApi`), `StoryMapWorkspaceView`; for a server, `storyMapRoutes` and `storyMapBuild` (`story-map-routes.ts`) and `STORY_MAP_PAGE` (`/story-map`, `story-map-page.ts`).
- **Domain:** none of its own. Every rule and every edit is the Python story model's (`cdd_guidance/practices/stories/model/story_model.py`: `StoryModel`, `Epic`, `Story`, `Scenario`, `Step`, `Increment`, saved through `OpenedStoryMap`), reached through the generated adapter (`@cdd/practices/stories/model/*`), with the formats chosen for the fidelity through `FidelitySessionOutput` (`@cdd/space/session/fidelity-session-output`). No JSON or database story map: the file it was opened from is the store.
- **Served:** by the board's server on its port (8778), at `/story-map`, with `storyMapRoutes` (the story map's objects, the formats chosen, and the session's file manager) under `/api`. `npm install` then `npm run build` writes `dist/`, which that server serves. `?file=<path from the project>` opens a Stories file; with none the page follows the story map of the session open in the project, read every two seconds.
- **Constraints:** source only: `node_modules/` and `dist/` are ignored, so neither the runtime pin (a git checkout) nor an install carries them; the toolset walk skips `node_modules`. A failed call says what failed and how to fix it, and the page keeps the map as Python last sent it (`fail-loud-on-mcp`). The views draw what the story model sends and nothing else: each node's description (the paragraph under its heading), edited through `edit_description`; a scenario's examples as the model's one table, read only, since no operation edits an example; each story's acceptance tests as links that open the file read only beside the map through the session's file manager (`SourceViewGenerated`); the increments, edited through `StoryModel.new_increment` and `Increment.add_story` / `remove_story` and kept in the thin slice beside the map; and, opened on a ticket, only the stories the ticket's session names (`StoryModel.scope`), with a Ticket scope toggle for the whole map. A map laid out by hand, such as `harness/.context/stories/story-map.md`, is edited too: it is read by itself and written back with every line an edit does not touch.
- **Tests:** `npm test` (type check and `story-map/story-map-client.spec.tsx`, jsdom); the story map tools are specified against a real cdd server in `cdd_guidance/practices/stories/model/story_map_edits_spec.py`.
