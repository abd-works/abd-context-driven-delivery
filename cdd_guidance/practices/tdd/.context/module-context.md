# cdd_guidance/practices/tdd
*TDD* is a practice supplement, not a practice of its own: it adds test-driven rules to the implementation fidelity of four practices (Clean Engineering code, Stories acceptance tests, BDD development, DDD tactics), as `tdd.md`'s front matter lists. Every behaviour is proven working for real before it is trusted, then kept proven by a test at the fastest tier that can prove it. *Tdd* (`tdd.py`) is a *PracticeSupplement*; `tiers.py` says which tier a test file belongs in (unit, heavy, end-to-end) and what real resources it reaches; *TddOverlay* (`graph_overlay.py`) records those facts on the Stories and BDD nodes the graph already holds, so the supplement's rules read them. `practices/stories` and `practices/bdd` hold the rules it adds to each of those practices. *ModuleTiers* (`module_tiers.py`) fills the session's record of the test tiers each module uses as a generate or a render writes tests at Stories acceptance tests or BDD development (`Tdd.records_for(fidelity, files)`): it reads each test file's tier from its name (`recorded_tier_of`) and its module from the nearest folder holding a module card, records the unit tier of each module the fidelity writes under, and says what it could not tell, the module of a story test under `story_tests`, a test tool the file's name does not say, or whether a module needs the server or web tier, so the agent decides and records it with `session.record_test_tier`. It never replaces a tool already recorded, and it reports a recorded module whose folder is no longer there, leaving its removal to the person.

- **Purpose:** Hold the test-tier and test-first rules every implementation fidelity follows, once, beside the practices they supplement.
- **Seam (terms):** Tdd (`records_for(fidelity, files)`), TddOverlay, ModuleTiers, `tier_of`, `recorded_tier_of`, `test_tool_of`, `is_code_file`, `real_resources_in`
- **Dependencies (one-way):** `harness/guidance` (*PracticeSupplement*), `harness/graph` (*Graph*, *Node*, *GraphOverlay*), `harness/agent_tools`, the session it works in through `harness/guidance`'s *WorkedSession* (`session.test_tiers`), `cdd_guidance/practices/stories` and `cdd_guidance/practices/bdd` (the practices whose nodes it decorates)

## Constraint

A test lives in the fastest tier that can prove its behaviour: unit by default, heavy only for real resources, end-to-end only for a real browser or a real agent. The tiers and their budgets are this supplement's rules; `scripts/test.ps1` runs them.
