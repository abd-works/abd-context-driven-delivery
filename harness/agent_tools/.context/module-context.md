# harness/agent_tools
*AgentToolSet* turns an ordinary Python class into a set of operations an agent can list, run as Python, or follow as written **instructions**, without the author writing MCP, skill, or hook files. The author types `@agent_toolset` on the class; the class docstring is the description the agent reads, and the class name, in kebab case, is the toolset's one name everywhere it is published.
*AgentTool* is one member of that set that an agent can see and call. *AgentOperation* is a member annotated `@agent_tool`: the agent runs its Python now. *AgentInstructions* is a member annotated `@agent_instructions`: the method body is the recipe the agent follows, and inside it `tools(...)` names the operations the agent may call while following it and `instructions(...)` includes another recipe.
`@tool_subject` annotates the class method that finds the object a call acts on, so a domain class whose constructor takes collaborators can still publish its instance operations as tools. A loader or class tool that takes `project` is handed the call's project, and one that takes `call` the call itself (`TakesFromCall`); neither is one of the tool's arguments. `@noSessionLog` keeps a frequently repeated read out of the session log.
*ToolSetCollection* lets one toolset publish named child toolsets in the order they were added, so nested toolsets stay nested. A *ToolSetCollection* is named and found the way a toolset is (*AgentToolSetOrigin*). `@subAgent` puts the hand-off to a background sub-agent at the start of a member's description; the `sub-agent.sub_agent` operation itself is tools/sub_agent. `@published_where_held` marks a collection's tool that only the toolset holding the collection itself publishes, as a practice publishes its shared rules' injection and not each fidelity's again.
*ToolsetReference* is a toolset named `module:Class`, the one way such a reference is written (`ToolsetReference.of(cls)`) and read back; a module in a hyphenated folder is found under the folders on the import path. `AgentToolSet.LOAD_FAILURES` is what making a toolset raises when its code cannot be loaded, which the servers catch to skip it. An *AgentTool* writes the `Use MCP tool:` line a skill ends with (`invoke_line`) and reads tool names back from it (`invoked_names`, `is_invoke_line`), so the installer parses the line it wrote one way.
*ParameterSchema* is the JSON Schema of a callable's parameters read from its type hints, so what MCP publishes and what it passes on agree; `with_defaults(arguments)` gives a call's arguments with each optional parameter's default, which a recipe's placeholders and its body read. A toolset's `parameter_notes` say what an agent reads about a parameter after the description of every tool that takes it, as a guidance action explains `guidance`.
*ToolCall* is one call of a tool: the arguments its caller sent, the project folder the calling chat names, and *ChatPointer*, the chat it came from (its id, its transcript, and the transcript lines the call covers), which ends every session.log line the call writes. `ToolCall.sent(arguments, project, tool=..., mcp_host=...)` takes the chat out of the arguments a chat sent, so the tool gets only its own, and the call carries the tool's name and the MCP host answering it, so a tool that inspects the host (the diagnostics) reaches it from its call. A call's session (`call.session`, or `call.session_named(session_file)` for the session a board command names) is opened through a *SessionOpener*, the seam *ToolCall* declares: the module that keeps sessions (space/session) registers its opener with `ToolCall.open_sessions_with` when it is imported, so the framework opens a call's session without importing space. Work on a project that serves no call, such as the agent BDD harness or a diagnostics probe, reads the session open there through `ToolCall.session_in(project)`, so it never builds a call it does not send; a tool that serves a call takes the call (see `cdr/0001-a-tool-is-handed-the-call-it-serves.md`). A call that names no project, or runs where no opener is registered, works in no session.
*AgentTool* knows which channels it is published to by asking the *Destination* annotations in harness/annotations, so this module never imports the publishers (harness/installation, harness/mcp, harness/hooks); they depend on it. A member's description is read from markdown beside the toolset through harness/markdown. *ToolSubjectLoader* is how a publisher reads the `@tool_subject` loader of a domain class, so the arguments that find the object come before the operation's own.

- **Purpose:** Let an author publish an ordinary class as operations and recipes an agent can list and use, and let every publisher (MCP, skills, hooks, the catalog) read those members from one place.
- **Seam (terms):** AgentToolSet, AgentTool, AgentOperation, AgentInstructions, ToolSetCollection, ToolsetReference, ParameterSchema, InstallDestination, ToolCall, SessionOpener, SessionsNotLoaded, ChatPointer, ToolSubjectLoader; the annotations `@agent_toolset`, `@agent_tool`, `@agent_instructions`, `@tool_subject`, `@noSessionLog`, `@subAgent`, `@published_where_held`; `tools(...)`, `instructions(...)`; `parameter_notes`
- **Dependencies (one-way):** harness/annotations (the annotations, and *Name* for every published name), harness/markdown. space/session registers its *SessionOpener* with *ToolCall*; this module imports nothing above the framework.

## Constraint

Put `@agent_toolset` on the class rather than subclassing *AgentToolSet*, so the class keeps its own base and constructor. Give each published member exactly one of `@agent_tool` (run the Python) or `@agent_instructions` (follow the recipe), because the agent has to know which of the two it is calling. Inside an `@agent_instructions` body, name callable operations only through `tools(...)` and nested recipes only through `instructions(...)`; a recipe that includes itself is rejected when the class is decorated. Where a member is published (MCP, skill, command, rules, hook) is decided by the annotations harness/installation, harness/mcp, and harness/hooks define on *Destination*, not by this module; a publisher asks the *AgentTool* whether it is published on its channel, and nothing here imports a publisher's annotation.
