# harness/agent_tools
*AgentToolSet* turns an ordinary Python class into a set of operations an agent can list, run as Python, or follow as written **instructions**, without the author writing MCP, skill, or hook files. The author types `@agent_toolset` on the class; the class docstring is the description the agent reads, and the class name, in kebab case, is the toolset's one name everywhere it is published.
*AgentTool* is one member of that set that an agent can see and call. *AgentOperation* is a member marked `@agent_tool`: the agent runs its Python now. *AgentInstructions* is a member marked `@agent_instructions`: the method body is the recipe the agent follows, and inside it `tools(...)` names the operations the agent may call while following it and `instructions(...)` includes another recipe.
`@tool_subject` marks the class method that finds the object a call acts on, so a domain class whose constructor takes collaborators can still publish its instance operations as tools. `@noSessionLog` keeps a frequently repeated read out of the session log.
*ToolSetCollection* lets one toolset publish named child toolsets in the order they were added, so nested toolsets stay nested. `@subAgent` puts the hand-off to a background sub-agent at the start of a member's description; the `sub-agent.sub_agent` operation itself is harness/sub_agent.
*ParameterSchema* is the JSON Schema of a callable's parameters read from its type hints, so what MCP publishes and what it passes on agree. A toolset's `parameter_notes` say what an agent reads about a parameter after the description of every tool that takes it, as a guidance action explains `guidance`.
*AgentTool* lists the channels it is published to (`destinations`, `install_to(channel)`) by asking the *Destination* marks in harness/marks, so this module never imports the publishers (harness/installation, harness/mcp, harness/hooks); they depend on it. A member's description is read from markdown beside the toolset through harness/markdown.

- **Purpose:** Let an author publish an ordinary class as operations and recipes an agent can list and use, and let every publisher (MCP, skills, hooks, the catalog) read those members from one place.
- **Seam (terms):** AgentToolSet, AgentTool, AgentOperation, AgentInstructions, ToolSetCollection, ParameterSchema, InstallDestination, ToolCall; the marks `@agent_toolset`, `@agent_tool`, `@agent_instructions`, `@tool_subject`, `@noSessionLog`, `@subAgent`; `tools(...)`, `instructions(...)`; `parameter_notes`
- **Dependencies (one-way):** harness/name, harness/marks, harness/markdown, and space/session through *ToolCall* alone (a call's session is opened there, when a tool first asks for it). space/session imports this module back, so that one import still closes a cycle (`.sessions/_backlog/break-module-dependency-cycles.md`).

## Constraint

Put `@agent_toolset` on the class rather than subclassing *AgentToolSet*, so the class keeps its own base and constructor. Give each published member exactly one of `@agent_tool` (run the Python) or `@agent_instructions` (follow the recipe), because the agent has to know which of the two it is calling. Inside an `@agent_instructions` body, name callable operations only through `tools(...)` and nested recipes only through `instructions(...)`; a recipe that includes itself is rejected when the class is decorated. Where a member is published (MCP, skill, command, rules, hook) is decided by the marks harness/installation, harness/mcp, and harness/hooks define on *Destination*, not by this module; read a member's channels through `AgentTool.install_to(channel)`, never by importing a publisher's mark here.
