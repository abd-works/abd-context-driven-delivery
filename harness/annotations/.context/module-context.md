# harness/annotations
*Annotation* is what an author types on an operation or class to say how CDD treats it — install it, keep it out of the catalog, keep it out of install — so install and discovery find the member by its annotations rather than by a list kept somewhere else; each kind of annotation is a subclass. A kind is itself the one instance of its *AnnotationKind*, the class of every kind, so install and discovery ask the kind (`Skill.annotates(member)`, `recorded_on(member)` for a kind that records itself, as `@on_stage` does, `written_as()`, `installs_member()`, `companion_flags()`) as an instance operation; a family of kinds that answers in a way of its own names its own kind of kind (*NamesKind* `names_on`, *OmissionKind*, *HostedOnlyKind*, *DestinationKind* `publishes`, `name_given`, `disabled_on`), and a kind that makes a member installable says so with `makes_installable`. Every kind joins `annotation_kinds` as its class is made. *OmissionAnnotation* leaves what it annotates out of something: `@noCatalog` (*NoCatalog*) out of the catalog, `@noDeploy` (*NoDeploy*, which sets `omits_install`) out of install, and `@hosted_only` (*HostedOnly*) keeps a class whose tools run only through what holds it (a practice's rules, its fidelities) from being loaded as a toolset on its own; it is read on the class it was written on, never inherited, so each practice that subclasses one stays a toolset. Other modules read an omission through the name an author types (`noCatalog.annotates(target)`, `hosted_only.written_as()`), so its class stays behind it.
*Destination* is an annotation that says where a member is published, its **channel**: a skill, a command, a rules file, an MCP tool, or a hook. Each publisher defines its own kind (`Skill`, `Command`, `Rules` and their base *NamedDestination* in harness/installation, `Mcp` in harness/mcp, `Hook` and `Toast` in harness/hooks), and the kind *is* the channel: install asks it whether it publishes a member (`Mcp.publishes(operation)`) and what name it gave the member (`Hook.name_given(operation)`, the event a hook runs on). Its `channel` string is only the key a published list and `diagnostics.json` file the channel under. Two class flags say what is special about a channel, so no reader names one: `marks_a_collection` (set by `Rules`, whose member holds a collection of its toolset's tools) and `answers_calls` (set by `Mcp`, whose server answers an agent's calls to the member). A destination annotation that holds a `name` gives the member that name there, and one that holds `disabled` set records itself turned off, as `@Hook(..., disabled=True)` does, which its kind reads back (`disabled_on`), so no publisher defines a kind of its own for either. *NamesAnnotation* is an annotation that records a tuple of names on what it decorates and reads them back (`names_on`): the fields that name one object (`@identity`), the fields an operation edits (`@edits`), and the arguments a tool takes from its call (*TakesFromCall*) are its kinds, each naming only its flag.
*ClassRegistry* holds the classes a package registers with the framework when it is imported, in the order it lists them, each by its name (`register`, `classes`, `names`, `has`, `named`): the one mechanism the practice catalogue, the action catalogue, and the graph's registry of patterns each hold an instance of, so no registry keeps its classes in class-level state of its own.
`class_folder(cls)` is the folder a class is defined in, which the class holds once it is first asked: a toolset's install folder, a practice's key and documents, an action's guide, the catalog's utility page, and the markdown beside any class all start from it.
`annotation_kinds` is the one list of the kinds of annotation, which each kind joins as it is defined: harness/agent_tools asks it where install publishes an operation (`destinations_of(operation)`, the destination kinds in the order they were defined), the name a destination gave it for its installed file (`deploy_name_of(operation)`), which destination answers an agent's calls (`answering_calls`, MCP), whether a member holds a collection of tools (`marking_a_collection(member)`) or becomes a tool on its own (`enlisting(member)`), and which annotations a wrapper copies (`copied_flags()`, `copy_annotations`), without importing a single publisher.
*Name* is one name, such as a class, an event, or a fidelity, that CDD writes in several cases: `StoryMap`, `story_map`, and `story-map` are the same name, and so are a title's words (`Pet visits`, `pet-visits`, `PetVisits`). Every annotation publishes a member under a name, and every case conversion in CDD reads *Name*, so a class name, a toolset slug, a published tool name, and a file named after a title always agree.

- **Purpose:** Hold the annotations an author types, the one place a member's destinations are read, and the one way a name is written in each case, below every module that defines or reads an annotation, so the publishers depend on the toolsets and never the other way round.
- **Seam (terms):** Annotation, NamesAnnotation, Destination (`marks_a_collection`, `answers_calls`), DestinationKind (`publishes`, `name_given`, `disabled_on`), `annotation_kinds` (`destinations_of`, `deploy_name_of`, `answering_calls`, `marking_a_collection`, `enlisting`), ClassRegistry, `class_folder`, the annotations an author types (`@hosted_only`, `@noCatalog`, `@noDeploy`); Name (`words`, `snake`, `kebab`, `camel`, `spellings`, `title_slug`, `title_snake`, `title_pascal`, `title_camel`). The bases publishers subclass, the registry, *DestinationKind* (the type of a channel, which a tool and an installation hold), and *Name* are the classes other modules name; the other kinds of kind (*AnnotationKind*, *NamesKind*, *OmissionKind*, *HostedOnlyKind*), *OmissionAnnotation*, the omission annotations' classes, and the registry of kinds' own class stay behind them (`cdr/0002-the-module-keeps-its-kinds-behind-its-bases.md`).
- **Dependencies (one-way):** none.

It is the lowest module of the framework, so harness/markdown and everything above it may use it.

## Constraint

Convert a name between cases only through *Name*; a second conversion elsewhere splits words differently (`MCPServer`, `pre-tool-use`) and the published name stops matching the class.

Define a new channel as a *Destination* subclass in the module that publishes it, with its `flag` and `channel`, so the channel joins `annotation_kinds` by being imported. Set `enlists_member` only on a destination whose member the IDE calls directly, as a hook is, because such a member becomes a tool of its toolset without `@agent_tool`. Mark what is special about the channel with its class flags (`marks_a_collection`, `answers_calls`) rather than having a reader test for the channel by name, so a reader asks `annotation_kinds` and never imports the publisher. A channel whose publisher was never imported annotates nothing, which holds by construction: nothing can carry an annotation that was never defined.
