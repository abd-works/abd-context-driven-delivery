# harness/design_canvas
*DesignCanvas* is a Claude Design canvas written as files: its pages, the boards placed on them, and the artboard files they show, with the `canvas.json` that ties them together. A practice lays out its own artboards — the story map, the screens — as an *Artboard* (its title, size, body, look, and its `name` under `project/`, whose `stem` a dc-import uses), with the cards and thumbnails drawn at a *Place* (`place.card(look, text)` in a *CardLook* the practice keeps, `place.thumbnail(caption, image, href)`), and puts it on the canvas (`add(artboard, at)`); an artboard the project already holds, such as a screen people edited, is placed by its name (`place(name, at)`). The canvas decides where every file goes and answers them (`files()`), each by its path. A practice that places one artboard beside another asks the canvas where it placed that one (`placed(name)`), so where a board sits on the canvas stays the canvas's own record. A canvas made with its project folder (`DesignCanvas(title, project)`) holds what that folder already holds (*CanvasProject*, `canvas.project`): the artboards people made there (`artboards_in`), the stylesheets they link and the scripts they load (`stylesheets_linked_by`, `scripts_linked_by`), and whether it holds a file and how large it is (`holds`, `size_of`), so a practice never reads the canvas project itself.

*CanvasVersions* keeps numbered versions of a canvas (`version-1`, `version-2`, ...) under the `design-canvas` folder in the UX practice's root (`CanvasVersions.in_practice_root(practice_root)`, the caller naming the root session.json gives the UX practice), beside the practice's other outputs, each a *CanvasVersion* (its `number`, `folder`, the `link` it was published at, `title(name)`, `publish_at(url, walk, accepted_misses)`, `accepted_misses`, and `release(name)`), with the links kept in `versions.json` (*PublishedLinks*, harness/installation), because people edit a published canvas directly. `publish_at` takes a walk of the version's screens (*WalkedScreens*: the misses, each a value a step names that its screen leaves out, which the UX practice's story canvas walk reports) and refuses with *UnshownStepValues* while a miss is not among `accepted_misses`; the accepted ones are kept beside the link: generating again starts the next version (`working()`, `start_next()`) instead of writing over one that is published, and writing into a published version fails with *PublishedVersion* (`unpublished()`).

- **Purpose:** Let a practice publish its views as a Claude Design canvas without knowing the canvas's file layout, and regenerate it without overwriting what people edited.
- **Seam (terms):** DesignCanvas (`add`, `place`, `placed`, `files`, `project`), CanvasProject, CanvasBoard, Artboard (`name`, `stem`), `artboard_stem(path)`, Place, CardLook; CanvasVersions (`latest`, `working`, `unpublished`, `start_next`, `published`), CanvasVersion, PublishedVersion, WalkedScreens, UnshownStepValues. The practices' own canvas parts live with them: UX's abd look (`LOOK`, `FONTS`, `BACKGROUND`) and its fixture screens (*FixtureScreen*, *ScenarioSource*) are in `cdd_guidance/practices/ux/model/claude_design/`.
- **Dependencies (one-way):** harness/installation (*JsonFile*, *PublishedLinks*, which keep `versions.json`).

Nothing in harness imports it back; the UX practice's story canvas (`model/claude_design` in cdd_guidance/practices/ux) and space/session (each version's link) use it.

## Constraint

Lay out artboards in the practice that owns them and give the canvas only finished artboards, so the canvas stays the same for every practice. Take a canvas's files only from `DesignCanvas.files()`, which the practice's render returns and the Render action places, so one object decides every path under `project/`; regenerate a published canvas only by starting a new version through *CanvasVersions*, never by writing into the published one.
