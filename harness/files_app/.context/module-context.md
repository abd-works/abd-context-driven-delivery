# harness/files_app

The *Files app* shows a session's files beside the chat and takes a person's comments on them back to that chat: the file viewer as an app of its own, on its own server and port (`app/ports.json`, 8783), which reads only the files its link names and never the board. It is the one place a session's files are viewed; the chat bar's files button, its session name, and an `open_file` another page sends a chat all open it. Stories and scenarios: the main map's (E) Review Generated Work In File Viewer (`.context/story-map.md`, `story_tests/review-generated-work-in-file-viewer/`); acceptance tests: `space/session/review-files-in-files-app.story.*.py`, `app/files/*.spec.ts`. Model: `.context/files-app-model.md`.

**Opening it.** Python registers it once as an *App* (`files_app.py`, `FILES_APP`, harness/diagnostics); a chat readies it with `app.open('Files')` and starts its server while it is not running. A link names what to show and who opened it:

| Query | Means |
|---|---|
| `files=<ticket>&fidelity=<slug,slug>` | the files of those fidelities of the ticket; the chat bar's files button names every fidelity of the shown stage, every practice's |
| `session-folder=<ticket>` | every file in `.sessions/<ticket>` |
| `file=<path>` | the file to open first, a `.drawio` file in the draw.io editor beside the file list |
| `chat=<id>` | the chat that opened the page, which its comments and practice changes are sent to |
| `project=<folder>` | the project every call names (`X-CDD-Project`) |

**What it calls.** Its server (`app/files-server.ts`) answers only this machine's own page and serves the generated routes of `session.*`, `file-comments.*`, `fidelity-progress.*`, `practice-session-output.*`, and one chat route, `chat.send`, through the cdd server; so the Files app does what those operations do and holds no rule of its own. The page reads the session's practices with `session.show`, and a practice toggle calls `practice-session-output.enable` then sends the chat a `refresh`, which its chat bar answers by reading the board again. A comment is added, edited, sent and cleared with the `file-comments.*` tools; the open file is read with `session.file` (text, comments, folds, violations), again every two seconds while a comment on it is sent. A `.drawio` file shows the draw.io editor (`tools/drawio_viewer`, port 8791) in the file view beside the file list, through the server's draw.io page, which starts the viewer when nothing answers its port; its ↗ link opens the same page in a tab of its own where the browser opens one (the app's browser pane opens none). A right-click on a file or folder offers to show it in the system's file browser (Explorer, Finder, or the desktop's file manager), which the server starts on this machine through `/reveal` (`app/file-explorer.ts`).

**Its graph view.** The file bar's Graph button shows the session's graph instead of the files: the practice trees holding only the nodes read from the files the bar lists (`session.graph_trees`, read again whenever the bar lists other files, so the stage, practice, format and Changed filters narrow both alike), each opened a level at a time (`session.graph_branch`). Each row is drawn as the Graph app draws it, with its kind's mark (`@graph-app/labels/kind-mark`), and while the graph reads, the page shows the cdd server's progress with the Graph app's `LoadProgressView` (`/cdd/progress`). Selecting a node opens its file at its lines, or, for a node no file's lines hold such as a folder, each listed file below it (`session.graph_node_ranges`); with Ctrl, Cmd or Shift it joins the nodes selected, and each other file they sit in opens below the first, the page scrolling to the first node's lines. Once the trees are read, the page reads every member the graph holds (`session.graph_members`) so the source view opens a call in place across files. An open file then reads its folds and opens only those holding a selected node (`files/files-graph.ts` *FilesGraph*, `files-graph-view.tsx`, the source view's `openAround`). The graph is the session's own, read from exactly the files the bar lists (`Session.graph_trees`, `Graph.load_files`), so the bar's filters are the graph's one filter; the page keeps no copy of it beyond what the session answered.

**Seam (terms):** the page's link and its query (`files`, `fidelity`, `session-folder`, `file`, `chat`, `project`); the server's routes under its API root (the generated `session.*`, `file-comments.*`, `fidelity-progress.*`, `practice-session-output.*` and `chat.send` routes, the draw.io page, and `/reveal`); the *App* `FILES_APP` that `app.open('Files')` readies.

**Depends on:** the generated TypeScript adapters (`.claude/language-adapters/typescript`), the graph explorer's source view (`harness/graph/app/source`), harness/diagnostics (*App*, *AppPackage*, *AppPage*, *AppServer*), and the cdd server. Nothing imports it.

## Constraint

Open the Files app only through `app.open('Files')` and a link that names its files, and reach a session only through the server's generated routes; the page keeps no rule or copy of the session of its own. A link names its files; one with neither `files` nor `session-folder` shows that it names none. A practice change reaches the chat bar only while the chat checks in with the board, as comments do. A field added to a session operation's data reaches the page only after the language adapters are written again (an install, or `installer.deployment.write_language_adapters()`) and the app is built again.
