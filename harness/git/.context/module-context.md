# harness/git
*Git* runs the git command line in one folder, with a time limit that suits the command (10 s for reads; 180 s for commands that reach origin or read or rewrite the whole working tree: push, fetch, pull, checkout, merge, worktree, add, commit) and no inherited stdin (which hangs git under the MCP server on Windows): `Git(folder).run(*args, env=..., timeout=...)` answers git's output, and `succeeds(*args)` answers whether a command such as `show-ref --verify` succeeds. `listed(*args)` answers the entries of a command that lists files, such as `ls-files`, `diff --name-only` or `status --porcelain`, each as git writes it under `-z`, so a name with letters outside ASCII, a quote, a backslash or a tab is the name the file has on disk. Every failure, whether git is missing, times out, or exits with an error, raises *RepoConnectError*. *Checkout* (`checkout.py`) is one checkout of a repository, known by its top folder: `Checkout.holding(folder)` is the checkout holding a folder (the folder itself when no checkout holds it), `is_main` and `is_linked_worktree` say whether its `.git` is a directory or a file, `main_folder` is the repository's main checkout, `branch` is the branch it has out (empty when detached or no clone), and `facts` is what its git holds. *GitFacts* (`git_facts.py`) is that one interface: `head_branch`, `is_on_branch`, `head_commit`, `has_ref(ref)`, `branch_names`, `has_remote(name)`, `worktrees`, `common_folder`. *GitFolder* answers them from the checkout's `.git` files, because the board asks them many times in one read and starting git costs about 40 ms on Windows; *AskedOfGit* asks the git command line, for a checkout whose refs only git reads, such as a reftable; *NoGitFacts* answers nothing for a folder that is no clone, where asking git would only fail or find a repository above it. A *Checkout* chooses among them once its files can be read, and chooses again until then, so a plain folder made a repository is read from its files from then on. The framework (harness/mcp's lanes and pinned runtime, harness/process, harness/agent_tools' chat pointer) and space/repo's *Repo* each ask a *Checkout*, so git's facts have one reader on both sides of the boundary.

The repository tools (space/repo), the session's file reads (space/session), the catalog's source links, the release and the test cadence (harness/diagnostics), and the pinned cdd runtime (harness/mcp) all run git through it.

- **Purpose:** Run git the same way everywhere, with one set of time limits and one error, so no caller has to stop a hung git or read its exit code.
- **Seam (terms):** Git, RepoConnectError, Checkout, GitFacts, GitFolder, AskedOfGit, NoGitFacts.
- **Dependencies (one-way):** none (standard library only), so harness/catalog_generator, harness/diagnostics, harness/mcp, space/repo, and space/session all use it without depending on each other.

## Constraint

Run git only through *Git*, and ask a checkout's facts only of its *Checkout*, so every git command gets the same time limit and the same error. Git for Windows' `cmd\git.exe` is a launcher, so a git that outlives its limit is stopped with its whole process tree; stopping only the launcher leaves the real git holding the output pipes.
