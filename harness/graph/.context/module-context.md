# harness/graph
*Graph* reads a working copy — the code, specs, story maps, and model documents in a folder — into its practices' nodes and edges, so rules can be checked against what is actually on disk and a person can browse the result in the graph explorer. `graph.load_working_copy` reads a whole folder, `graph.load_files` reads only the files being edited, and `graph.save_json` saves the graph in the folder's `.context/graph.json`. `graph.return_nodes` returns the nodes a filter matches, with their ancestors, children, relationships, and the rules each one passes or breaks; `graph.inventory`, `graph.filter_choices`, and `graph.source` answer the explorer's tree, its filter, and a node's source, and `graph.explorer_trees` answers each practice's tree as the explorer's filter leaves it: *Filter* decides which nodes it keeps, and the explorer shows what it sends. An *EdgeType* says whether a person filters by its kind (`is_offered`): the `belongsTo` back-edge and `scopes` are never offered. `graph.set_overlays` and `graph.overlay_of` apply a pattern's extra rules (such as `lern_domain_driven`) on top of the practices; the graph holds each applied pattern and asks it for the *GraphOverlay* it owns. `graph.refresh(paths)` reads again exactly the files an action wrote: it drops their nodes, reads them as they are now, links them, and runs the rules again. Nothing watches the files and no load compares dates, so a changed file reaches the graph only through `refresh` or a forced load. A session holds its graph (`Session.graph`, space/session), and `Graph.for_call` gives each graph tool call its session's graph, so no call rebuilds it from disk.
The graph holds the *PracticeGuidance* objects it is given: a session gives it the session's own practices, the same objects the session's actions work with, and a graph no session holds makes a set of its own from *PracticeCatalogue* (`create_all`). A model object made without a graph is detached: it belongs to no practice and records no edge until a part of a graph adopts it, or something asks it for its graph, which then makes one for its whole tree; parsing a file builds no graph. Each practice holds the graph (`practice.graph`) and its own part of it, a *PracticeNodes* the graph makes once and keeps (`practice.in_graph`): the practice's root node, source root, nodes, and edges — `practice.in_graph.nodes(type)`, `.edges(kind)`, `.root`, `.source_root`, `.add(node, ...)`, `.add_named(...)`, `.holds(node_id)`, `.schema`, and `.check()`, which runs the practice's graph rules. The graph aggregates those parts: `graph.link(kind, parent, child)` (an edge is kept on its parent's practice) and `graph.node(node_id)` reach every practice. Code that knows a practice's class reaches it by that class, never by its key: `graph.practice_of(kind)` opens it, and `graph.loaded(kind)` answers it only when the last load reads it, which is how one practice links or checks its nodes against another's. A node's practice is that *PracticeGuidance* (`node.practice`), its fidelity is the *FidelityGuidance* of that practice that creates it (`node.fidelity`), its schema is its practice's with the graph's overlays applied (`node.schema`), and `node.rules` are the rules that apply to it, from its practice (`practice.checks()`), the practice it extends, and each overlay the graph applies. A *Node* is the object a practice's parser built from the source (a class, an operation, a story, a step), so a rule reads measurements from the same object the explorer shows; a practice's model objects extend *ModelNode* and *ModelChildren* to be nodes. *Source* is where a node's text sits in its file. *SavedGraph* is the graph as `graph.json` keeps it — each node by name, type, location, facts, and the rules it broke, in the same fields `graph.return_nodes` answers with — and a graph read back from it holds plain nodes with their saved facts; a file saved in an older shape raises *SavedGraphOutdated* and is read from the folder again. *PracticeInventory* is one loaded practice as the explorer's inventory shows it: its node and edge counts, node types, edge kinds, rules, and tree.
A practice says on its own *PracticeGuidance* class what the graph reads from it: how it reads a working copy into its graph (`read_working_copy()`), how it links its nodes to other practices' (`link_to_other_practices()`), the graph rules it checks (`graph_checks`), and which of its node types are classes, members, read in source order, or anchored to a rule's subject (`class_types`, `member_types`, `source_ordered_types`, `anchor_types`, `rule_types`, `extends`, `align_node(node)`), so the graph names no practice's types. *GraphOverlay* is what a pattern adds on top; a pattern makes it once and keeps it as `graph_overlay`, and *PatternOverlays* makes each pattern the graph's overlays name once per process, so the graph never imports a practice or a pattern in code.
*PracticeGraphRule* is one rule a practice checks on loaded nodes; a practice writes its rules as subclasses, and *RuleCheckContext* gives each check the practice, its graph, and the folder its source was read from, and reads the practice's nodes and edges (`context.nodes(type)`, `context.edges(kind)`, `context.node(node_id)`). Each finding is a *Violation*, kept on the node's *GraphRule*, saved in `graph.json`, and read back by the Validate action's report and the board.
The explorer app in `harness/graph/app` reaches the same operations through the graph's TypeScript language adapter. *GraphAppPorts* (`graph_app.py`) reads the app's ports from `app/ports.json`, the one file the app's Vite config and web server also read, so the server health report and the instance scripts never write a port of their own. The app's tests type-check it first (`npm test` runs `tsc --noEmit`).

- **Purpose:** Turn a working copy into a graph of its practices that rules can check and a person can explore, from an agent's tools or from the graph explorer.
- **Seam (terms):** Graph, PracticeNodes, Node, EdgeType (`edge.py`, below the graph and the schema edges, so neither imports the other), ModelNode, ModelChildren, Source, GraphOverlay, PracticeGraphRule, RuleCheckContext, Violation, SavedGraph, SavedNode, SavedPractice, SavedGraphOutdated, PatternOverlays, PracticeInventory; the MCP operations `graph.load_working_copy`, `graph.load_files`, `graph.refresh`, `graph.save_json`, `graph.return_nodes`, `graph.explorer_trees`, `graph.inventory`, `graph.filter_choices`, `graph.source`, `graph.set_overlays`, `graph.overlay_of`; `@language_adapter(language="typescript")` on *Graph*
- **Dependencies (one-way):** harness/agent_tools, harness/guidance (*Rule*, *RulesCollection*, *Schema*, *PracticeGuidance*, *PracticeCatalogue*), harness/installation, harness/mcp, harness/annotations (*Name*). The practices and patterns depend on this module: a practice is a *PracticeGuidance* the graph is given (or, for a graph no session holds, makes from *PracticeCatalogue*, the one registry of practices), and a pattern owns its *GraphOverlay*, which the graph asks the pattern for, so no module here imports a practice. Each practice keeps the spec support that runs its rules on examples, and the specs of those rules, in its own `rules/` folder (`rule_examples.py`).

## Constraint

Load before you ask: every query operation answers from the graph last loaded or refreshed, so call `graph.load_working_copy` or `graph.load_files` first. After writing files, call `graph.refresh` with exactly those files; never add file-change detection, a watcher, or date checks. Pass `graph.load_files` the files being edited, so a check reads them as they are now without rebuilding or overwriting the saved graph. A folder is a module in the graph only when it owns `.context/module-context.md`; any other folder with source is a package inside the nearest such module. Write a new rule as a *PracticeGraphRule* in the practice that owns it, and a new node type on that practice's *PracticeGuidance* class, never in this module, so the graph stays the same for every practice. Give a graph the practices it holds (a session gives its own) and reach a practice's nodes through `practice.in_graph.nodes(type)`; never keep nodes or edges anywhere but the practice's part of the graph. Graph builds run one at a time in a process (`Graph._fill`), because they are CPU-bound Python sharing the MCP server's one interpreter; several at once each take far longer and stall every other call.
