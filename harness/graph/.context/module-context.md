# harness/graph
*Graph* reads a working copy — the code, specs, story maps, and model documents in a folder — into one graph per practice, so rules can be checked against what is actually on disk and a person can browse the result in the graph explorer. `graph.load_working_copy` reads a whole folder, `graph.load_files` reads only the files being edited, and `graph.save_json` saves the graph in the folder's `.context/graph.json`. `graph.return_nodes` returns the nodes a filter matches, with their ancestors, children, relationships, and the rules each one passes or breaks; `graph.inventory`, `graph.filter_choices`, and `graph.source` answer the explorer's tree, its filter, and a node's source. `graph.set_overlays` and `graph.overlay_of` apply a pattern's extra rules (such as `lern_domain_driven`) on top of the practices. `Graph.of_practice(folder, name, source_root)` opens one practice's graph for an action's log line, without reading a source tree too large to load.
*PracticeGraph* is one practice's nodes and edges. A *Node* holds the object a practice's parser built from the source (a class, an operation, a story, a step), so a rule reads measurements from the same object the explorer shows. A practice's model objects extend *BoundNode* and *BoundChildren* to take their place in the graph.
*PracticeGraphRule* is one rule a practice checks on loaded nodes; a practice writes its rules as subclasses, and *RuleCheckContext* gives each check the practice and the folder its source was read from.
The explorer app in `harness/graph/app` reaches the same operations through the graph's TypeScript language adapter.

- **Purpose:** Turn a working copy into practice graphs that rules can check and a person can explore, from an agent's tools or from the graph explorer.
- **Seam (terms):** Graph, PracticeGraph, Node, BoundNode, BoundChildren, PracticeGraphRule, RuleCheckContext; the MCP operations `graph.load_working_copy`, `graph.load_files`, `graph.save_json`, `graph.return_nodes`, `graph.inventory`, `graph.filter_choices`, `graph.source`, `graph.set_overlays`, `graph.overlay_of`; `@language_adapter(language="typescript")` on *Graph*
- **Dependencies (one-way):** harness/agent_tools, harness/guidance (*Rule*, *RulesCollection*, *Schema*, *PracticeCatalogue*), harness/installation, harness/mcp, and, through the working-copy loader, the practice models of cdd_guidance/practices/stories, ddd, clean_engineering, and bdd and the pattern rules of cdd_guidance/patterns/lern_domain_driven and cdd_web_domain_access. Every one of those practices and patterns imports this module back, so the framework depends on every practice; the backlog item `.sessions/_backlog/break-module-dependency-cycles.md` lists each import, and the practice parsing belongs with each practice.

## Constraint

Load before you ask: every query operation answers from the graph last loaded, so call `graph.load_working_copy` or `graph.load_files` first. Pass `graph.load_files` the files being edited, so a check reads them as they are now without rebuilding or overwriting the saved graph. A folder is a module in the graph only when it owns `.context/module-context.md`; any other folder with source is a package inside the nearest such module. Write a new rule as a *PracticeGraphRule* in the practice that owns it, never in this module, so the graph stays the same for every practice.
