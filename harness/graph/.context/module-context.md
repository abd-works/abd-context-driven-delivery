# harness/graph
*Graph* reads a working copy — the code, specs, story maps, and model documents in a folder — into one graph per practice, so rules can be checked against what is actually on disk and a person can browse the result in the graph explorer. `graph.load_working_copy` reads a whole folder, `graph.load_files` reads only the files being edited, and `graph.save_json` saves the graph in the folder's `.context/graph.json`. `graph.return_nodes` returns the nodes a filter matches, with their ancestors, children, relationships, and the rules each one passes or breaks; `graph.inventory`, `graph.filter_choices`, and `graph.source` answer the explorer's tree, its filter, and a node's source. `graph.set_overlays` and `graph.overlay_of` apply a pattern's extra rules (such as `lern_domain_driven`) on top of the practices. `graph.refresh(paths)` reads again exactly the files an action wrote: it drops their nodes, reads them as they are now, links them, and runs the rules again. Nothing watches the files and no load compares dates, so a changed file reaches the graph only through `refresh` or a forced load. The cdd server holds one graph per session in memory (`Graph.of_session(session_folder, root)`, reached as `Session.graph`), and `Graph.for_call` gives each graph tool call its session's graph, so no call rebuilds it from disk.
*PracticeGraph* is the part of a graph that holds one practice: the practice's *PracticeGuidance* (held, never looked up by name; the graph makes one of its own per practice from *PracticeCatalogue*, at no fidelity, and that guidance knows the graph), and the nodes and edges read for it. A node reaches its practice through `node.practice` and its fidelity through `node.fidelity`, the *FidelityGuidance* of that practice that creates it; `node.rules` are the rules that apply to it, from its practice, the practice it extends, and each overlay the graph applies. The practice reaches its nodes through the graph it holds, `practice.graph.nodes_of(practice)`. A *Node* is the object a practice's parser built from the source (a class, an operation, a story, a step), so a rule reads measurements from the same object the explorer shows; a practice's model objects extend *ModelNode* and *ModelChildren* to be nodes. *Source* is where a node's text sits in its file. *SavedGraph* is the graph as `graph.json` keeps it — each node by name, type, location, facts, and the rules it broke, in the same fields `graph.return_nodes` answers with — and a graph read back from it holds plain nodes with their saved facts; a file saved in an older shape raises *SavedGraphOutdated* and is read from the folder again.
A practice says on its own *PracticeGuidance* class what the graph reads from it: how it reads a working copy (`read_working_copy`), how it links its nodes to other practices' (`link_to_other_practices`), the graph rules it checks (`graph_checks`, `language_checks`), and which of its node types are classes, members, read in source order, or anchored to a rule's subject (`class_types`, `member_types`, `source_ordered_types`, `anchor_types`, `rule_types`, `extends`, `align_node(node)`), so the graph names no practice's types. *GraphOverlay* is what a pattern adds on top; a pattern keeps it as `OVERLAY` in its `graph_overlay.py`, which `GraphOverlay.of(pattern)` imports, so the graph never imports a practice or a pattern by name in code.
*PracticeGraphRule* is one rule a practice checks on loaded nodes; a practice writes its rules as subclasses, and *RuleCheckContext* gives each check the practice and the folder its source was read from. Each finding is a *Violation*, kept on the node's *GraphRule*, saved in `graph.json`, and read back by the Validate action's report and the board.
The explorer app in `harness/graph/app` reaches the same operations through the graph's TypeScript language adapter.

- **Purpose:** Turn a working copy into practice graphs that rules can check and a person can explore, from an agent's tools or from the graph explorer.
- **Seam (terms):** Graph, PracticeGraph, Node, ModelNode, ModelChildren, Source, GraphOverlay, PracticeGraphRule, RuleCheckContext, Violation, SavedGraph, SavedNode, SavedPractice, SavedGraphOutdated, PatternOverlays; the MCP operations `graph.load_working_copy`, `graph.load_files`, `graph.refresh`, `graph.save_json`, `graph.return_nodes`, `graph.inventory`, `graph.filter_choices`, `graph.source`, `graph.set_overlays`, `graph.overlay_of`; `@language_adapter(language="typescript")` on *Graph*
- **Dependencies (one-way):** harness/agent_tools, harness/guidance (*Rule*, *RulesCollection*, *Schema*, *PracticeGuidance*, *PracticeCatalogue*), harness/installation, harness/mcp, harness/name. The practices and patterns depend on this module: a practice is a *PracticeGuidance* the graph makes from *PracticeCatalogue*, the one registry of practices, and a pattern keeps its *GraphOverlay* as `OVERLAY`, which `GraphOverlay.of` finds by the pattern's folder name, so no module here imports a practice. Each practice keeps the spec support that runs its rules on examples, and the specs of those rules, in its own `rules/` folder (`rule_examples.py`).

## Constraint

Load before you ask: every query operation answers from the graph last loaded or refreshed, so call `graph.load_working_copy` or `graph.load_files` first. After writing files, call `graph.refresh` with exactly those files; never add file-change detection, a watcher, or date checks. Pass `graph.load_files` the files being edited, so a check reads them as they are now without rebuilding or overwriting the saved graph. A folder is a module in the graph only when it owns `.context/module-context.md`; any other folder with source is a package inside the nearest such module. Write a new rule as a *PracticeGraphRule* in the practice that owns it, and a new node type on that practice's *PracticeGuidance* class, never in this module, so the graph stays the same for every practice.
