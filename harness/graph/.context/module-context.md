# harness/graph
*Graph* reads a working copy — the code, specs, story maps, and model documents in a folder — into its practices' nodes and edges, so rules can be checked against what is actually on disk and a person can browse the result in the graph explorer. `graph.load_working_copy` reads a whole folder, `graph.load_files` reads only the files being edited, and `graph.save_json` saves the graph in the folder's `.context/graph.json`. `graph.return_nodes` returns the nodes a filter matches, with their ancestors, children, relationships, and the rules each one passes or breaks; `graph.inventory`, `graph.filter_choices`, and `graph.source` answer the explorer's tree, its filter, and a node's source, and `graph.explorer_trees` answers each practice's tree as the explorer's filter leaves it: *Filter* decides which nodes it keeps, and the explorer shows what it sends. An *EdgeType* says whether a person filters by its kind (`is_offered`): the `belongsTo` back-edge and `scopes` are never offered. `graph.set_overlays` and `graph.overlay_of` apply a pattern's extra rules (such as `lern_domain_driven`) on top of the practices; the graph holds each applied pattern and asks it for the *GraphOverlay* it owns. `graph.refresh(paths)` reads again exactly the files an action wrote: it drops their nodes, reads them as they are now, links them, and runs the rules again. Nothing watches the files and no load compares dates, so a changed file reaches the graph only through `refresh` or a forced load. A session holds its graph (`Session.graph`, space/session), and `Graph.for_call` gives each graph tool call its session's graph, so no call rebuilds it from disk.
The graph holds the *PracticeGuidance* objects it is given: a session gives it the session's own practices, the same objects the session's actions work with, and a graph no session holds makes a set of its own from *PracticeCatalogue* (`create_all`). A model object made without a graph is detached: it belongs to no practice and records no edge until a practice adopts it with its whole tree (`model.join(practice)`) or an owner on a graph takes it as a part; parsing a file builds no graph, and asking a detached object for its graph raises *ModelDetached*. Each practice's reading part (`practice.reading`, a *PracticeReading*) holds the graph (`practice.reading.graph`) and the practice's own part of it, a *PracticeNodes* the graph makes once and hands it (`held_in`, read as `practice.reading.in_graph`): the practice's root node, source root, nodes, and edges — `practice.reading.in_graph.nodes(type)`, `.edges(kind)`, `.root`, `.source_root`, `.add(node, ...)`, `.add_named(...)`, `.holds(node_id)`. The part holds three parts of its own, each made once: its edges by kind with their indexes (`.edge_index`, an *EdgeIndex*), the run of its graph rules (`.rule_run`, a *PracticeRuleRun*: `.schema`, the practice's *PracticeSchema* with the graph's overlays, made once and kept there, `.schema_with(overlays)` for another set, `.checks`, its graph rules with those the applied patterns add, and `.check()`, which runs them), and what it takes back from saved records (`.restore`, a *PracticeRestore*, the one way a restore and a worker's changes come back). The graph aggregates those parts: `graph.link(kind, parent, child)` (an edge is kept on its parent's practice) and `graph.node(node_id)` reach every practice. The graph's own jobs are parts it makes once and keeps: its practices (`graph.practices`, a *GraphPractices*), the scope of the read it last made (`graph.scope`, a *LoadScope* each load or refresh makes for itself: `source_files(root, suffixes)`, `edited_files`, `folders`), its build (`graph.build`, a *GraphBuild*), the schema edges between its model objects (`graph.schema_edges`, which holds whether it syncs and `held()` for a batch of links), and the explorer's queries (`graph.explorer`, a *GraphExplorer* with the graph's *Filter*). Code that knows a practice's class reaches it by that class, never by its key: `graph.practices.of(kind)` opens it, and `graph.practices.loaded(kind)` answers it only when the last load reads it, which is how one practice links or checks its nodes against another's. `graph.practice(key)` is the one lookup by key, for a call that names a practice by the key it sent. A node's practice is that *PracticeGuidance* (`node.practice`), its fidelity is the *FidelityGuidance* of that practice that creates it (`node.fidelity`), its schema is its practice's with the graph's overlays applied (`node.schema`), and `node.rules` are the rules that apply to it, from its practice (`practice.reading.checks()`), the practice it extends, and each overlay the graph applies. A *Node* is the object a practice's parser built from the source (a class, an operation, a story, a step), so a rule reads measurements from the same object the explorer shows; a practice's model objects extend *ModelNode* and *ModelChildren* to be nodes. *Source* is where a node's text sits in its file. *SavedGraph* is the graph as `graph.json` keeps it — each node by name, type, location, facts, and the rules it broke, in the same fields `graph.return_nodes` answers with — and a graph read back from it (`graph.restored_from(saved)`) holds plain nodes with their saved facts; a file saved in an older shape raises *SavedGraphOutdated* and is read from the folder again. The graph's *PatternOverlays* answers which rules a practice checks with the overlays a saved graph was saved with (`graph.applied_patterns.checks_of(practice, saved.overlays)`), with the patterns it already holds, so a report reads no graph back and makes no pattern again. A saved graph kept for the files a validate checks also names the folders of the other files the graph held (`held_beside`), which practice-wide rules compared them with. *PracticeInventory* is one loaded practice as the explorer's inventory shows it: its node and edge counts, node types, edge kinds, rules, and tree.
A practice holds the part the graph talks to, its *PracticeReading* (`practice.reading`), of the kind its class names (`reading_type`): how it reads a working copy into its graph and links its nodes to the practices it reads after (`read_working_copy()`), the graph rules it checks (`graph_checks`), and which of its node types are classes, members, read in source order, or anchored to a rule's subject (`class_types`, `member_types`, `source_ordered_types`, `anchor_types`, `rule_types`), so the graph names no practice's types. *GraphOverlay* is what a pattern adds on top; a pattern makes it once and keeps it as `graph_overlay`. The patterns register their classes with *PatternOverlays*, and each graph holds one *PatternOverlays* (`graph.applied_patterns`), which makes each pattern the first time the graph applies it or reads its schemas, so the graph never imports a practice or a pattern in code. `PatternOverlays().names` lists every registered pattern, whether its folder holds practices yet or not, for a person to choose from; `available` lists only those that hold practices. The graph also holds one *SchemaEdges*, which reads the relationship fields of its practices' schemas, and of every pattern's schema for them (`overlay.practice_file`), the first time it records an edge.
*BuildOrder* and *WorkerBuild* run a graph build apart from the cdd server: in a call the server answers for a chat (`call.answers_a_chat`, which the MCP host sets on each chat's *ToolCall*), the graph writes what it holds and what to do as a *BuildOrder*, a worker process (`python -m harness.graph.graph_worker`) carries it out on a graph of its own (`graph.build.carry_out`) and reports its progress at most four times a second, and the graph then holds the *SavedGraph* the worker built; a failed worker raises *GraphBuildFailed* and leaves the graph as it was, since a refresh drops the files' nodes in the worker (`BuildStep.REFRESH`). Every operation that builds takes the call it serves (`call`), and builds in a worker only when that call answers a chat. `Graph.refreshed(paths, checked, call)` refreshes and writes the nodes of those files at checked as one change, which a validate checks; for a chat's call the worker writes them (*CheckedFiles*), so the server never serialises them. The build keeps the file of the worker's last answer (*HeldAnswer*), which counts every change to what the graph holds (`PracticeNodes.changed`); while it has not changed since, the next order names that file instead of the server writing the graph out, and a refresh's worker answers only what it changed (*GraphChanges*), which the graph's practices take in place (`GraphPractices.take`, each practice through its *PracticeRestore*, CDR 0003). The worker starts from what the graph held, read back as plain nodes, so on a refresh or a load of edited files only the nodes of the files in scope are parsed objects. A practice that builds its own nodes from another practice's, as DDD builds its building blocks from Clean Engineering's classes, takes them from `practice.in_graph.nodes_read_now(type)`, the nodes the load or refresh in progress read, and keeps what it built before for every other file; it then sees the same parsed objects whether the worker, the server, or a graph opened from its saved graph did the read. Every other reader of the graph, a practice's linking, a rule, a pattern's overlay, or UX's story links, reads a node only through what every node has: its id, name, type, and source, its saved facts (`node.get_fact`), and the graph's edges. Whatever it needs from a parsed object is a fact the object's model class lists in `graph_facts`, so a node read back from a saved graph answers it too, and a refresh links the nodes it kept to the nodes it read now from their facts (CDR 0002). Ids and checksums a saved graph keeps are computed with `zlib.crc32`, never `hash`, which Python salts per process. Anywhere else, such as a spec or a script, the graph builds in its own process. A node's file language is the name of the format, among its practice's and then every practice's formats, that reads the file's extension (`practice.format_reading(file)`).
*PracticeGraphRule* is one rule a practice checks on loaded nodes; a practice writes its rules as subclasses, and *RuleCheckContext* gives each check the practice, its graph, and the folder its source was read from, and reads the practice's nodes and edges (`context.nodes(type)`, `context.edges(kind)`, `context.node(node_id)`). Each finding is a *Violation*, kept on the node's *GraphRule*, saved in `graph.json`, and read back by the Validate action's report and the board. The framework checks one rule of its own in every practice, whatever the practice's schema lists (`FRAMEWORK_RULES`): *ConformsToSchema* (`conforms-to-schema`), content conforms to its schema. The practice's *PracticeSchema* lists each *RequiredRelationship* its schema and the applied patterns' schemas require (`requirements`: a field not written optional, `name?:`, that names only other schema types), and the rule fails each node lacking an edge of that field to a node of a target type, when the target's fidelity is at or before the practice's current fidelity (`current_stage`; with none, only targets its own fidelity creates). `PatternOverlays.checks_of` adds it to every practice's checks, and the schema gives it to every node type with its prose.
The explorer app in `harness/graph/app` reaches the same operations through the graph's TypeScript language adapter. `GRAPH_APP_PORTS` (`graph_app.py`, an *AppPorts* of harness/installation, read once) gives the app's ports from `app/ports.json`, the one file the app's Vite config and web server also read, so the server health report and the instance scripts never write a port of their own. The app's tests type-check it first (`npm test` runs `tsc --noEmit`). Its tests stand in for the cdd server, and answer `graph.filter_choices` with the answers Python recorded in `app/filter-choices.json` (`app/filter_choices_record.py` works them out with `Graph.filter_choices` on the fixture's practices, on a real *Graph* holding the fixture's nodes and edges, whose rule runs read the fixture's schema; `app/filter_choices_spec.py` fails while they are stale), so the tests hold no copy of the filter's rule.

- **Purpose:** Turn a working copy into a graph of its practices that rules can check and a person can explore, from an agent's tools or from the graph explorer.
- **Seam (terms):** Graph, GraphPractices, LoadScope, GraphBuild, GraphExplorer, PracticeNodes, EdgeIndex, PracticeRuleRun, PracticeRestore, CheckedFiles, Node, EdgeType (`edge.py`, below the graph and the schema edges, so neither imports the other), ModelNode, ModelChildren, Source, GraphOverlay, PracticeGraphRule, RuleCheckContext, Violation, SavedGraph, SavedNode, SavedPractice, SavedGraphOutdated, GraphChanges, PracticeChanges, HeldAnswer, PatternOverlays, PracticeSchema, ModelDetached, BuildOrder, BuildStep, WorkerBuild, GraphBuildFailed, PracticeInventory; the MCP operations `graph.load_working_copy`, `graph.load_files`, `graph.refresh`, `graph.save_json`, `graph.return_nodes`, `graph.explorer_trees`, `graph.inventory`, `graph.filter_choices`, `graph.source`, `graph.set_overlays`, `graph.overlay_of`; `@language_adapter(language="typescript")` on *Graph*
- **Dependencies (one-way):** harness/agent_tools, harness/guidance (*Rule*, *RulesCollection*, *Schema*, *PracticeGuidance*, *PracticeCatalogue*), harness/installation, harness/mcp, harness/annotations (*Name*). The practices and patterns depend on this module: a practice is a *PracticeGuidance* the graph is given (or, for a graph no session holds, makes from *PracticeCatalogue*, the one registry of practices), and a pattern owns its *GraphOverlay*, which the graph asks the pattern for, so no module here imports a practice. Each practice keeps the spec support that runs its rules on examples, and the specs of those rules, in its own `rules/` folder (`rule_examples.py`).

## Constraint

Load before you ask: every query operation answers from the graph last loaded or refreshed, so call `graph.load_working_copy` or `graph.load_files` first. After writing files, call `graph.refresh` with exactly those files; never add file-change detection, a watcher, or date checks. Pass `graph.load_files` the files being edited, so a check reads them as they are now without rebuilding or overwriting the saved graph. A folder is a module in the graph only when it owns `.context/module-context.md`; any other folder with source is a package inside the nearest such module. Write a new rule as a *PracticeGraphRule* in the practice that owns it, and a new node type on that practice's *PracticeGuidance* class, never in this module, so the graph stays the same for every practice. Give a graph the practices it holds (a session gives its own) and reach a practice's nodes through `practice.in_graph.nodes(type)`; never keep nodes or edges anywhere but the practice's part of the graph. A graph build asked for by a chat's call runs in a worker process (`GraphBuild.run`), never in the cdd server's interpreter: it is minutes of CPU-bound Python, and in the interpreter every chat shares it slowed the event loop until the server refused connections. Read a node in a reader or a rule through `get_fact`, its source, and the graph's edges, never through an attribute only a parsed object has or `getattr` with a default: a worker refresh holds every node it did not read again as a plain node, and such a read fails there or quietly finds less. Report a build's progress as it goes and let *ThrottledReporter* pass on at most four reports a second; every report a chat hears is a message the event loop sends.
