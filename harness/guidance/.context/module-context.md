# harness/guidance
*Guidance* is a body of practice an agent can follow: an overview, guidance, rules, templates, and the **instructions** that join them, read from markdown kept beside the class. A guidance class is an *AgentToolSet*, so the same words are installed as a skill, an MCP prompt, and rules files.
*PracticeGuidance* is one field of practice, such as Stories or Clean Engineering, that deepens through named stages. Each stage is a *FidelityGuidance* (Stories' `story_map`, then `scenarios`, then `acceptance_tests`), and the practice knows its current fidelity and format, the examples beside it, the Clean Engineering companion of each fidelity, and how to `render` an artifact into another format.
*Rule* is one named rule a practice holds (`one-way-deps`), with the text an agent checks work against. *RulesCollection* is a practice's or fidelity's rules together with where they apply: always, or to files matching a glob. A practice's rules are injected into the chat when a file they apply to is edited.
*PracticeCatalogue* is the one list of practices CDD ships, in the order the approach walks them (Stories, DDD, UX, Clean Engineering, BDD), so the board, the graph, and the catalog read the same practices; `toolset_ref` gives the toolset an action lists for a practice's or fidelity's slug.
*ActionCatalogue* is the one list of actions CDD ships, found from the action folders under `cdd_guidance/actions`: each folder's kit, and each operation it publishes as a skill is one *Action* (generate, repair, createRule). The catalog, the session log, and the prompt notifier read it, and a new action folder joins it by being there.
*Schema* reads one practice's `model/schema.yaml` (or a pattern overlay's `rules.yaml`) into its types, fields, and rule slugs, so the graph and the fidelity map see the same types.
*GuidanceProbe* checks an install's practice and fidelity instructions and calls each guidance action with probe arguments; a person runs it as `guidance-diagnostics.guidance_diagnostics` (`/guidance-diagnostics`) and reads the result under `guidance` in `diagnostics.json`.

- **Purpose:** Let a practice be one class plus its markdown, with fidelities, rules, templates, and examples an agent can follow and a validator can check against.
- **Seam (terms):** Guidance, PracticeGuidance, FidelityGuidance, Rule, RulesCollection, PracticeCatalogue, ActionCatalogue, Action, Schema, GuidanceProbe; each practice's and fidelity's instructions published as MCP prompts under its slug (`stories`, `stories-story-map`); the MCP operation `guidance-diagnostics.guidance_diagnostics`
- **Dependencies (one-way):** harness/agent_tools, harness/markdown, harness/installation, harness/mcp, harness/hooks (rules are injected on a hook), harness/guidance_actions, space/session, tools/prompt_notify (imported through `sys.path` as `prompt_notify`), cdd_guidance/practices/clean_engineering (the companion fidelity), every practice through *PracticeCatalogue*'s class references, and every action kit through *ActionCatalogue*'s folders. Most of these import this module back: the framework modules, space/session, and the practices form one dependency cycle with it, listed in `.sessions/_backlog/break-module-dependency-cycles.md`.

## Constraint

Subclass *PracticeGuidance* for a new practice and keep its words in `{practice}.md` beside the class (Overview, Guidance, shared rules, a section per fidelity with its Rules), so the installer, the catalog, and the validator all read the same text. Reach another practice's fidelity through the practice's `fidelities`, and a fidelity's Clean Engineering companion through `PracticeGuidance.clean_engineering_companion`, rather than joining companion text in a subclass. Convert artifacts with `PracticeGuidance.render`, and put each format's adapter under `{practice}/model/{format}/`, so one practice has one object model behind every format. A caller that changes a practice's current fidelity or format makes its own instance with `PracticeCatalogue.create(key)`, because the shared instance is read by every other caller.
