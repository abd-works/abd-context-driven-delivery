# harness/guidance_actions
*GuidanceAction* is the shared start of every action an agent runs on practice guidance (Generate, Validate, Document, Sketch, Partition, ...): the action is subclassed once, and the cdd server makes a new action for each call with `for_call(call)`, made for the session that call works in and working on the guidance it names; the action logs the call there and runs the operation once for every guidance listed. The session is the one a board command names in a `session=` word, else the one open in the call's project; an action started inside another (`_inside`) is made for that action's session. An action made for no session, such as one listed for install, logs nothing.
*GuidanceArg* is what a caller passes as `guidance`: a slug they type (`stories`, `clean-engineering-model`), a list of slugs that runs the action once per slug, a `{toolset, fidelity}` reference, or any other string, which the action runs on once as text. Inside an operation the action reads that guidance back with `listed()` and runs work per item with `each(...)` and `run(...)`, so each listed practice is the one object its session holds.

- **Purpose:** Give every guidance action the same way to take guidance, open its session, and run once per listed guidance, so each action holds only its own words and steps.
- **Seam (terms):** GuidanceAction, GuidanceArg, ActionWorksInNoSession; `for_call(call)`, `made_for(session)`, `listed()`, `each(...)`, `run(...)`, `session`
- **Dependencies (one-way):** harness/agent_tools (*ToolCall*, which opens the session a call works in and the session a `session=` word names; a guidance action explains its `guidance` parameter through `parameter_notes`), harness/guidance (*PracticeCatalogue* turns a slug into a practice and fidelity), harness/hooks (*Hook*, and `rules_toast`, the toast `inject_rules` gives in its result), harness/marks (`@Toast`), harness/name. Nothing in the framework imports this module, and it imports nothing above the framework.

## Constraint

Subclass *GuidanceAction* for a new action and mark its operations `@agent_tool` or `@agent_instructions`; take `guidance: GuidanceArg` as the parameter rather than parsing slugs yourself, so every action reads guidance the same way. Read the guidance through `listed()` and the session through `session`; never reach for a current session, because one cdd server answers every chat and a call must act on its own session. Start an inner action with `_inside(...)`, so it is made for this action's session and works on the same practice objects. Pass `paths` to name files on an MCP call and let the action read them; leave the document body out of the call.
