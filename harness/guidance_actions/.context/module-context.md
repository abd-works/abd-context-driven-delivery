# harness/guidance_actions
*GuidanceAction* is the shared start of every action an agent runs on practice guidance (Generate, Validate, Document, Sketch, Partition, ...): the action is subclassed once, and the cdd server makes a new action for each call with `for_call(call)`, made for the session that call works in and working on the guidance it names; the action logs the call there and runs the operation once for every guidance listed. The session is the one a board command names in a `session=` word, read once into the action's *GuidanceCommand*, else the one open in the call's project; an action a subclass starts inside another is made for that action's session and call, and holds that action, which it asks for the practices it works with and the fidelity it works at on each. An action is made from its call alone: the call names the chat its log lines point at and says whether a graph build it starts runs in a worker. An action made for no session, such as one listed for install, logs nothing. What the agent following an action's instructions is told about the session it works in is the action's *SessionBrief* (`action.brief`): the session, the project root paths are named from, the session's root and where each listed practice writes (`session_context`), and the shared rules of each pattern the work is held to with the stories the session's increment is about (`overlay_rules(paths)`).
*GuidanceArg* is what a caller passes as `guidance`: a slug they type (`stories`, `clean-engineering-model`), a list of slugs that runs the action once per slug, a `{toolset, fidelity}` reference, or any other string, which the action runs on once as text. A board or chat-bar command adds words to it, which are chat text a person reads and an agent sends on as the guidance: the session it is for (`session=`), the pattern overlays it runs with (`overlays=`, comma separated), and the formats it writes in (`format=`). The call's guidance is read once, where the call arrives, into a *GuidanceCommand* (`GuidanceCommand.from_guidance`: the guidance without those words, `session_file`, `overlays`, `formats`), which the action holds from then on, so nothing below the call reads the text again (`cdr/0001-the-session-word-is-read-at-the-call.md`). *GuidanceArgument* reads the command's guidance once into the practice and fidelity objects of the action's own set, a *PracticeSet* (*NamedGuidance*: the object and the format it is written in, once for each format the command names that it writes): the session's practices, or a set the action makes when it works in no session, so no slug is looked up again. Taking the command chooses its overlays on the session first (`session.choose_overlays`), so the action and the session's graph run with them; a command that names none leaves the session's overlays as they are, and an `overlays=` word with nothing after it clears them. Inside an operation the action reads that guidance back with `listed()` and runs work per item with `each(...)` and `run(...)`, so each listed practice is the one object its session holds. The action holds what it works on in its *WorkList* (`action.work`): the guidance read once, and the fidelity it works at on each listed practice (`fidelity_of(guidance)`); an inner action holds a list made inside its outer action's, which answers the practices and fidelities it names none of itself. The action asks that *FidelityGuidance* for its instructions, rules, templates, and format, so two calls on two fidelities of one practice never mix their text. `each(...)` hands each operation that held fidelity rather than the practice (`practice_of(guidance)` gives the practice back), and an operation returns its text, because a recipe expansion only reads what a line returns. An inner action started on a fidelity works on its practice at that fidelity. This module registers *FidelityActionRunner* with the action catalogue, so a fidelity runs an action on itself (`fidelity.actions.generate(format="drawio")`): the runner makes the action and hands its work list that fidelity (`action.work.take_fidelity`). One word sent alone that is shaped like a slug and names no practice or fidelity, such as `stories_story_map`, is a misspelt slug and raises *UnknownGuidance*, as the same word in a list does; only a string of several words runs as text. A mapping's `toolset` is a slug or a `module:Class` ref, and a mapping with none raises *GuidanceMappingNamesNoToolset*. An action reads the paths a call names through `files.paths_to_read`, which refuses a path that is not there or not under the session's root.

- **Purpose:** Give every guidance action the same way to take guidance, open its session, and run once per listed guidance, so each action holds only its own words and steps.
- **Seam (terms):** GuidanceAction, GuidanceArg (a *GuidanceEntry* or a list of them), ListedGuidance (what `listed()` holds: a practice of the set, or a toolset made from a ref), WorkedGuidance (what `each` hands an operation: listed Guidance at its fidelity, or text), ActionSession (what an action asks of space/session's *Session*, named without importing it), ActionWorksInNoSession, GuidanceCommand (the guidance a call sends, read once: its guidance, `session_file`, `overlays`, `formats`), SessionBrief (`action.brief`: `session_context`, `overlay_rules(paths)`), UnknownGuidance (a listed word no practice or fidelity has as its slug; its message lists the slugs there are), GuidanceAgentOperation (an action's `@agent_tool`, whose call is logged as the action, such as `render`, rather than as a `tool` line), `injects_rules`; `for_call(call)`, `listed()`, `run(...)`, `log_running(action)`, `session`; its *WorkList* (`action.work`, which a recipe asks for the fidelity it works at, `work.fidelity_of(guidance)`, and a practice, `work.practice_of(guidance)`: `each(...)`, `at_fidelity(guidance)`, `rules_to_follow`, each listed guidance's shared and fidelity rules, read from the held fidelity, checking nothing); its *ActionFiles* (`action.files`: `path_named(path)`, `read(content, paths)`, the document a call names, and `wrote(paths)`, which refreshes the session's graph with the files the action wrote); `source_label(content, paths)`. An action's subclasses make an action of their kind for a session with `_made_for` and list another action as a tool with `_tool_inside(action_type)`
- **Dependencies (one-way):** harness/agent_tools (*ToolCall*, which opens the session a call works in and the session a `session=` word names; a guidance action explains its `guidance` parameter through `parameter_notes`), harness/guidance (a practice answers to a slug; *PracticeCatalogue* makes a set for an action with no session), harness/hooks (*Hook*, `@Toast`, and `rules_toast`, the toast `inject_rules` gives in its result), harness/annotations (*Name*). Nothing in the framework imports this module, and it imports nothing above the framework.

## Constraint

Subclass *GuidanceAction* for a new action and annotate its operations `@agent_tool` or `@agent_instructions`; take `guidance: GuidanceArg` as the parameter rather than parsing slugs yourself, so every action reads guidance the same way. Read the guidance through `listed()` and the session through `session`; never reach for a current session, because one cdd server answers every chat and a call must act on its own session. Start an inner action from the running action, never with its own `for_call`, so it is made for this action's session and works on the same practice objects. An action whose result is not an edit, such as Document, sets `injects_rules = False`, so its hook adds no rules. Pass `paths` to name files on an MCP call and let the action read them; leave the document body out of the call.
