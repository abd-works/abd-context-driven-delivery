# harness/guidance_actions
*GuidanceAction* is the shared start of every action an agent runs on practice guidance (Generate, Validate, Document, Sketch, Partition, ...): the action is subclassed once, and the cdd server makes a new action for each call with `for_call(call)`, made for the session that call works in and working on the guidance it names; the action logs the call there and runs the operation once for every guidance listed. The session is the one a board command names in a `session=` word, else the one open in the call's project; an action a subclass starts inside another is made for that action's session. An action made for no session, such as one listed for install, logs nothing.
*GuidanceArg* is what a caller passes as `guidance`: a slug they type (`stories`, `clean-engineering-model`), a list of slugs that runs the action once per slug, a `{toolset, fidelity}` reference, or any other string, which the action runs on once as text. Inside an operation the action reads that guidance back with `listed()` and runs work per item with `each(...)` and `run(...)`, so each listed practice is the one object its session holds. The action holds the fidelity it works at on each listed practice (`fidelity_of(item)`) and asks that *FidelityGuidance* for its instructions, rules, templates, and format, so two calls on two fidelities of one practice never mix their text. `each(...)` hands each operation that held fidelity rather than the practice (`practice_of(item)` gives the practice back), and an operation returns its text, because a recipe expansion only reads what a line returns. An inner action started on a fidelity works on its practice at that fidelity. This module registers *FidelityActionRunner* with the action catalogue, so a fidelity runs an action on itself (`fidelity.actions.generate(format="drawio")`).

- **Purpose:** Give every guidance action the same way to take guidance, open its session, and run once per listed guidance, so each action holds only its own words and steps.
- **Seam (terms):** GuidanceAction, GuidanceArg, ActionWorksInNoSession, `injects_rules`; `for_call(call)`, `made_for(session)`, `listed()`, `fidelity_of(item)`, `at_fidelity(item)`, `practice_of(item)`, `work_on_fidelity(fidelity)`, `log_running(action)`, `each(...)`, `run(...)`, `session`, `path_named(path)`, `document_named(content, paths)`, `source_label(content, paths)`
- **Dependencies (one-way):** harness/agent_tools (*ToolCall*, which opens the session a call works in and the session a `session=` word names; a guidance action explains its `guidance` parameter through `parameter_notes`), harness/guidance (*PracticeCatalogue* turns a slug into a practice and fidelity), harness/hooks (*Hook*, and `rules_toast`, the toast `inject_rules` gives in its result), harness/annotations (`@Toast`, *Name*). Nothing in the framework imports this module, and it imports nothing above the framework.

## Constraint

Subclass *GuidanceAction* for a new action and annotate its operations `@agent_tool` or `@agent_instructions`; take `guidance: GuidanceArg` as the parameter rather than parsing slugs yourself, so every action reads guidance the same way. Read the guidance through `listed()` and the session through `session`; never reach for a current session, because one cdd server answers every chat and a call must act on its own session. Start an inner action from the running action, never with its own `for_call`, so it is made for this action's session and works on the same practice objects. An action whose result is not an edit, such as Document, sets `injects_rules = False`, so its hook adds no rules. Pass `paths` to name files on an MCP call and let the action read them; leave the document body out of the call.
