# harness/installation
*RepositoryToolsets* finds every toolset class in one repository by reading its source, and puts the folders that load them on the import path; the installer (harness/installer), the hook server, and the MCP host each read the repository this way, so all three publish the same toolsets.
A member's destination is chosen with a mark on it: `@skill`, `@command("name")`, `@rules` (defined here), `@mcp` (harness/mcp), or `@Hook("event")` (harness/hooks); each is a *Destination* from harness/marks. A member with no destination mark stays in-process. `@noDeploy` keeps a member out of every destination, and `@noCatalog` keeps it out of the generated catalog without changing what is installed.
*ContextConfig* is a project's `.context/config.json` (`CONTEXT_FOLDER` names the `.context` folder once): the guidelines that apply to file patterns, which the hook server reads to decide whether a pattern's hooks run, and the folder each practice writes in, which a session reads.
`RepositoryToolsets.import_modules()` imports the module of every toolset the repository defines without making one, so a process that serves only some toolsets, as the hook server does, still has every registration those modules make.
*Installation* writes one destination's files: *FileInstallation* writes skills, commands, and rules, and harness/mcp and harness/hooks each extend *Installation* for their own channel, so a new channel is one more pair rather than a change to the installer.
`@language_adapter(language="typescript")` on a toolset class publishes its `@mcp` operations as typed TypeScript, so an application outside Python calls the same tools as typed objects; `@identity(...)` on a class names the data fields that name one of its objects, the ones a tool loads it by. `@data_field` under `@property` marks a property as part of the object's data, and `@data_field(reference=True)` sends the object it holds by its identity alone, so data can name an object that is sent in full elsewhere; `@edits("field")` names the field an operation changes when its argument is called something else, and *SourceFile* marks a field that holds a path in the session's workspace. `data_of(value)` is the one way an object becomes JSON data, for every MCP answer and every language adapter type alike.

- **Purpose:** Give every channel the marks, the data, and the writer it publishes a member with, and find the toolsets a repository defines.
- **Seam (terms):** RepositoryToolsets, ContextConfig, MalformedContextConfigError, `CONTEXT_FOLDER`, Installation, FileInstallation, LanguageAdapterInstallation, SourceFile; the marks `@skill`, `@command`, `@rules`, `@noDeploy`, `@noCatalog`, `@language_adapter`, `@identity`, `@data_field`, `@edits`; `data_of(value)`
- **Dependencies (one-way):** harness/agent_tools, harness/marks, harness/markdown, harness/name. harness/hooks, harness/mcp, and harness/installer depend on this module; it imports none of them.

## Constraint

Put the destination mark on the member, never in a list on the toolset, so moving a member moves its publication with it. Read the repository's toolsets and import path through *RepositoryToolsets*, so every reader skips the same folders. Import this package as `harness.installation`, and leave `harness/` off `PYTHONPATH`, so `import mcp` loads the MCP SDK.
