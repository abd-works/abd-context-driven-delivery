# harness/installer
*Installer* publishes every marked toolset member in one repository into an IDE's folder (`.claude`, `.cursor`, `.github`, Kilo), so an author never writes a skill, command, rules file, MCP entry, or hook entry by hand. A person runs it as `/install`, or `python scripts/install.py --ide Claude`, and `/clean` removes what it wrote. It is made for the repository it installs (`Installer(ide, path, repo=...)`, or `Installer.load(project=...)` for the project a call names), never for the checkout its own code sits in, because one server installs many projects. It finds the toolsets with *RepositoryToolsets* (harness/installation), writes each member through the installation of every channel its marks name (files and language adapters from harness/installation, MCP from harness/mcp, hooks from harness/hooks), then starts the hook server and the cdd server and installs the board and cdd plugins (`claude_plugins`), so a finished install answers at once.
The install record (`record`) is the list of files the last install wrote; a record that cannot be read stops the install and the clean with *InstallRecordUnreadable* rather than being written over, so no installed file is forgotten. `diagnostics` is the install's `diagnostics.json`: `write_section(section, results)` adds one section coloured by its worst result, which is how the diagnostics probes report. An install that fails names the toolset and its cause (*ToolsetInstallFailed*), or the hook server that is not running (*HookServerNotRunning*).

- **Purpose:** Install one repository into one IDE folder through every channel, from one walk of the repository, and start what that install needs running.
- **Seam (terms):** Installer (`install`, `install_self`, `clean`, `ensure_runtimes`, `ensure_mcp_server`, `diagnose_install`, `toolsets`, `record`, `diagnostics.write_section`, `claude_plugins`), ToolsetInstallFailed, HookServerNotRunning, InstallRecordUnreadable; `/install`, `/clean`; `python scripts/install.py`
- **Dependencies (one-way):** harness/agent_tools, harness/installation, harness/markdown, harness/hooks (*HookDaemon*, *HookInstallation*), harness/mcp. It sits at the top of the publishing chain: none of these imports it; harness/diagnostics does.

## Constraint

Change installed files only by changing the marked source and installing again; `.claude/`, `.cursor/`, `.github/`, `.mcp.json`, and the `cdd` entry in `~/.claude.json` are overwritten on every install. Name the repository on every *Installer* you make. Install into an IDE folder that exists: when the install record names a folder that is gone, the install goes to `{repo}/.cursor`. Code that only needs the repository's toolsets or its import path reads *RepositoryToolsets*, not the Installer, so it does not depend on every channel.
