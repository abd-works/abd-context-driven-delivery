# harness/whiteboard
*Whiteboard* is a Claude Whiteboard board as a practice draws it: its title and its elements in back-to-front order, saved as a `.whiteboard` file in the session and loaded back from one. A practice renders its model to a *Whiteboard* and parses its model from one, as it does with a `.drawio` file; the board in Claude is the Whiteboard artifact whose store holds the same `board/meta` and `elements/<id>` records. `Whiteboard.batches(previous)` answers the store writes that turn the board as it was into this one, in batches the store takes, so an agent sends them to the artifact's store and never rebuilds a board people have worked on. `Whiteboard.drawn_over(previous)` saves a board drawn over the file it replaces, every element the file held kept where people put it (`keep_places`).

*BoardElement* is one record on a board, under its *ElementId*. A practice builds its elements directly as the kind each is: *Shape* for a block (an epic bar, a story card, a class or module box), *Section* for a container that holds other elements under a title (`HOLDS_OTHERS`), *Label* for words with no box, and *Arrow* for a line joining two elements by their ids; *OtherElement* keeps a record no practice draws, such as a person's note. A practice reads a board back through the board's typed `sections`, `shapes`, `labels` and `arrows`, each element whole however many pieces it was drawn in, and `holding(roles, missing)` refuses a board that holds none of the roles the practice draws as an *UnreadableBoard*.

*ElementId* is an element's id, which is how a board already published in Claude is updated in place: its role, then its parts, joined by dots (`story.user.a1b2c3d4e5`), answering `role`, `parts` and `key`. A node keeps one id from one render to the next because its key is the hash of its names (`ElementId.of(role, *names, length)`), the one hash every practice keys its elements with; each practice keeps the length of that key on its nodes (`WhiteboardNode.KEY_LENGTH`: Clean Engineering 12, the others 10), so no board already published is redrawn.

*WhiteboardNode* is what a practice's diagram node mixes in to be drawn on a board: it answers the elements it draws, placed at the box the diagram already gave it, as `DrawioVertex` does for a draw.io cell. A node drawn on the previous board keeps the place a person moved it to (`Whiteboard.keep_places(previous)`).

`Whiteboard.links_beside(file)` is the *PublishedLinks* (harness/installation) of the boards the `.whiteboard` files in a folder were published to, kept in the folder's `whiteboards.json` (`Whiteboard.LINKS`) by each file's name: the Render action's `record_board` writes it once the agent has created the board in Claude, and the session's file list reads it, so the Files app opens the board instead of the file.

*WhiteboardFile* is the one reader of a `.whiteboard` file for a page: `whiteboard-file.show`, published through `@language_adapter`, answers the board a file in the project holds, its title and its whole sections, shapes, labels and arrows as data (`WhiteboardData`, `@data_fields` on *Box* and *BoardElement*, with each block's `lines` and a shape's `is_rounded` and a label's `is_title` beside its fields), so the Files app draws the board from that and never reads the file's records in TypeScript; a file that holds no board is refused as an *UnreadableBoard*.

*StoreWrite* is one write to the artifact's store: set a record, update its changed fields, or delete it; an agent sends them as the entries `Whiteboard.batches(previous)` answers.

*KeepsDocumentOnBoard* is what a practice's whiteboard format mixes in, ahead of its model, to keep the document a board was drawn from (*SourceDocument* of harness/markdown) in the board's meta (`Whiteboard.kept_document`, written as `document` beside the title and the order, so the board in Claude keeps it too): `keeping` writes it there and `document_kept_in` reads it back, as *KeepsDocumentInDrawing* does for a draw.io file.

- **Purpose:** Let any practice draw its diagram on a Claude Whiteboard and read it back, with one board format, one element id, and one way of updating a board in Claude.
- **Seam (terms):** KeepsDocumentOnBoard (`keeping`, `document_kept_in`), Whiteboard (`kept_document`, `title`, `sections`, `shapes`, `labels`, `arrows`, `holding`, `batches`, `drawn_over`, `links_beside`), WhiteboardFile (`whiteboard-file.show`), BoardElement, Shape, Section, Label, Arrow, ElementId (`of`, `read`, `role`, `parts`, `key`), WhiteboardNode (`KEY_LENGTH`), Box, UnreadableBoard
- **Dependencies (one-way):** harness/installation, for the JSON record of published addresses and the data annotations; harness/markdown, for *Format* and *SourceDocument*; harness/agent_tools and harness/mcp, for *WhiteboardFile*'s tool.

The practices' whiteboard packages (`model/whiteboard` in each practice), the Render action, the session's file list and the Files app (through the generated `whiteboard-file` adapter) depend on it; it names no practice and no diagram type, so a *WhiteboardNode* is handed the box it is drawn in.

## Constraint

Build a board by drawing practice nodes, each a *WhiteboardNode*, and read one through its practice's whiteboard model; never write `board/meta` or `elements/<id>` by hand. Send a rendered board to Claude only as the batches of writes `Whiteboard.batches(previous)` answers, read against the board as it is in Claude, because people move, add and colour elements on a shared board and a whole rewrite would lose what they did. Key a drawn node's element with `ElementId.of` at its practice's key length: a different hash or length gives every element of a published board a new id, and the next render redraws it all and loses where people moved them. Element ids keep to the store's characters (`[A-Za-z0-9_.~:@+-]`, at most 40).
