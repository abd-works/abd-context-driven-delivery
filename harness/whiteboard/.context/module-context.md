# harness/whiteboard
*Whiteboard* is a Claude Whiteboard board as a practice draws it: its title and its elements in back-to-front order, saved as a `.whiteboard` file in the session and loaded back from one. A practice renders its model to a *Whiteboard* and parses its model from one, as it does with a `.drawio` file; the board in Claude is the Whiteboard artifact whose store holds the same `board/meta` and `elements/<id>` records. `Whiteboard.batches(previous)` answers the store writes that turn the board as it was into this one, in batches the store takes, so an agent sends them to the artifact's store and never rebuilds a board people have worked on.

*BoardElement* is one record on a board, under its element id, made by its factories: `BoardElement.shape(id, box, ...)` for a block (an epic bar, a story card, a class or module box), `section(id, box, ...)` for a container that holds other elements under a title (`HOLDS_OTHERS`), `words(id, corner, ...)` for a label with no box, and `arrow(id, from_id=..., to_id=...)` for a line joining two elements by their ids. The kinds behind the factories (*Shape*, *Section*, *Label*, *Arrow*, and *OtherElement* for a record no practice draws) stay inside the module: a practice reads a board back through the board's `sections`, `shapes`, `labels` and `arrows`, each element whole however many pieces it was drawn in, and `holding(roles, missing)` refuses a board that holds none of the roles the practice draws as an *UnreadableBoard*. An element's id names the kind of practice node it draws and a stable key of that node, so a board read back says which node each element was, and the same node keeps its id from one render to the next.

*WhiteboardNode* is what a practice's diagram node mixes in to be drawn on a board: it answers the elements it draws, placed at the box the diagram already gave it, as `DrawioVertex` does for a draw.io cell. A node drawn on the previous board keeps the place a person moved it to (`Whiteboard.keep_places(previous)`).

*BoardLinks* keeps the address of the board each `.whiteboard` file in a folder was published to, in the folder's `whiteboards.json`, by the file's name: the Render action's `record_board` writes it once the agent has created the board in Claude, and the session's file list reads it, so the Files app opens the board instead of the file.

*StoreWrite* is one write to the artifact's store: set a record, update its changed fields, or delete it; an agent sends them as the entries `Whiteboard.batches(previous)` answers.

- **Purpose:** Let any practice draw its diagram on a Claude Whiteboard and read it back, with one board format and one way of updating a board in Claude.
- **Seam (terms):** Whiteboard (`sections`, `shapes`, `labels`, `arrows`, `holding`, `batches`), BoardElement (`shape`, `section`, `words`, `arrow`), WhiteboardNode, Box, BoardLinks (`beside`, `of`, `record`)
- **Dependencies (one-way):** none. The practices' whiteboard packages (`cdd_guidance/practices/stories/model/whiteboard`, `cdd_guidance/practices/clean_engineering/model/whiteboard`), the Render action (`cdd_guidance/actions/render`) and the session's file list depend on it; it names no practice and no diagram type, so a *WhiteboardNode* is handed the box it is drawn in.

## Constraint

Build a board by drawing practice nodes, each a *WhiteboardNode*, and read one through its practice's whiteboard model; never write `board/meta` or `elements/<id>` by hand. Send a rendered board to Claude only as the batches of writes `Whiteboard.batches(previous)` answers, read against the board as it is in Claude, because people move, add and colour elements on a shared board and a whole rewrite would lose what they did. Element ids keep to the store's characters (`[A-Za-z0-9_.~:@+-]`, at most 40).
