# Keep Generated Assets Guided By Their Context Tools
* approx 5-7 total stories

## Deliver Guidance Once Per Chat, Then Reuse It

### Agent --> Edit A Governed Asset
given an asset - any file a context tool generated (production code, tests, story docs, or another context tool's own source) - stamped at generation time with one or more `# @toolset-manifest` / `# invoke-edit` header lines naming its governing toolset(s)

#### touching a governed asset for the first time this chat delivers its governing tool's guidance
given the asset above, header intact, not yet touched earlier in this chat
when the Agent reads it, or is about to edit it
then the gate runs each named governing toolset's manifest and delivers the full guidance - that toolset's tools, actions, and each action's instructions (generate, document, validate, satisfy, …) - into the Agent's context

#### the edit proceeds directly on that same touch
when the Agent then edits the asset
then the edit proceeds directly - it is never held pending a separate "run compliance yourself first" step

#### touching the same asset again this chat just refers back to guidance already delivered
given the same asset, its manifest guidance already delivered earlier in this chat
when the Agent touches it again
then the gate checks whether that guidance already appears in context
and the gate does not require that the manifest be run before an edit is made
and the Agent keeps using the guidance it already has, with nothing re-run and nothing re-injected

#### a governing tool's own source is itself a governed asset
given a context tool's own source file (e.g. context_tools/bdd/bdd.py, context_tools/clean_engineering/clean_engineering.py) - itself generated by another context tool (CreateContextTool, BDD, …) and header-stamped the same way as any asset that tool generates for others
when the Agent is about to edit that context tool's own source
then the gate delivers that file's own governing toolset's guidance, the same as it would for any other generated asset

#### the recursion has no floor - base primitives are governed too
given a base primitive's own source file (e.g. primitives/assets/assets.py) - itself generated by a context tool (e.g. BDD) and header-stamped the same way
when the Agent touches that base primitive's own source
then the gate still delivers its governing toolset's guidance - no tool is too foundational to be exempt from the guidance of whichever tool generated it

## Treat A Missing Manifest As Exceptional

### Agent --> Recover From A Manifest That Won't Load
given an asset whose header names a governing toolset, and the toolset's manifest command errors or times out when the gate runs it
when the gate retries the manifest command 2 times
then a correctly configured manifest succeeds on retry - this should not happen if the toolset is set up correctly
    and when every retry still fails
    then the gate raises one super-obvious, all-caps failure notification through the IDE's own notification channel - not buried agent text - so the user cannot miss it
    and this is treated as exceptional, never a silent skip

#### normal mode confirms a hook-triggered manifest run
given a mode setting of normal for the context tools configuration
when a toolset's manifest command executes because a hook touched a governed asset
then one message confirms the manifest has been run

#### normal mode confirms a direct CLI-triggered manifest run too
given a mode setting of normal for the context tools configuration
when a toolset's manifest command executes via a direct `python -m tools manifest …` call, with no hook involved at all
then that same confirmation is emitted from the CLI's own manifest command (primitives/tools/cli.py `_manifest_main`)

#### verbose mode narrates each step of a hook-triggered manifest run
given a mode setting of verbose for the context tools configuration
when a governed asset is touched
then a message reports the hook firing
    and a further message reports the manifest command executing
    and a further message reports the manifest having loaded (output received and ready to deliver)
