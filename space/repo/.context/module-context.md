# space/repo
*Repo* is the local git clone of the project being worked on — its branches and its commits — so callers commit, push, merge, and delete work without running `git` themselves. `Repo.of_project(project)` is the clone holding the project a tool call names; the cdd server hands each repo tool its call's project, the folder the calling chat works in, so one server answers chats on several projects and checkouts and no repo tool takes a repository path. The process holds one Repo for each checkout it works in (*ServedCheckouts*), which `Repo.of_project` and `repo.worktrees.repository_at(folder)` answer, so every tool call and every session of one checkout works on the same Repo.

*Branch* is a line of development on a *Repo*: it is checked out, saved (committed and pushed), opened in its own worktree, landed on the default branch, and deleted. *Worktrees* (`repo.worktrees`) are the checkouts of the repository — the main clone and each linked worktree beside it — and a *Worktree* is one of them, where one branch is worked on while the main clone stays on the default branch. A ticket opens in its own worktree and closes it (space/kanban); the repository gives it the branches and worktrees to do so. *Commit* is a recorded snapshot whose message carries trailers such as `Ticket:`; git commit trailers are the record of why a change was made, so there is no second index of work to keep in step. `repo.git` is the clone's *Git* (harness/git), which runs the git command line with one set of time limits and one error, *RepoConnectError*, for every operation. *LatestRelease* keeps the end-to-end results of the release that just landed and removes older ones.

A push first merges in what origin's copy of the branch has (`origin.catch_up`), so work pushed from elsewhere never rejects it; a merge that conflicts is aborted, never left half done. Every branch appends to the same session logs, so a merge keeps both sides' lines of `.sessions/**/session.log`, and a branch check-out carries uncommitted changes along (`checkout -m`). Landing and deleting a branch, and listing and removing worktrees, run in the main clone, so they work whichever checkout the branch was found from.

A *Repo* makes its parts once and keeps them: `repo.git`, `repo.worktrees`, its *Refs* (`repo.refs.has(ref)`, read from the .git files where it can be, else asked of git), and its *WorkingTree* (`repo.working_tree`: `is_dirty(path)`, `is_merging`, and `commit(paths, message)`, which writes git's index while the repo's `writing_index` is held) are made with it, and `repo.main_clone` (the main checkout: the repository itself unless it is a linked worktree, and a folder in no repository is its own) is found once when first asked for. Callers read these instead of building a *Repo* or a *Worktrees* again from a folder path. `repo.current_branch` is the *Branch* checked out. Each *Worktree* keeps the *Worktrees* that listed it, which removes it when it closes, its own checkout's *Repo*, and the *Branch* checked out there, acting in that checkout; all three are made once, when it is listed, and a worktree is its folder and its branch.

The work sessions kept in the clone's `.sessions` folder are not the repository's concern: `space/session` owns them (*Sessions*), and the file manager that lists the checkout's files is the sessions' (`sessions.file_manager`).

The MCP tool `repo.push_commit` commits the working tree of the checkout its call names and pushes its branch; the command `/push` calls it. The MCP tools `repo.merge_to_main` and `repo.push_to_main`, the chat bar's ⇪ calling `push_to_main`, commit that checkout's work on its branch and merge the branch into main in the main clone, which then goes back to the branch it had; `push_to_main` also pushes the branch and main. Neither raises the version. `repo.push_work`, the chat bar's ⤴, commits and pushes the checkout's branch with nothing merged. Each of these tools asks the repository's *Publishing* (`repo.publishing`: `push_commit`, `push_work`, `take_work_to_main(push)`), which runs the steps that publish a checkout's work; the *Repo* itself only answers what git holds, and its *WorkingTree* commits. Main here is `Repo.default_branch`: the branch origin's HEAD names, else main or master, whichever the repository has, so a repository whose default is master merges into master. A repository `git init` made, with no commit yet, has the branch HEAD names as its default, which its first commit makes, so a `git init` that named master is not taken for main; only a default read from the refs is kept, so a folder made a repository after its first read, or given its first commit, is read again.

CDD works in a git repository. The MCP tool `repo.make_repository`, the chat bar's Create the git repository in a session whose project is a plain folder, makes that folder a git repository on main (*NewRepository*, `new_repository.py`): its `.gitignore` first takes what CDD writes into a project (`CDD_WRITTEN_PATTERNS`) and nothing else, so the first commit holds the folder's own files and not `.claude` or `.sessions`; a repository already there is left as it is. `repos.open` creates a new repository through the same *NewRepository*.

- **Purpose:** Give every caller one object graph for the clone, its branches and worktrees, and its commits, so version control is never reimplemented with raw `git` output.
- **Seam (terms):** Repo (its parts: Origin `repo.origin`, which pushes and catches up with origin; Merges `repo.merges`; Publishing `repo.publishing`, which commits, pushes, and takes work to main), ServedCheckouts (`SERVED_CHECKOUTS.serve(repo)`, which holds a given repository for its folder), MockGit (with its HeldOrigin `held.origin` and its HeldBranches `held.branches`, both HeldTrees, the one shape that keeps each branch's files and log; the branches `record_commit` what a checkout commits, and add, merge, and delete branches) and MockRepo (with MockOrigin, MockMerges, MockRefs, MockWorkingTree, MockBranch, and MockWorktrees, each reading the MockGit through its repository's `held`; one checkout of a MockGit, whose working tree reads that checkout's files and answers `commit` and `uncommitted` itself) (specs only: our Repo, Branch, and Worktrees answered from memory, recording each command, so a quick spec starts no git), Branch, Worktrees, Worktree, Commit, LatestRelease, `repo.git`, `repo.main_clone`, `repo.current_branch`, `repo.worktrees`, `worktrees.at(folder)`, `branch.open_in_worktree`, `branch.land_on_default`, `branch.merge_into_default`, `branch.delete`, `repo.origin.catch_up`, `repo.origin.push_upstream`, `repo.refs`, `repo.working_tree` (Refs, WorkingTree), `repo.working_tree.is_merging`, `repo.is_linked_worktree`, `repo.is_on_branch`, `repo.worktrees.listing`, CommitPathsRequiredError, CommitMessageRequiredError, WorktreeNotRemovedError, `Repo.of_project`, `repo.push_commit`, `repo.push_work`, `repo.merge_to_main`, `repo.push_to_main`, `repo.default_branch`
- **Dependencies (one-way):** `harness/agent_tools`, `harness/hooks` (*HookDaemon*, which a closing worktree asks to stop its checkout's hook daemon), `harness/installation`, `harness/mcp`, `harness/git` (*Git* and its *RepoConnectError*, which every repository operation raises when git fails), `space/work_state` (`SESSIONS_FOLDER` and `E2E_RESULTS_FOLDER`, where *LatestRelease* finds a release's results).

## Constraint

Callers pass the domain objects (*Repo*, *Branch*, *Worktree*, *Commit*), never `git` output as strings. A *Repo* acts only on the clone it was made for; to act on another clone, make a *Repo* for that clone, so a call can never change a clone it did not mean to. The repo tools take no repository path; they act on the clone of the project their call names. Run git only through `repo.git`, so every command gets the same time limits and the same error. Specs that need a repository make a real one in a temporary folder; there is no in-memory repository. A worktree is one only while its folder is on disk, whatever git still lists. `Worktrees.open` gives each branch a folder of its own beside the main clone and refuses a folder already there that is not that branch's checkout (`WorktreeFolderTakenError`, naming the branch and the folder); `Worktrees.remove` raises `WorktreeNotRemovedError` while the folder is still there, such as one a running program holds open. A merge git refuses is undone and raised as `MergeRefusedError`, a `RepoConnectError` naming both branches.
