# space/repo
*Repo* is the local git clone of the project being worked on — its branches and its commits — so callers commit, push, merge, and delete work without running `git` themselves. `Repo.of_project(project)` is the clone holding the project a tool call names; the cdd server hands each repo tool its call's project, the folder the calling chat works in, so one server answers chats on several projects and checkouts and no repo tool takes a repository path. The process holds one Repo for each checkout it works in (*ServedCheckouts*), which `Repo.of_project` and `repo.checkout_at(folder)` answer, so every tool call and every session of one checkout works on the same Repo.

*Branch* is a line of development on a *Repo*: it is checked out, saved (committed and pushed), opened in its own worktree, landed on the default branch, and deleted. *Worktrees* (`repo.worktrees`) are the checkouts of the repository — the main clone and each linked worktree beside it — and a *Worktree* is one of them, where one branch is worked on while the main clone stays on the default branch. A ticket opens in its own worktree and closes it (space/kanban); the repository gives it the branches and worktrees to do so. *Commit* is a recorded snapshot whose message carries trailers such as `Ticket:`; git commit trailers are the record of why a change was made, so there is no second index of work to keep in step. `repo.git` is the clone's *Git* (harness/process), which runs the git command line with one set of time limits and one error, *RepoConnectError*, for every operation. *LatestRelease* keeps the end-to-end results of the release that just landed and removes older ones.

A push first merges in what origin's copy of the branch has (`catch_up_with_origin`), so work pushed from elsewhere never rejects it; a merge that conflicts is aborted, never left half done. Every branch appends to the same session logs, so a merge keeps both sides' lines of `.sessions/**/session.log`, and a branch check-out carries uncommitted changes along (`checkout -m`). Landing and deleting a branch, and listing and removing worktrees, run in the main clone, so they work whichever checkout the branch was found from.

A *Repo* makes its parts once and keeps them: `repo.git` and `repo.worktrees` are made with it, and `repo.main_clone` (the main checkout: the repository itself unless it is a linked worktree, and a folder in no repository is its own) is found once when first asked for. Callers read these instead of building a *Repo* or a *Worktrees* again from a folder path. `repo.current_branch` is the *Branch* checked out. Each *Worktree* keeps the *Worktrees* that listed it, which removes it when it closes, its own checkout's *Repo*, and the *Branch* checked out there, acting in that checkout; all three are made once, when it is listed, and a worktree is its folder and its branch.

The work sessions kept in the clone's `.sessions` folder are not the repository's concern: `space/session` owns them (*Sessions*), and the file manager that lists the checkout's files is the sessions' (`sessions.file_manager`).

The MCP tool `repo.push_commit` commits the working tree of the checkout its call names and pushes its branch; the command `/push` calls it.

- **Purpose:** Give every caller one object graph for the clone, its branches and worktrees, and its commits, so version control is never reimplemented with raw `git` output.
- **Seam (terms):** Repo, ServedCheckouts, Branch, Worktrees, Worktree, Commit, LatestRelease, `repo.git`, `repo.main_clone`, `repo.current_branch`, `repo.worktrees`, `worktrees.at(folder)`, `branch.open_in_worktree`, `branch.land_on_default`, `branch.delete`, `repo.catch_up_with_origin`, `repo.push_upstream`, `repo.is_merging`, CommitPathsRequiredError, CommitMessageRequiredError, WorktreeNotRemovedError, `Repo.of_project`, `repo.push_commit`
- **Dependencies (one-way):** `harness/agent_tools`, `harness/hooks` (*HookDaemon*, which a closing worktree asks to stop its checkout's hook daemon), `harness/installation`, `harness/mcp`, `harness/process` (*Git* and its *RepoConnectError*, which every repository operation raises when git fails), `space/work_state` (`SESSIONS_FOLDER` and `E2E_RESULTS_FOLDER`, where *LatestRelease* finds a release's results).

## Constraint

Callers pass the domain objects (*Repo*, *Branch*, *Worktree*, *Commit*), never `git` output as strings. A *Repo* acts only on the clone it was made for; to act on another clone, make a *Repo* for that clone, so a call can never change a clone it did not mean to. The repo tools take no repository path; they act on the clone of the project their call names. Run git only through `repo.git`, so every command gets the same time limits and the same error. Specs that need a repository make a real one in a temporary folder; there is no in-memory repository.
