# space/repo
*Repo* is the local git clone of the project being worked on — its branches and its commits — so callers commit, push, merge, and delete work without running `git` themselves. `Repo.of_project(project)` is the clone holding the project a tool call names; the cdd server hands each repo tool its call's project, the folder the calling chat works in, so one server answers chats on several projects and checkouts and no repo tool takes a repository path. The process holds one Repo for each checkout it works in (*ServedCheckouts*), which `Repo.of_project` and `repo.worktrees.repository_at(folder)` answer, so every tool call and every session of one checkout works on the same Repo.

*Branch* is a line of development on a *Repo*: it is checked out, saved (committed and pushed), opened in its own worktree, landed on the default branch, and deleted. A branch answers where it is checked out: `is_checked_out` is true when any checkout of the repository has it, `is_checked_out_here` when the checkout it was found from has it, `checkout` is the *Repo* of the checkout that has it, and `linked_worktree` is that checkout when it is a linked worktree beside the main clone. `branch.save(commit_message, push=True)` is the one way to commit everything in the checkout that has a branch and push it when origin lacks some of it; `push=False` commits only. `repo.default_branch` is a *Branch*. *Worktrees* (`repo.worktrees`) are the checkouts of the repository — the main clone and each linked worktree beside it — each a *Repo*, where one branch is worked on while the main clone stays on the default branch: `worktrees.of(branch)`, `worktrees.at(folder)`, `worktrees.open(branch)`, and `worktrees.by_branch`, the checkout each branch is out in, read from git's listing so no git starts for each checkout. A linked worktree's *Repo* catches up with origin (`catch_up_with_origin`) and closes (`close(commit_message)`: its branch saved, its folder removed); `repo.is_main_clone` says which checkout is the main clone. A ticket opens in its own worktree and closes it (space/kanban); the repository gives it the branches and worktrees to do so. *Commit* is a recorded snapshot whose message carries trailers such as `Ticket:`; git commit trailers are the record of why a change was made, so there is no second index of work to keep in step. `repo.git` is the clone's *Git* (harness/git), which runs the git command line with one set of time limits and one error, *RepoConnectError*, for every operation. *LatestRelease* keeps the end-to-end results of the release that just landed and removes older ones.

A push first merges in what origin's copy of the branch has (`origin.catch_up`), so work pushed from elsewhere never rejects it; a merge that conflicts is aborted, never left half done. Every branch appends to the same session logs, so a merge keeps both sides' lines of `.sessions/**/session.log`, and a branch check-out carries uncommitted changes along (`checkout -m`). Landing and deleting a branch, and listing and removing worktrees, run in the main clone, so they work whichever checkout the branch was found from.

A *Repo* makes its parts once and keeps them: `repo.git`, `repo.worktrees`, its *Checkout* (`repo.checkout`, harness/git), whose *GitFacts* answer which branch is out, which commit, the branches, refs, origin, and worktrees, read from the .git files where they can be, else asked of git, so `branches`, `current_branch`, `is_on_branch`, `current_commit`, `has_origin`, and its *Refs* (`repo.refs.has(ref)`) each ask it in one line, and its *WorkingTree* (`repo.working_tree`: `is_dirty(path)`, `is_merging`, `commit(paths, message)`, and `commit_all(message)` for everything in the checkout, new files included; a commit writes git's index while the repo's `writing_index` is held) are made with it, and `repo.main_clone` (the main checkout: the repository itself unless it is a linked worktree, and a folder in no repository is its own) is found once when first asked for. Callers read these instead of building a *Repo* or a *Worktrees* again from a folder path. `repo.current_branch` is the *Branch* checked out. Each *Worktree* keeps the *Worktrees* that listed it, which removes it when it closes, its own checkout's *Repo*, and the *Branch* checked out there, acting in that checkout; all three are made once, when it is listed, and a worktree is its folder and its branch.

The work sessions kept in the clone's `.sessions` folder are not the repository's concern: `space/session` owns them (*Sessions*), and the file manager that lists the checkout's files is the sessions' (`sessions.file_manager`).

The MCP tool `repo.push_commit` commits the working tree of the checkout its call names and pushes its branch; the command `/push` calls it. The MCP tools `repo.merge_to_main` and `repo.push_to_main`, the chat bar's ⇪ calling `push_to_main`, commit that checkout's work on its branch and merge the branch into main in the main clone, which then goes back to the branch it had; `push_to_main` also pushes the branch and main. Neither raises the version. `repo.push_work`, the chat bar's ⤴, commits and pushes the checkout's branch with nothing merged. Each of these tools asks the repository's *Publishing* (`repo.publishing`: `push_commit`, `push_work`, `take_work_to_main(push)`), which runs the steps that publish a checkout's work; the *Repo* itself only answers what git holds, and its *WorkingTree* commits. Main here is `Repo.default_branch`: the branch origin's HEAD names, else main or master, whichever the repository has, so a repository whose default is master merges into master. A repository `git init` made, with no commit yet, has the branch HEAD names as its default, which its first commit makes, so a `git init` that named master is not taken for main; only a default read from the refs is kept, so a folder made a repository after its first read, or given its first commit, is read again.

CDD works in a git repository. The MCP tool `repo.make_repository`, the chat bar's Create the git repository in a session whose project is a plain folder, makes that folder a git repository on main (*NewRepository*, `new_repository.py`, which takes the folder's *Repo* and answers a *MadeRepository*: whether a repository was there already, its branch, and the lines its .gitignore was given, which the tool words): its `.gitignore` first takes what CDD writes into a project (`CDD_WRITTEN_PATTERNS`) and nothing else, so the first commit holds the folder's own files and not `.claude` or `.sessions`; a repository already there is left as it is. `repos.open` creates a new repository through the same *NewRepository*.

*Repos* (`repos.py`) are the repositories CDD works on beside one another, in the folder the person's `~/.cdd/config.json` keeps as `repos_folder` (*CddConfig*). The MCP tool `repos.set_folder` (`/repos-folder`) chooses that folder, `repos.siblings` (`/repos`) lists each repository there as a *SiblingRepo*, which holds that repository's *Repo*, with its branch, whether it is published, and whether CDD is installed in it, and `repos.open` (`/open-repo`) creates a repository when missing, publishes it, installs CDD into it, and opens a top-level chat of its own in it (*NewChat*).

- **Purpose:** Give every caller one object graph for the clone, its branches and worktrees, and its commits, so version control is never reimplemented with raw `git` output.

## Constraint

Callers pass the domain objects (*Repo*, *Branch*, *Commit*), never `git` output as strings. A *Repo* acts only on the clone it was made for; to act on another clone, make a *Repo* for that clone, so a call can never change a clone it did not mean to. The repo tools take no repository path; they act on the clone of the project their call names. Run git only through `repo.git`, so every command gets the same time limits and the same error. A heavy spec that needs a repository makes a real one in a temporary folder; a quick spec works on a *MockRepo* over a *MockGit*, which answers from memory and starts no git. A worktree is one only while its folder is on disk, whatever git still lists. `Worktrees.open` gives each branch a folder of its own beside the main clone and refuses a folder already there that is not that branch's checkout (`WorktreeFolderTakenError`, naming the branch and the folder); `Worktrees.remove` raises `WorktreeNotRemovedError` while the folder is still there, such as one a running program holds open. A merge git refuses is undone and raised as `MergeRefusedError`, a `RepoConnectError` naming both branches.
