# space/repo
*Repo* is the local git clone of the project being worked on — its branches and its commits — so callers switch, commit, push, merge, and close work without running `git` themselves. `Repo.of_project(project)` is the clone holding the project a tool call names; the cdd server hands each repo tool its call's project, so one server answers chats on several projects and no repo tool takes a repository path. The process holds one Repo for each checkout it works in (*ServedCheckouts*), which `Repo.of_project` and `repo.checkout_at(folder)` answer, so every tool call and every session of one checkout works on the same Repo, and its one *WorkState* is the only object that reads and writes that checkout's `.sessions/session.json`.

*Branch* is a line of development on a *Repo*: it is checked out, switched to, saved (committed and pushed), moved into its own worktree, landed on the default branch, and closed. *Worktrees* (`repo.worktrees`) are the checkouts of the repository — the main clone and each linked worktree beside it — and a *Worktree* is one of them, where one branch is worked on while the main clone stays on another. *Commit* is a recorded snapshot whose message carries trailers such as `Ticket:`; git commit trailers are the record of why a change was made, so there is no second index of work to keep in step. `repo.git` is the clone's *Git* (harness/process), which runs the git command line with one set of time limits and one error, *RepoConnectError*, for every operation. *LatestRelease* keeps the end-to-end results of the release that just landed and removes older ones.

A *Repo* makes its parts once and keeps them: `repo.git` and `repo.worktrees` are made with it, and `repo.main_clone` (the main checkout: the repository itself unless it is a linked worktree, and a folder in no repository is its own) and `repo.work_state` (the main clone's *WorkState*, shared by every checkout of the repository) are found once when first asked for. Callers read these instead of building a *Repo*, a *Worktrees*, or a *WorkState* again from a folder path, so the repository's state has one owner. `repo.current_branch` is the *Branch* checked out. `repo.open_worktree` is the worktree saved as open, as the main clone's *Worktrees* list it. Each *Worktree* keeps the *Worktrees* that listed it, which removes it when it closes, and its own checkout's *Repo*: for the main clone that is the repository that listed it, for a linked worktree one made when first asked for.

The work sessions kept in the clone's `.sessions` folder are not the repository's concern: `space/session` owns them (*Sessions*), and the file manager that lists the checkout's files is the sessions' (`sessions.file_manager`).

The MCP tools `repo.switch_branch`, `repo.close_branch`, `repo.switch_worktree`, `repo.close_worktree`, and `repo.push_commit` act on `Repo.of_project(project)`; each finds the branch it names (else the branch saved as open in `.sessions/session.json`), calls one operation on it, and saves the open branch and worktree in `.sessions/session.json` itself: *Branch* and *Worktree* only work the checkout, so one class writes what is saved as open. The commands `/switch-branch`, `/close-branch`, `/switch-worktree`, `/close-worktree`, and `/push` call them.

- **Purpose:** Give every caller one object graph for the clone, its branches and worktrees, and its commits, so version control is never reimplemented with raw `git` output.
- **Seam (terms):** Repo, ServedCheckouts, Branch, Worktrees, Worktree, Commit, `repo.git`, `repo.main_clone`, `repo.work_state`, `repo.open_worktree`, `repo.current_branch`, `worktrees.at(folder)`, CommitPathsRequiredError, CommitMessageRequiredError, WorktreeNotRemovedError, `Repo.of_project`, `repo.switch_branch`, `repo.close_branch`, `repo.switch_worktree`, `repo.close_worktree`, `repo.push_commit`
- **Dependencies (one-way):** `harness/agent_tools`, `harness/hooks` (*HookDaemon*, which a closing worktree asks to stop its checkout's hook daemon), `harness/installation`, `harness/mcp`, `harness/process` (*Git* and its *RepoConnectError*, which every repository operation raises when git fails), `space/work_state` (*WorkState*, which saves the open branch by its name and the open worktree by its folder; the main clone's *Repo* holds it and turns them back into a *Branch* and a *Worktree*).

## Constraint

Callers pass the domain objects (*Repo*, *Branch*, *Worktree*, *Commit*), never `git` output as strings. A *Repo* acts only on the clone it was made for; to act on another clone, make a *Repo* for that clone, so a call can never change a clone it did not mean to. The repo tools take no repository path; they act on the clone of the project their call names. Run git only through `repo.git`, so every command gets the same time limits and the same error. Specs that need a repository make a real one in a temporary folder; there is no in-memory repository.
