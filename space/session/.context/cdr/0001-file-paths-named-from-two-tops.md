# A session names file paths from two tops until the page's file views name them from the project's top

A session reads files through two *FileManager* objects: its own, which names paths from its workpath because the board page's file views (`cdd-files.tsx`, which the installer deploys from `harness/installation`) list and open files that way, and the one *SessionFiles* holds, which names paths from the project's top because the board names declared files, reports, and a ticket's worktree that way. `Sessions.file_manager` is a third, which lists every folder of the checkout for the board's folder picker, before any session exists. We keep them, because one file manager needs one way of naming a path, and the page's file views are the reader that still names paths from the workpath. The steps to one file manager are: (1) the file views in `harness/installation` name every path from the project's top, which is the harness area's change; (2) *SessionFiles* then keeps one file manager whose roots are the repository and the session's practice folders, and `file-manager.list` and `file-manager.read` name paths from the project's top; (3) the folder picker asks the open session's file manager instead of `Sessions.file_manager`.
