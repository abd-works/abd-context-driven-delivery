# The session's core sits on top of its practices, files, and validation, and imports no action

space/session was one module of eight concepts, and `session.py` imported the Render action (through format alignment), the Generate and Validate actions (through the session probe), and the board's own concerns. Proposal 20 of `.sessions/release-1-2-fixes/design-proposals.md` splits it. The split follows the imports the code makes at run time, not only the proposal's picture: *Session* makes and holds its practices, its files, and its validation records (`session.practice(name)`, `session.session_files`, `session.file(path)`, `session.folder.violation_history`, and the graph tools *SessionExplorer* mixes into it), so the core imports those modules, and each of them names the session only for typing (an import under `if TYPE_CHECKING:` is no dependency, as the Clean Engineering rule `one-way-deps` says). The proposal drew the arrows the other way (practices -> session); keeping them that way would have meant taking every part out of *Session* and changing every caller, which is a redesign, not a split.

What goes where, and why:

- **space/session** (the core): *Session*, *Sessions*, *OpenSessions*, *CallSessions*, the record, folder, paths, checkout, hierarchy, idea file, log, handoffs, decision records, chat injections, saves, and the session's graph (*SessionGraph*, *DocumentGraph*). It imports the three modules below and nothing that runs an action, a practice, or a tool.
- **space/session/practices**: *PracticeSessionOutput*, *FidelitySessionOutput*, *WrittenFiles*, *ProposedRoots*, *SessionPractices*, *GuidanceSelection*, and *FileListing* (the selection's listing of files, which only the selection makes). It imports files and validation.
- **space/session/files**: *FileManager*, *SessionFiles*, *SessionFile*, *Range*, *FileComments*, *FileViewFilter*, *NodeSpans*, *SessionExplorer*. It imports none of the other three.
- **space/session/validation**: *ValidationReport*, *Judgment*, *ViolationHistory*, *AcceptedViolations*. It imports none of the other three.
- **space/session/spec_support**: *ThrowawayProject*, *ExampleHome*, *OPEN_PROJECTS*, and the root-choosing examples. Only specs import it.
- **harness/process**: *AnswerReads* and *HeldForAnswer*, and *LogTimestamp* with `REPORT_DATE_FORMAT`. Practices and validation need them at run time, and so does the core; left in the core, they would have made every module below it import the core back. Each is a mechanism of the process (answers it gives, the one time stamp its logs use), not of a session, and imports only the standard library.
- **cdd_guidance/align**: format alignment and its callout check, published as their own toolset *FormatAlignment* (`format-alignment.diagnose_alignment`, `format-alignment.align_formats`), since they run the Render action. It is not a folder of `cdd_guidance/actions`: every folder there is an action of the action catalogue, which the chat bar offers on every fidelity, and alignment works on a whole session. The Files app asks the new toolset's client instead of the session's.
- **cdd_guidance/diagnostics**: *SessionDiagnostics* and *SessionProbe*, which run Generate and Validate. The skill and command they publish move with them.
- **space/kanban**: *BoardPractices* (held per checkout by `BOARD_PRACTICES.of(sessions)`, as `Sessions.board_practices` held it) and *ProgressCache* (held per work folder by `PROGRESS_CACHES.of(session)`, as the session held it), since the board is their only reader; the Files app's graph view examples, which seed sessions with the board's *SessionSeed*. *SessionSaves* no longer names the progress cache's file: the board registers it to be left out of every save (`SessionSaves.leave_out`).

No class changed its behaviour; the published names that changed are the two alignment tools and the session diagnostics' skill and command folder.
