# space/session
*Session* is one named piece of work in a project — a board ticket's work, or `main`, which works on the whole repository — so every action, log line, handoff, and validation report lands in the folder of the work it belongs to. A session keeps its files in two folders, each named for what it holds. Its *record folder* (`session.record_folder`) is `.sessions/{name}/` in the repository's main clone: its `session.json` (title, scope, parent, whether it was pulled out of that parent, tags, workpath, practice roots, and stage) and its idea file `<name>.md` (`text`, `keep_text(text)`, an *IdeaFile*: a heading and the text under it), which is everything the board needs to list the ticket, show what it is about, and track where it stands; every checkout reads the same record, so the board sees every ticket wherever its work happens. Its *work folder* (`session.work_folder`) holds everything else the session writes: its `session.log` and `session.err`, its hook logs (`logs/`), debug reports, handoffs, progress cache, violation history, validation reports and the graphs they checked, its saved graph, file comments, and chat injections. For a ticket with its own worktree the work folder is `<worktree>/.sessions/{name}/`, so the work travels on the ticket's branch and is merged with it; for a session with no worktree of its own, such as main or a ticket not yet activated, it is the record folder itself. The session holds both folders: *HeldSessions* gives it its record folder when it first reads it, and places it (`sessions.held.placed(session)`) on every load, setting its checkout, its work folder (`sessions.roots.work_folder_of(session)`), and its root, so a worktree opened since is seen; a new work folder makes the session's handoffs, progress cache, and graph again in it. *SessionHierarchy* (`session.hierarchy`: `set_parent(parent)`, `mark_pulled_out()`, `open_child(name, title, scope)`) and `add_tag(word)` keep a board ticket's hierarchy and tags; *SessionFolder* (`session.folder`) moves its record folder among the open, closed, archived, and backlog sessions (`move_to_closed`, `move_to_archive`, `move_to_backlog`, `reopen`), taking the work folder along only when the two are one folder, so a ticket's work stays in its worktree; keeps a person's file in the record folder (`keep_file`, a started backlog item's idea, which becomes the idea file); names a hook's log in the work folder (`hook_log`), holds its violation history there (`violation_history`), and `remove()` deletes both folders. What a page lists of a session's files is the session's to say: *FileListing* (`session.guidance.listing(linked)`, `file_listing.py`) applies the guidance selection and the fidelities a page's link names to each file a ticket or the session answers (`of_fidelity`, `of_root`, `of_folder`), and each *FileEntry* says `is_listed` and `is_session_work` (in a git repository, a file the branch changed; in a plain folder, a file a fidelity declares or holds that is there), so the Files app filters by those and restates no rule. The selection also answers `covered_stages`, the titles of the stages it covers (those selected, every stage while none is), which the chat bar heads its dots with.

*SessionRecord* (`session.record`) is its `session.json`: `fields` (typed *SessionFields*), `update(change, said)`, `extra(owner)`, `save`, and `saved(change)`, which queues every change to the folder to be saved on main. *SessionPaths* (`session.paths`) reads every path a call names from the session's project (`path_named`, `document_named`, `from_project`, `context_folder`, `folder_under_root`). A session derives where it works itself (`session.placed()`), from its *SessionCheckout* and the checkout's *CheckoutWorktrees* (`sessions.worktrees`: `of_branch`, `branch_names`, `in_checkout`). *SessionGraph* (`session.session_graph`, `session_graph.py`) is the session's knowledge graph and the one owner of the graph file saved in its work folder (`graph`, `overlay`, `forget`, `saved_file`, `last_read`); it reads a file a viewer shows into the whole graph when it changed (`holding(path, is_held)`), keeps when the graph view's listed files were read (`listed`, `as_it_is_now`), and holds the *DocumentGraph* a viewer reads one file into on its own (`alone`). *DocumentGraph* is the one reader of a single document into a graph of its own instances of the practices: a file from a folder (`read(folder, path)`), or a document's text written into a folder of its own (`read_text(practice, text, placed_at)`), as a format alignment compares formats; and *GuidanceSelection* (`session.guidance`) changes the guidance selection and raises its version on each change (`toggle`, `select`, `changed`, `wait_past`). *SessionPractices* (`session.session_practices`, `session_practices.py`) are the session's one instance of each practice (`every`, `working`, `forget` when the workpath moves), made under the reentrant lock (`lock`) the *SessionGraph* is made under too, which with the graph `session.graph`, `session.practices`, `session.own_practices`, and `session.practice(name)` answer from. *SessionExplorer* (`session_explorer.py`), mixed into *Session*, is the graph tools a page browsing the session's files calls (`graph_trees`, `graph_branch`, `graph_node_ranges`, `graph_members`), each reading the session's graph itself. The session's published tools keep their `session.*` names while their declarations sit in the bases mixed into *Session*, one per job, each doing its job or asking the part that does it: *SessionFileTools* (its files, through *SessionFiles*), *SessionExplorer* (its graph, read by the tools themselves), *SessionGuidanceTools* (*GuidanceSelection*), *SessionLogTools* (its log and handoffs), and *SessionDecisionTools* (*DecisionRecords*). What one fidelity writes in a session, where each format goes, which files are there, and which the branch changed, is its *FidelitySessionOutput*'s *WrittenFiles* (`session_output.written`: `output_paths`, `files`, `holds`, `every_file`, `has_output`). A fidelity keeps one or several roots (`choose_root`, `add_root`, session.json `root` or `roots`). The folders it proposes for the pieces a ticket works on are its *ProposedRoots* (`session_output.proposed_roots`, `proposed_roots.py`: `holding(files)`, `named(names)`, `proposed(names)`; published as `fidelity-session-output.propose_roots`): the narrowest folder holding each piece, read from the fidelity's own declared outputs, so no practice is named in it. `session.set_up_roots` is the instructions an agent follows to set a session's roots, which switching to a session with unchecked roots points to: read the ticket and its branch, ask each fidelity for its proposals, dig to the narrowest folders, confirm with the person, then set them. A closed session's record moves to `.sessions/_complete/{name}/` (`sessions.closed_folder`, the one place that folder is named). A session is one object for each record folder, which its *Sessions* hold, and what it keeps on disk is read from its folder each time a caller asks for it, so a switch or a close made by another chat or by the hook server is seen at once; its `session.json` (`session.record.fields`), which one board read asks thousands of times, is read once for each answer (*AnswerReads*, `answer_reads.py`): each call and each hook event that finds its sessions through *CallSessions* begins an answer (`sessions.answers.begin()`, *ServedAnswers*, which `session.answer` reads), so a change another process wrote is seen by the next call, and each `save_fields` begins one too, so no read in the process answers what the file held before its own write; between answers the file is read again only once its last-written time or size changes (*HeldJsonFile*, harness/installation). Sessions no call is served from, such as ones a spec makes itself, hold nothing and read on every ask. A practice's folder named in the project's `.context/config.json` is held for the answer the same way.

*Sessions* are the work sessions of one checkout and which of them is open. `Sessions(project)` holds the checkout holding the project (`sessions.repo`, `Repo.of_project`, the one Repo this process holds for that checkout), and every session it loads or creates is made with those sessions and its record folder, which names it (`Session(sessions, record_folder)`, `session.sessions`), and is placed where it works now in one order (`session.placed()`: its checkout, then its work folder, then its workpath) and holds that repository (`session.repo`), so a session closes, moves, and lists its files without building either again. A chat in a ticket's own worktree works on that ticket, found from the worktree's branch, whatever any chat chose to open. Which session each chat has open is the sessions' part *OpenSessions* (`sessions.opened`, `open_sessions.py`): a chat in the repository's own folder keeps its open session in *WorkState* (`sessions.opened.state(chat)`), kept by the cdd server under `~/.cdd` and never in the checkout; `opened.name_for(chat)`, `opened.open(session, chat)`, `opened.current(chat)`, `opened.close(session, chat)`, and `opened.switch(name, workpath, call)` read and change it, each for the chat it is handed (an empty chat is a call that names none, which keeps the checkout folder's own entry; nothing falls back to a process-wide call), and `SessionNameRequiredError` is raised there. A switch answers a *SwitchedSession*: the session opened, what the modules listening for an opening told the chat (`OpenSessions.on_session_opened`), the ticket it opened in place of the one asked for when the chat works in that ticket's worktree (`opened_in_worktree_of`), the session's own worktree when the chat works elsewhere (`outside_worktree`), and the practices whose roots nobody set (`default_roots`); its `instructions` say them in the words of `SESSION-SWITCH.md`, then how to keep the log, and `sessions.switch` answers that text. `session.close(call)` closes the session for the calling chat. `Sessions(project).current()` and `Sessions(project).switch(name, workpath)` are the only operations that read or change which session is open; `load(folder)` and `with_file(session_file)` read a session without opening it, `named(name)` and `all()` find the board's sessions, `create(name, workpath, title=, scope=, parent=)` makes a session for later without opening it, and `opened.close(session, chat)` makes main chat's open one again when chat had that session open; `sessions.current` and `sessions.switch` are the published tools, each asking *OpenSessions*. Every checkout's sessions keep their records in the repository's own `.sessions`, in its main clone (`sessions.folder`), so the board reads every ticket from one place; a chat in a ticket's linked worktree writes the session's log and the rest of its work into the worktree's own `.sessions/{name}/`, the session's work folder, so the ticket's branch carries its work and main carries only its record. A session moved to the closed sessions, the archive, or the backlog, or reopened, moves its record folder and stays the same object. `sessions.read_apart()` answers a *SessionsRead*: every session whose `session.json` reads (`sessions`), with the failure of each one that does not (`failures`), so a reader that shows many sessions, such as the board, shows the rest and names the damaged file, where `all` stops at the first.

*SessionRecord* (`session.record`) is the session's `session.json` read into typed fields (*SessionFields*): name, title, scope, workpath, tags, overlays, parent, pulled out, the branch, worktree, and chat its checkout recorded, its guidance selection (*SelectionFields*), and one entry per practice (*PracticeFields*: whether it is on, its chosen root, and one *FidelityFields* per fidelity: the formats chosen, its own roots, and a file name per format). Each part of the session changes its own fields with `record.update(change, said)`, which changes the file as it is now and queues its save on main. A file in the shape older servers wrote, a practice's roots kept apart under `outputs`, is upgraded as it is read and written in today's shape on its next save; `repo_path`, which nothing read, is dropped. An owner outside the session keeps its own fields through `record.extra(owner)` (*OwnedFields*), such as the board's `stage` and `stage_mark`, which stay where they are in the file; it is refused a field of the session's own (*SessionFieldOwnedError*). *SessionCheckout* (`session.checkout`, `session_checkout.py`) is the one reader and writer of the `branch`, `worktree`, and `chat` the record keeps: the session's own branch (recorded, else named as the session, else the one branch holding its name as a whole word, `names_ticket`), its own linked worktree, its one project (`repo`, `root`: that worktree, else the checkout whose sessions hold it, whose `.context/config.json` it reads), the chat a person assigned, and `record_opened()`. *CheckoutWorktrees* (`sessions.worktrees`, `checkout_worktrees.py`) lists the linked worktrees and branches once and again after two seconds, the one caching rule.

The *workpath* is the folder a session works in; its practices write under it and its graph is opened on it. `Session.graph` is the session's knowledge graph (harness/graph's *Graph*). `Session.overlays` names the patterns the session overlays on that graph, kept in its session.json; `choose_overlays` replaces them and applies them to the graph at once, and a graph made later applies them when it opens. The sessions that loaded a session hold one *Session* object per session folder (*HeldSessions*, `sessions.held.load(folder)`, answers it, and a session moved to another folder stays that object; *SessionListing*, `sessions.listing`, says which folders hold a session), and every call in the session, from any chat, works on it: it makes its graph and its one instance of each practice (made with `PracticeCatalogue.create_all()`) once, under a lock, so two calls that first ask at once wait for the one the first makes, and every call in the session works on the same graph and the same practices and none rebuilds them. A session holds no chat: a call's chat is the call's own, and the lines a call writes go through `session.log.by(call.request.chat)`. The process holds the sessions of each project it serves (*CallSessions*, `Sessions.of_project(project)`), so the kept sessions last for as long as the cdd server runs. A new graph reads back the graph saved in its root's `.context/graph.json` (`graph.reads.open_saved`, its *GraphReads*), so a session opened again, such as a ticket just activated, shows what was loaded in it before rather than an empty graph. When a session's root moves, it makes its graph and practices again on the new root. An action that writes files refreshes it with exactly those files (`GuidanceAction.wrote`, or `graph.refresh` from the agent); nothing watches the files. An empty workpath is the whole repository. `Session.work_root` is that folder, worked out in one place: sketches, grill answers, partitions, each practice's folder, and the file manager all start from it.

*PracticeSessionOutput* is what one practice has in one session: the session's one instance of the practice (`guidance`), whether it is on, and the folder it writes under. `session.practice("stories")` returns it. Its data also carries the practice's `short_name`, `colour` and `fidelity_slugs`, so a page such as the Files app draws a toggle for it in its colour and knows which of a stage's files are its own; `session.show()` answers the session with every practice, on or off, changing nothing. An action works on that same practice: it holds the fidelity its guidance names (`GuidanceAction.fidelity_of`) and never moves the practice's current fidelity, which stays the one the practice was made at, and gives the format it names to that fidelity, which keeps it; so another call on another fidelity of the same practice changes nothing it reads. The line it logs names that fidelity: it hands the log the fidelity's *FidelitySessionOutput*, the one the fidelity holds, whose `practice` answers the practice's name and folder and whose `fidelity` its name and format; the log takes no other kind, and a practice worked at no fidelity is named on no line. The practice works in the session through `PracticeGuidance.work_in`, which gives each of its fidelities, through `FidelityGuidance.work_in`, its *FidelitySessionOutput*: where that fidelity writes each format in the session, the files it declares there, the format it last used, and its reports folder. Where a practice writes is kept in one place, its session's `session.json` (`outputs`), else it is the practice's default: the folder the project's `.context/config.json` (`session.context_config`, the config of the checkout the session works in: its ticket's own worktree when it has one, whichever checkout's sessions read it, made again only when the session moves to another checkout) names for it, else the guidance's own default folder. A fidelity reads and saves its part of the practice's `session.json` through the practice's public `chosen_outputs`, `saved`, and `save`. The session makes its practices once, with its graph; a validate is logged for the call that ran it (`session.log.by(call.request.chat).validation(worked, violations)`, which a guidance action reaches as its `log`), so the line points at that call's chat. A root is chosen as a folder: `root_named(path)` reads the path from the repository and refuses an empty path or a file with *OutputRootRefused*, so the agent is never told to write a practice's files into a file; a folder that is not there yet is a root the practice writes into.

*SessionLog* (`session.log`) is the session's `session.log` and `session.err`: one line per action, tool call, note, and loop marker, stamped with a *LogTimestamp* (UTC, to the second; the one time format every log a session keeps uses, and the board's last-activity times, the prompt log, the toasts, the violation history's lines, and an accepted violation's time use it too; `REPORT_DATE_FORMAT`, beside it, is the stamp a validation report's or a handoff's file name ends with), each ending with a pointer to the chat that caused it. Both are capped (*CappedLogFile*, harness/process): a log that reached 4 MB moves its lines to `session.log.1` (or `session.err.1`), and the new `session.log` starts with the loop it was in (`--- N continued from session.log.1`), so loops number on; the hook logs in `logs/` are capped the same way. A *Loop* is one context–generate–evaluate cycle marked in the log, so the lines of one cycle can be read back together with the chat that produced them. Each line points at the chat that caused it — the *ChatPointer* (harness/agent_tools) of the tool call that wrote it, through the *ChatLog* that call writes with (`session.log.by(call.request.chat)`), else `no-chat`; never a chat the server's environment names, which would point one chat's line at another — so `session.read_loop` can put that chat's words back under the line. A session tool that writes a line, such as `session.mark_loop` or `session.append_log`, takes the call it answers, which the framework hands it as it hands `project`. The rules a hook gave the agent (*InjectedRules*, made once with the log) wait in the session's work folder until the next log line names them, because the hook server notes them and the cdd server writes that line. *ChatInjections* (`session.chat_injections`) keep the rules a hook gave each chat of the session in its `chat-injections` folder and replay them on that chat's next prompt, never another chat's; the hook server asks the session of each event for them. How an agent keeps the log is `SESSION-LOG.md`, which `sessions.switch` answers with. *SessionFiles* (`session.session_files`) are the files a session works with: the ones in its record folder and its work folder, and any file of its repository it reads. They are the one place a path a call names is checked: `existing(named)` answers the path once something is there, `from_root(named)` writes it from the session's root, as the session's graph names its files, and `in_root(path)` says whether a path lies under that root; each refuses with *NamedPathNotFoundError*, which names the path, the project it was read from, and the root when the root refused it, so the Validate, Grill, and Context Index actions never work on nothing and report it as a clean result; the files a practice declares are each fidelity's own, through its *FidelitySessionOutput*, which searches the session's file manager named from the project's top with each declared path's glob (*DeclaredFile*, harness/guidance) and keeps the files its fidelity declares (`fidelity.declared.includes(path, format)`).

*FileManager* lists, reads, and saves the files under a session's roots — the folder each of its practices works in — so every application shows files the same way instead of each object growing a read operation of its own. `session.session_files.file_manager` is the session's, held in memory and made again only when its roots change; a tool call loads it with `FileManager.load(call=...)`, from the session open in the call's project (`call.session`). A session reads through two file managers because paths are named from two tops: its own, named from its workpath, which a page lists and reads, and one named from the project's top (*SessionFiles*), which reads and finds the files the board names that way. `sessions.file_manager` lists the folders anywhere in the checkout, named from its top, for the board's folder picker. *Folder* is a listed folder and its entries, folders first; *FolderEntry* is one entry with its path and size. *FileEntry* is a declared file with its path from the project, whether it exists, and whether the session's branch changed it (`is_changed`, which the board's changed-files filter reads; `SessionFiles.branch_changes.files()` asks git once a file is there). *FileText* is a file's path, its text, and the language a viewer shows it in, from its suffix. The MCP tools are `file-manager.list(folder)`, `file-manager.read(path)`, and `file-manager.write(path, text)`, which refuses a path outside the roots as reading does; a board command saves a ticket's file with `session.write_file(path, text)`, named from the project as `session.read_file` names it. A *FileText* says whether its file was there when it was read (`exists`), so a viewer says a listed file is gone instead of showing it empty.

*FileComments* (`file_comments.py`) are the comments a person writes on lines of a session's files in the Files app (`harness/files_app/`, its own module context), kept in `file-comments.json` in the session's work folder so they stay when a page reloads; `session.file_comments` is the session's, and a tool call loads it with `FileComments.load(session=...)`. *FileComment* is one comment on a *Range* of a file, with its text, anchored as `path:Lstart-Lend`, one per range; `add(path, start_line, end_line, text)` keeps what those lines hold when the comment is written. Its state is read from the chat it was sent to (`harness/chat`), never kept twice: `not_sent` until `Chat.queue` holds it, `sent` until the chat's turn that worked on it has ended, then `processed`; a message the chat failed to show leaves it not sent. `send(anchor, chat)` and `send_open(chat)` put the comments in the chat's prompt in one fill, each as `path:start-end: comment` and its lines marked `> n |`, with `session=<session.json>` last. The MCP tools are `file-comments.on(path)`, `file-comments.add`, `file-comments.remove(anchor)`, `file-comments.send(anchor, chat)`, `file-comments.send_open(chat)`, and `file-comments.clear_processed`; the board's TypeScript reaches them through the language adapter the installer deploys.

*SessionFile* (`session_file.py`) is a file of the session as the viewer shows it, from `session.file(path)`: its text and language, its comments, its *Folds*, and its *FileViolations*, each on a *Range* of its lines (`SessionFile.range(start_line, end_line)` returns a Range with the text those lines hold). Folds and violations come from the graph the session saved in its folder (`graph.json`), whose files are named from the session's root: a fold for each class (`class`) and each operation or property (`block`), the kinds the graph's source view folds on (`harness/graph/app/source/call-expansion.ts`); the viewer keeps which folds are open. A file the saved graph never read, or a session with no saved graph, has none. The viewer shows a file of at most `VIEWER_SHOWS_LINES` (30,000) lines; a longer one is refused with *FileTooLongToShowError*, which carries the file, its lines and that limit, because drawing it would freeze the page and lose the comments not yet sent. A page that filters its files sends its filters with the read, `session.file(path, paths=..., node_filter=...)`: the files it lists for the stages, practices and formats chosen, and the graph view's node filter, as `session.graph_trees` takes them. The session then answers only the callouts those filters show (*FileViewFilter*, `file_view_filter.py`, which asks the graph's own *Filter*): a link into a file of a practice turned off is left out, a file no fidelity declares or one that is not there always shows, and what a step invokes or observes is left out while the node filter leaves out that connector or node type. A read that sends neither holds every callout, so the decision is made once, in Python, for every page.

*SessionAlignment* (`format_alignment.py`) says whether the formats a session chose for each fidelity hold the same thing, and brings them in step. `session.diagnose_alignment` goes through the fidelities the session's guidance selection covers and answers an *AlignmentDiagnosis*, each *AlignmentGap* in plain words with its kind, file, and the file it is aligned from: a chosen format whose file is not there (`missing_file`); a file that lacks nodes or edges another format of the same document holds (`format_lacks`), or two that each hold something alone (`formats_conflict`), compared as *GraphReading*s, what the knowledge graph reads from each file once the Render action has put it in the fidelity's leading format (a comparison graph and folder apart from the session's, private to `format_alignment.py`); and, from *CalloutAlignment* (`callout_alignment.py`), a link whose target is not there, a callout to a heading that no edge of the session's graph matches, and an edge between a markdown file and another document or code file that no callout shows. `session.align_formats` renders each gap a render closes through the Render action, so a drawing keeps its layout and a document its own words, and answers an *AlignmentResult*: each *AlignedFile*, each *AlignmentFailure* (kind, file, message), and the diagnosis afterwards. A missing file is rendered from the leading format, the first chosen document format; a file that lacks is rendered from the one that holds more; files that conflict are a person's decision, and while two files of a document conflict none of its files is rendered. A chosen code format with no file is rendered too, from the first chosen format whose file is there, into the files the fidelity declares; a code file already there takes the new shape and keeps every line it held, each *AlignedFile* naming as `migrate` the members that file keeps though its model no longer holds them, and code the declared paths cannot place, or a render that would lose a line, is answered as `render_failed`. A diagnosis searches the session's folders again first (`FileManager.search_again`), so it holds a file written a moment ago.

A ticket's record is kept on main so every chat and worktree reads the same board. A session saves itself: each write to its record folder (`session.record.update(change, said)`, where each part of the session changes its own typed fields, `keep_text`, `session.folder.keep_file`, a move of its record folder, `session.folder.remove`) queues the save of that change and returns at once, so a caller such as a board ticket only says what changes. *SessionSaves* (`sessions.saves`, one for each repository's `.sessions`, shared by its main checkout and every worktree) commits the session folders on main and pushes main on a thread of its own, half a second after a change so every file it writes goes in one commit, several waiting saves in one commit, and not while a merge is in progress in the repository's own folder, which a commit would conclude. A project git does not hold has nothing to commit, so a save there is never queued and no thread starts for it. In a repository `git init` made, with no commit yet, the first save is its first commit, so opening a ticket has a commit on the default branch to start the ticket's branch from. `saves.later(message)` queues a save of something in `.sessions` that is no session's own, such as a Backlog item or the board's card order; `saves.now(message)` waits for the queued saves and saves in the caller's thread, for work that needs main committed before it goes on (opening a ticket's worktree, closing or archiving it), and raises git's refusal. Before it commits, it makes sure the session folders' own `.gitignore` lists `**/progress-cache.json`, so no save commits a progress cache in a project whose own `.gitignore` does not name it. A queued save git refuses is kept as `saves.failure`, a *SaveFailure* naming the changes not saved and what git said, until a save succeeds; `saves.retry()` queues them again. The changes stay on disk, so the board works on them meanwhile. Removing a record folder that a running program holds open, such as a shell working in it, raises *SessionFolderHeldError*, which names the folder, with every file still in it.

*ProgressCache* (`session.progress_cache`, made when the session is given its folder) keeps, in the session's `progress-cache.json`, the answers about each fidelity that are slow to work out on every board read: whether a file it declares is there, and how many violations its latest report names. `of(fidelity).answer(question, key, work_out)` gives the kept answer while its key is unchanged, else works it out and keeps it; the board keys an answer on what Generate and Validate change, so a move works nothing out again. A missing or unreadable file only means the answers are worked out again.

*ViolationHistory* (`violation_history.py`, `session.folder.violation_history`) is the session's `violation-history.jsonl`, tracked in git with the folder: one JSON line per event, only ever appended to, so the rules that keep breaking, the fixes that bring a hit back, and the hits judges call noise can be read across every run. A report is a *ValidationReport* (`validation_report.py`, listed and made by a fidelity's `session_output.validation_reports`: `listed()`, and `new()`, which claims a file of its own): it holds its fidelity, and its name, `{fidelity slug}-{moment}.md` with `_2` after the moment for a second report in one second, is written and read there alone (`made_at`, `is_newer_than`, `saved_graph`, `has_result`, `judgment`, and `listed_hits`, the hits its markdown lists, read only for a rebuild). Each history line is a typed *HistoryLine* (*RunLine*, *FoundLine*, *FixedLine*, *JudgedLine*, each with its run's *RunStamp* and a hit's *HistoryHit*) that writes exactly the keys earlier lines carry. Validate records each run it saves (`record(report, hits, scope)`): a `run` line (its report, fidelity, the files it checked, how many hits), a `found` line per graph hit (`rule`, `file` from the project's root, `line`, `node`, `message`), a `fixed` line for each hit of the previous run of the same fidelity, in a file this run checked, that this run no longer finds (matched by rule, file, and node, never line, since an edit above a hit moves it), and first the `judged` lines of that previous run's report, whose judgment is surely written by then: each finding of a failed rule (`verdict: stands`) and each row of its `## Graph hits judged noise` table (`verdict: noise`), each saying whether it `matched` a graph hit or is the judge's own; a run already folded in is skipped. Every line names its `run`, `at` (UTC), `commit` (the short HEAD of the checkout the session works in, read from the *Repo* it is handed; empty for a folder git does not know), `session`, and `fidelity`. `rebuild(reports, commits)` writes it again from saved reports' markdown alone (`ValidationReport.listed_hits`), which `scripts/backfill_violation_history.py` runs for a session, listing its reports through the session's fidelities. `validation_judgment.py` reads a report's judgment for it and for the board: *Judgment* (each failed rule in each judged file, with its findings) and *ReportJudgment* (`fails`, and `noise`, the noise table's rows).

*AcceptedViolations* (`accepted_violations.py`, `session.accepted_violations`) is the project's `.context/violations-accepted.json`, under the folder the session works in and committed with it, so an acceptance holds for everyone and in every session: `{"accepted": [...]}`, each *Acceptance* an object a person can read and edit by hand. A violation on a node is kept by its `rule`, its `node_id`, and its `message` (with `subject`, `file`, and `accepted_at` for the reader), and is left out while all three stay the same; a finding that names no node, such as a judged finding on a line of a file, is kept by its `rule`, its `file`, and `content`, the text of the judged line, never the line number, so it stays accepted when the line moves or the judge words it another way and shows again when that text changes; one that names no line is kept by its `message`. `accept` and `reopen` change the file, `open_among` and `accepted_among` split a list of violations, and a file that does not read raises *AcceptedViolationsUnreadable*, naming the file, and is never written over. Validate's *CheckedGraph* and the board's *ReportFile* both ask it, so the report, the counts, the log line, and a fidelity's done state leave the same violations out; the violation history still records every hit found, so an accepted one is never recorded as fixed.

A *handoff* is a compact account of a session — what it achieved, what was learned, and where the next agent starts — so a fresh agent can continue the work without rereading the whole chat. *Handoffs* (`session.handoffs`, made when the session is given its work folder) write each one as a new `handoff-{timestamp}.md` in the session's work folder, so a ticket's handoffs are committed on its branch; `Session.latest_handoff` names the newest. Each is a *Handoff* (`handoffs.latest`), whose `next_steps` are the numbered steps of its Approach for Next Agent. A module outside the session acts when a chat opens one through `OpenSessions.on_session_opened(listener)`, which tells the chat what the listener answers: tools/prompt_queue registers there to queue the latest handoff's next steps on the chat's queue (`PromptQueue.queue_once(source, texts)`), so the session imports no tool. A practice's `PracticeSessionOutput.design_view` is the Claude Design link recorded for the latest version of the design canvas under the folder it writes under (*CanvasVersions* of harness/design_canvas; the UX practice's), which the chat bar's file viewer opens; empty while the practice is off or none is recorded. The instructions `session.handoff_session(next_focus)` read the handoff format (`HANDOFF-FORMAT.md`, through `session.read_handoff_format`), draft the handoff, and call `session.write_handoff`.

A *Context Decision Record* (CDR) is a short, numbered markdown file that records a design choice a later reader would otherwise question: one that is hard to reverse, surprising without its context, and a real trade-off. *DecisionRecords* (`Session.decision_records`, made again when the workpath moves) are a session's records, `.context/cdr/{NNNN}-{slug}.md` under its workpath, each numbered one past the highest; `CDR-FORMAT.md` beside this module is their template. `session.read_cdr_format`, `session.list_cdrs(session)`, and `session.write_cdr(session, slug, paths)` read the format, list the records, and write one; the instructions `session.record_decisions_session(session)` wrap an action's turn so records are offered as decisions are made.

*CallSessions* holds the sessions of every checkout the process serves, each made once and held by the checkout's top, as its one Repo is (`Sessions.of_project`), so a call naming a folder inside the checkout reaches the same sessions; it is how a tool call opens its sessions: `sessions.py` registers it with `SESSION_OPENING` (harness/agent_tools) when it is imported, so `call.session` is the session open in the call's project and `call.session_named(session_file)` the one a board command names, each the one object its sessions hold, and `SESSION_OPENING.saved_in(project)` the session open in a project for work that serves no call, such as a hook event (`HookPayload.session`) or a diagnostics probe, while the framework never imports this module. `Session.from_file`, `PracticeSessionOutput.load`, and `FileManager.load` take the call they serve and find their session through it, so session.py, practice_session_output.py, and file_manager.py never import sessions.py, which imports them.

*ThrowawayProject* is an empty project a spec works in, so the actions a spec runs write to their own session log instead of the log of whoever is working in the repository. *ExampleHome* is a cdd home of one example's own, so the open-sessions file every switch reads and prunes holds only what that example opened, not an entry for every throwaway project the run made.

The MCP tools `sessions.current` and `sessions.switch` act on the project the call names. Every `session.*` tool acts on the session whose `session.json` its required `session` argument names (a path from the project): `session.close`, `session.show`, `session.choose_workpath`, `session.folder_files`, `session.workpath_files`, `session.read_file`, `session.write_file`, `session.file`, `session.mark_loop`, `session.read_loop`, `session.append_log`, `session.write_handoff`, `session.read_handoff_format`, `session.read_cdr_format`, `session.list_cdrs`, and `session.write_cdr`, and the instructions `session.handoff_session` and `session.record_decisions_session`; each finds its session and calls one operation on it or on its log, files, handoffs, or decision records. The file manager publishes `file-manager.list`, `file-manager.read`, and `file-manager.write`; the file comments publish the `file-comments.*` tools. Per practice there are `practice-session-output.enable`, `practice-session-output.choose_root`, and `practice-session-output.use_default_root`; `session-diagnostics.session_diagnostics` probes the session log through the live MCP host. ## Constraint

Name the session work is for. Every `session.*` tool takes the session's `session.json` as its `session` argument and refuses an empty or missing one with `SessionNotFoundError`, so work asked for one ticket never lands in whichever session a chat has open; ask `sessions.current` for the open session's `session_file` when the user names none. Only `sessions.switch` changes the open session, and only `sessions.current` and `ToolCall.session` read it. Read another session with `sessions.held.load`, `Sessions.with_file`, `Session.from_file(session, call)`, or `Sessions.named`, which do not open it. Write to a session's log through `session.log.by(chat)`, never by editing `session.log`. Draft a handoff or a decision record to a file and pass its path in `paths`; do not put its body on an MCP call. Offer a decision record only when all three criteria hold, write it as soon as the decision is made, and never invent or batch decisions. Write large or temporary outputs (graph JSON, probes, reports) under the session's work folder, not beside the work. Write into the record folder only what the board reads, `session.json` and the idea file, since every write there is committed on main. Name a file manager's paths from the session's workpath: a path outside the session's roots raises *PathOutsideRootsError*, so a caller cannot read the rest of the disk through a session, and `read` returns no text for a file that is gone, such as one deleted since a page listed it; check `FileText.text` rather than expecting an error. Specs that run actions open a *ThrowawayProject* and close it after each example.

*GuidanceSelection* (`guidance_selection.py`, `session.guidance`, held by the session and read from its record on each ask) is the stages, practices, and format groups the chat bar and the Files app show and act on. It changes itself: `toggle(part, name)` (published as `session.toggle_guidance`) works out the selection one press leaves, `select(stages, practices, formats)` writes it in one change of the record and raises the version once (`changed`), and `wait_past(version)` answers a waiting page. Before anyone chose stages, it shows the stage the session's ticket stands in selected, which the board registers how to read (`GuidanceSelection.start_on_ticket_stage_with`, read once per answer). It writes the command an action runs on its fidelities (`command(action, fidelities)`, and `commands` for the fidelities selected): the one place a command and its `format=` are written, with the formats chosen for an action that takes them. *FormatGroup* is one group of formats, with the data fields the chat bar reads (`label`, `formats`, `offered`, `is_selected`).
