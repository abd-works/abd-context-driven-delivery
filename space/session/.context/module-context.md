# space/session
*Session* is one named piece of work in a project — a board ticket's work, or `main`, which works on the whole repository — so every action, log line, handoff, and validation report lands in the folder of the work it belongs to. A session keeps its files in two folders, each named for what it holds. Its *record folder* (`session.record_folder`) is `.sessions/{name}/` in the repository's main clone: its `session.json` (title, scope, parent, whether it was pulled out of that parent, tags, workpath, practice roots, and stage) and its idea file `<name>.md` (`text`, `keep_text(text)`, an *IdeaFile*: a heading and the text under it), which is everything the board needs to list the ticket, show what it is about, and track where it stands; every checkout reads the same record, so the board sees every ticket wherever its work happens. Its *work folder* (`session.work_folder`) holds everything else the session writes: its `session.log` and `session.err`, its hook logs (`logs/`), debug reports, handoffs, progress cache, violation history, validation reports and the graphs they checked, its saved graph, file comments, and chat injections. For a ticket with its own worktree the work folder is `<worktree>/.sessions/{name}/`, so the work travels on the ticket's branch and is merged with it; for a session with no worktree of its own, such as main or a ticket not yet activated, it is the record folder itself. The session holds both folders: *HeldSessions* gives it its record folder when it first reads it, and places it (`sessions.held.placed(session)`) on every load, setting its checkout, its work folder (`sessions.roots.work_folder_of(session)`), and its root, so a worktree opened since is seen; a new work folder makes the session's handoffs, progress cache, and graph again in it. *SessionHierarchy* (`session.hierarchy`: `set_parent(parent)`, `mark_pulled_out()`, `open_child(name, title, scope)`) and `add_tag(word)` keep a board ticket's hierarchy and tags; *SessionFolder* (`session.folder`) moves its record folder among the open, closed, archived, and backlog sessions (`move_to_closed`, `move_to_archive`, `move_to_backlog`, `reopen`), taking the work folder along only when the two are one folder, so a ticket's work stays in its worktree; keeps a person's file in the record folder (`keep_file`, a started backlog item's idea, which becomes the idea file); names a hook's log in the work folder (`hook_log`), holds its violation history there (`violation_history`), and `remove()` deletes both folders. What a page lists of a session's files is the session's to say: *FileListing* (`session.guidance.listing(linked)`, space/session/practices) applies the guidance selection and the fidelities a page's link names to each file a ticket or the session answers (`of_fidelity`, `of_root`, `of_folder`), and each *FileEntry* says `is_listed`, `is_session_work` (in a git repository, a file the branch changed; in a plain folder, a file a fidelity declares or holds that is there) and `hidden_by_formats` (the format groups selected when they alone leave the file out, which the Files app says its empty list is for), so the Files app filters by those and restates no rule. The selection also answers `covered_stages`, the titles of the stages it covers (those selected, every stage while none is), which the chat bar heads its dots with. Where a declared path lands under a root, and which code is production code rather than a test of it, are the practice's to say (`PracticeGuidance.placed_under`, `is_production_code`), so the session imports no practice: Stories places its `story_tests` paths itself. A *SessionFile* (space/session/files) folds on every practice's class and member types, shows the steps each practice's reading names (`PracticeReading.steps`), each with a *StepCallout* for what it invokes and observes, on the line of the step's code that names it and titled by the owner its reading names for each member (`owner_of`; *StoryTestCode*, `files/file_steps.py`), says the form a viewer renders it in (`rendered_form`, from *FileText*), and *NodeSpans* asks a node's reading whether it is used from elsewhere (`is_used_from_elsewhere`), such as a story's example. A file the agent just edited is checked as a *ChangedArtifact* (`session.check_changed_artifact(path)`, space/session/validation), which the chat bar calls after each edit: Validate runs on that file alone for each fidelity the guidance selection covers, of a practice the session works on, that declares it, so the report and the validate line it logs move the chat bar's violation count with the edit, and a file no such fidelity declares is checked by none.

*SessionRecord* (`session.record`) is its `session.json`: `fields` (typed *SessionFields*), `update(change, said)`, `extra(owner)`, `save`, and `saved(change)`, which queues every change to the folder to be saved on main. *SessionPaths* (`session.paths`) reads every path a call names from the session's project (`path_named`, `document_named`, `from_project`, `context_folder`, `folder_under_root`). A session derives where it works itself (`session.placed()`), from its *SessionCheckout* and the checkout's *CheckoutWorktrees* (`sessions.worktrees`: `of_branch`, `branch_names`, `in_checkout`). *SessionGraph* (`session.session_graph`, `session_graph.py`) is the session's knowledge graph and the one owner of the graph file saved in its work folder (`graph`, `overlay`, `forget`, `saved_file`, `last_read`); it reads a file a viewer shows into the whole graph when it changed (`holding(path, is_held)`), keeps when the graph view's listed files were read (`listed`, `as_it_is_now`), and holds the *DocumentGraph* a viewer reads one file into on its own (`alone`). *DocumentGraph* is the one reader of a single document into a graph of its own instances of the practices: a file from a folder (`read(folder, path)`), or a document's text written into a folder of its own (`read_text(practice, text, placed_at)`), as a format alignment compares formats; and *GuidanceSelection* (`session.guidance`, space/session/practices) changes the guidance selection and raises its version on each change (`toggle`, `select`, `changed`, `wait_past`). *SessionPractices* (`session.session_practices`, space/session/practices) are the session's one instance of each practice (`every`; `working`, the practices switched on, which the board and chat show; `held`, those plus any switched off that an action works on (`session.take_up(name)`), which the graph holds; `forget` when the workpath moves), made under the reentrant lock (`lock`) the *SessionGraph* is made under too, which with the graph `session.graph`, `session.practices`, `session.own_practices`, and `session.practice(name)` answer from. *SessionExplorer* (space/session/files), mixed into *Session*, is the graph tools a page browsing the session's files calls (`graph_trees`, `graph_branch`, `graph_node_ranges`, `graph_members`), each reading the session's graph itself. The session's published tools keep their `session.*` names while their declarations sit in the bases mixed into *Session*, one per job, each doing its job or asking the part that does it: *SessionFileTools* (its files, through *SessionFiles*), *SessionExplorer* (its graph, read by the tools themselves), *SessionGuidanceTools* (*GuidanceSelection*), *SessionLogTools* (its log and handoffs), and *SessionDecisionTools* (*DecisionRecords*). What one fidelity writes in a session, where each format goes, which files are there, and which the branch changed, is its *FidelitySessionOutput*'s *WrittenFiles* (space/session/practices; `session_output.written`: `output_paths`, `files`, `holds`, `every_file`, `has_named_output`, `has_found_output`). A fidelity keeps one or several roots (`choose_root`, `add_root`, session.json `root` or `roots`). The folders it proposes for the pieces a ticket works on are its *ProposedRoots* (`session_output.proposed_roots`, space/session/practices: `holding(files)`, `named(names)`, `proposed(names)`; published as `fidelity-session-output.propose_roots`): the narrowest folder holding each piece, read from the fidelity's own declared outputs, so no practice is named in it. `session.set_up_roots` is the instructions an agent follows to set a session's roots, which switching to a session with unchecked roots points to: read the ticket and its branch, ask each fidelity for its proposals, dig to the narrowest folders, confirm with the person, then set them. A closed session's record moves to `.sessions/_complete/{name}/` (`sessions.closed_folder`, the one place that folder is named). A session is one object for each record folder, which its *Sessions* hold, and what it keeps on disk is read from its folder each time a caller asks for it, so a switch or a close made by another chat or by the hook server is seen at once; its `session.json` (`session.record.fields`), which one board read asks thousands of times, is read once for each answer (*AnswerReads*, harness/process): each call and each hook event that finds its sessions through *CallSessions* begins an answer (`sessions.answers.begin()`, *ServedAnswers*, which `session.answer` reads), so a change another process wrote is seen by the next call, and each `save_fields` begins one too, so no read in the process answers what the file held before its own write; between answers the file is read again only once its last-written time or size changes (*HeldJsonFile*, harness/installation). Sessions no call is served from, such as ones a spec makes itself, hold nothing and read on every ask. A practice's folder named in the project's `.context/config.json` is held for the answer the same way.

*Sessions* are the work sessions of one checkout and which of them is open. `Sessions(project)` holds the checkout holding the project (`sessions.repo`, `Repo.of_project`, the one Repo this process holds for that checkout), and every session it loads or creates is made with those sessions and its record folder, which names it (`Session(sessions, record_folder)`, `session.sessions`), and is placed where it works now in one order (`session.placed()`: its checkout, then its work folder, then its workpath) and holds that repository (`session.repo`), so a session closes, moves, and lists its files without building either again. A chat in a ticket's own worktree works on that ticket, found from the worktree's branch, whatever any chat chose to open. Which session each chat has open is the sessions' part *OpenSessions* (`sessions.opened`, `open_sessions.py`): a chat in the repository's own folder keeps its open session in *WorkState* (`sessions.opened.state(chat)`), kept by the cdd server under `~/.cdd` and never in the checkout; `opened.name_for(chat)`, `opened.open(session, chat)`, `opened.current(chat)`, `opened.close(session, chat)`, and `opened.switch(name, workpath, call)` read and change it, each for the chat it is handed (an empty chat is a call that names none, which keeps the checkout folder's own entry; nothing falls back to a process-wide call), and `SessionNameRequiredError` is raised there. A switch answers a *SwitchedSession*: the session opened, what the modules listening for an opening told the chat (`OpenSessions.on_session_opened`), the ticket it opened in place of the one asked for when the chat works in that ticket's worktree (`opened_in_worktree_of`), the session's own worktree when the chat works elsewhere (`outside_worktree`), and the practices whose roots nobody set (`default_roots`); its `instructions` say them in the words of `SESSION-SWITCH.md`, then how to keep the log, and `sessions.switch` answers that text. `session.close(call)` closes the session for the calling chat. `Sessions(project).current()` and `Sessions(project).switch(name, workpath)` are the only operations that read or change which session is open; `load(folder)` and `with_file(session_file)` read a session without opening it, `named(name)` and `all()` find the board's sessions, `create(name, workpath, title=, scope=, parent=)` makes a session for later without opening it, and `opened.close(session, chat)` makes main chat's open one again when chat had that session open; `sessions.current` and `sessions.switch` are the published tools, each asking *OpenSessions*. Every checkout's sessions keep their records in the repository's own `.sessions`, in its main clone (`sessions.folder`), so the board reads every ticket from one place; a chat in a ticket's linked worktree writes the session's log and the rest of its work into the worktree's own `.sessions/{name}/`, the session's work folder, so the ticket's branch carries its work and main carries only its record. A session moved to the closed sessions, the archive, or the backlog, or reopened, moves its record folder and stays the same object. `sessions.read_apart()` answers a *SessionsRead*: every session whose `session.json` reads (`sessions`), with the failure of each one that does not (`failures`), so a reader that shows many sessions, such as the board, shows the rest and names the damaged file, where `all` stops at the first.

*SessionRecord* (`session.record`) is the session's `session.json` read into typed fields (*SessionFields*): name, title, scope, workpath, tags, overlays, parent, pulled out, the branch, worktree, and chat its checkout recorded, its guidance selection (*SelectionFields*), and one entry per practice (*PracticeFields*: whether it is on, its chosen root, and one *FidelityFields* per fidelity: the formats chosen, its own roots, and a file name per format). Each part of the session changes its own fields with `record.update(change, said)`, which changes the file as it is now and queues its save on main. `update` is the one path that writes session.json, and it holds the file from its read to its write (`record.held()`, harness/installation's `JsonFile.held`: the operating system's lock on `session.json.lock` beside it), so a change two chats or two processes make to one session at the same moment are both kept; a caller that adds to what the record holds, such as a tag, a root, a chosen format, the guidance version, or a module's test tiers, works the new value out inside its change, from the fields the change is handed, never from a read made before it. The lock ends when its holder lets go or its process ends, so a killed holder blocks nobody; a change that waits 30 seconds for a live holder is refused (*JsonFileBusy*). A session.json that is not a readable JSON object, such as one left half written, is refused by name (*JsonFileUnreadable*) and left as it is. The saves leave the lock file and a killed writer's staged text out of every commit, as they do for every JSON file in the session folders, and the list of the session's folder leaves them out too (`SessionFiles.in_folder`, asking `record.is_left_beside(path)`), so the Files app never shows them. No file write reaches the record: `session.write_file` and `file-manager.write` refuse the session's own session.json, however its path is spelt (`record.is_its_file(path)`), with *SessionRecordWriteRefused*, which says to use the session's tools; reading it is unchanged. A file in the shape older servers wrote, a practice's roots kept apart under `outputs`, is upgraded as it is read and written in today's shape on its next save; `repo_path`, which nothing read, is dropped. An owner outside the session keeps its own fields through `record.extra(owner)` (*OwnedFields*), such as the board's `stage` and `stage_mark`, which stay where they are in the file; it is refused a field of the session's own (*SessionFieldOwnedError*). *TestTiers* (`session.test_tiers`, `test_tiers.py`) is the session's record of the test tiers each module uses, so the next test written for a module is written at every tier the module needs: `recorded` (each module's path from the project, with the test tool of each of the tiers unit, server and web it uses), `of(module)`, and `record(module, tiers)`, which keeps tiers beside those the module holds. The record is `test_tiers` in session.json, such as `{"space/kanban": {"unit": "mamba", "server": "mamba", "web": "playwright"}}`; a file with none reads as no tiers chosen yet, a record in any other shape is refused with *MisshapenTestTiersError*, and a tier that is none of the three, or one with no tool, is refused with *UnknownTestTierError* or *TestToolRequiredError* and nothing is recorded. A generate or a render that writes tests fills it (the TDD supplement, cdd_guidance/practices/tdd), and `session.record_test_tier(session, module, tier, tool)` records a tier an agent decided. *SessionCheckout* (`session.checkout`, `session_checkout.py`) is the one reader and writer of the `branch`, `worktree`, and `chat` the record keeps: the session's own branch (recorded, else named as the session, else the one branch holding its name as a whole word, `names_ticket`), its own linked worktree, its one project (`repo`, `root`: that worktree, else the checkout whose sessions hold it, whose `.context/config.json` it reads), the chat a person assigned, and `record_opened()`. *CheckoutWorktrees* (`sessions.worktrees`, `checkout_worktrees.py`) lists the linked worktrees and branches once and again after two seconds, the one caching rule.

The *workpath* is the folder a session works in; its practices write under it and its graph is opened on it. `Session.graph` is the session's knowledge graph (harness/graph's *Graph*). `Session.overlays` names the patterns the session overlays on that graph, kept in its session.json; `choose_overlays` replaces them and applies them to the graph at once, and a graph made later applies them when it opens. The sessions that loaded a session hold one *Session* object per session folder (*HeldSessions*, `sessions.held.load(folder)`, answers it, and a session moved to another folder stays that object; *SessionListing*, `sessions.listing`, says which folders hold a session), and every call in the session, from any chat, works on it: it makes its graph and its one instance of each practice (made with `PracticeCatalogue.create_all()`) once, under a lock, so two calls that first ask at once wait for the one the first makes, and every call in the session works on the same graph and the same practices and none rebuilds them. A session holds no chat: a call's chat is the call's own, and the lines a call writes go through `session.log.by(call.request.chat)`. The process holds the sessions of each project it serves (*CallSessions*, `Sessions.of_project(project)`), so the kept sessions last for as long as the cdd server runs. A new graph reads back the graph saved in its root's `.context/graph.json` (`graph.reads.open_saved`, its *GraphReads*), so a session opened again, such as a ticket just activated, shows what was loaded in it before rather than an empty graph. When a session's root moves, it makes its graph and practices again on the new root. An action that writes files refreshes it with exactly those files (`GuidanceAction.wrote`, or `graph.refresh` from the agent); nothing watches the files. An empty workpath is the whole repository. `Session.work_root` is that folder, worked out in one place: sketches, grill answers, partitions, each practice's folder, and the file manager all start from it.

*SessionLog* (`session.log`) is the session's `session.log` and `session.err`: one line per action, tool call, note, and loop marker, stamped with a *LogTimestamp* (harness/process: UTC, to the second; the one time format every log a session keeps uses, and the board's last-activity times, the prompt log, the toasts, the violation history's lines, and an accepted violation's time use it too; `REPORT_DATE_FORMAT`, beside it, is the stamp a validation report's or a handoff's file name ends with), each ending with a pointer to the chat that caused it. Both are capped (*CappedLogFile*, harness/process): a log that reached 4 MB moves its lines to `session.log.1` (or `session.err.1`), and the new `session.log` starts with the loop it was in (`--- N continued from session.log.1`), so loops number on; the hook logs in `logs/` are capped the same way. A *Loop* is one context–generate–evaluate cycle marked in the log, so the lines of one cycle can be read back together with the chat that produced them. Each line points at the chat that caused it — the *ChatPointer* (harness/agent_tools) of the tool call that wrote it, through the *ChatLog* that call writes with (`session.log.by(call.request.chat)`), else `no-chat`; never a chat the server's environment names, which would point one chat's line at another — so `session.read_loop` can put that chat's words back under the line. A session tool that writes a line, such as `session.mark_loop` or `session.append_log`, takes the call it answers, which the framework hands it as it hands `project`. The rules a hook gave the agent (*InjectedRules*, made once with the log) wait in the session's work folder until the next log line names them, because the hook server notes them and the cdd server writes that line. *ChatInjections* (`session.chat_injections`) keep the rules a hook gave each chat of the session in its `chat-injections` folder and replay them on that chat's next prompt, never another chat's; the hook server asks the session of each event for them. How an agent keeps the log is `SESSION-LOG.md`, which `sessions.switch` answers with.

A ticket's record is kept on main so every chat and worktree reads the same board. A session saves itself: each write to its record folder (`session.record.update(change, said)`, where each part of the session changes its own typed fields, `keep_text`, `session.folder.keep_file`, a move of its record folder, `session.folder.remove`) queues the save of that change and returns at once, so a caller such as a board ticket only says what changes. *SessionSaves* (`sessions.saves`, one for each repository's `.sessions`, shared by its main checkout and every worktree) commits the session folders on main and pushes main on a thread of its own, half a second after a change so every file it writes goes in one commit, several waiting saves in one commit, and not while a merge is in progress in the repository's own folder, which a commit would conclude, nor while that folder has a branch other than the default checked out, which a commit would put the records on: the saves stay queued and are made once the default branch is checked out there again, and meanwhile `saves.failure` says why, so the board shows it. A project git does not hold has nothing to commit, so a save there is never queued and no thread starts for it. In a repository `git init` made, with no commit yet, the first save is its first commit, so opening a ticket has a commit on the default branch to start the ticket's branch from. `saves.later(message)` queues a save of something in `.sessions` that is no session's own, such as a Backlog item or the board's card order; `saves.now(message)` waits for the queued saves and saves in the caller's thread, for work that needs main committed before it goes on (opening a ticket's worktree, closing or archiving it), and raises git's refusal, or *DefaultBranchNotCheckedOut*, naming the branch checked out, while the repository's own folder is off the default branch, leaving the queued saves queued. Before it commits, it makes sure the session folders' own `.gitignore` lists each file no save commits: what every JSON file's writes leave beside it for a moment (`LEFT_BESIDE`, harness/installation: the text a write stages before renaming it over the file, and the lock file a change holds), since `git add` would pick up staged text that is renamed away while git reads it and refuse the save; and each file a module registered to be left out (`SessionSaves.leave_out(pattern)`), such as the board's progress caches (`**/progress-cache.json`, registered by space/kanban), which are machine state worked out again wherever they are missing. So no save commits one in a project whose own `.gitignore` does not name it. A queued save git refuses is kept as `saves.failure`, a *SaveFailure* naming the changes not saved and what git said, until a save succeeds; `saves.retry()` queues them again. The changes stay on disk, so the board works on them meanwhile. Removing a record folder that a running program holds open, such as a shell working in it, raises *SessionFolderHeldError*, which names the folder, with every file still in it.

A *handoff* is a compact account of a session — what it achieved, what was learned, and where the next agent starts — so a fresh agent can continue the work without rereading the whole chat. *Handoffs* (`session.handoffs`, made when the session is given its work folder) write each one as a new `handoff-{timestamp}.md` in the session's work folder, so a ticket's handoffs are committed on its branch; `Session.latest_handoff` names the newest. Each is a *Handoff* (`handoffs.latest`), whose `next_steps` are the numbered steps of its Approach for Next Agent. A module outside the session acts when a chat opens one through `OpenSessions.on_session_opened(listener)`, which tells the chat what the listener answers: tools/prompt_queue registers there to queue the latest handoff's next steps on the chat's queue (`PromptQueue.queue_once(source, texts)`), so the session imports no tool. A practice's `PracticeSessionOutput.design_view` (space/session/practices) is the Claude Design link recorded for the latest version of the design canvas under the folder it writes under (*CanvasVersions* of harness/design_canvas; the UX practice's), which the chat bar's file viewer opens; empty while the practice is off or none is recorded. The instructions `session.handoff_session(next_focus)` read the handoff format (`HANDOFF-FORMAT.md`, through `session.read_handoff_format`), draft the handoff, and call `session.write_handoff`.

A *Context Decision Record* (CDR) is a short, numbered markdown file that records a design choice a later reader would otherwise question: one that is hard to reverse, surprising without its context, and a real trade-off. *DecisionRecords* (`Session.decision_records`, made again when the workpath moves) are a session's records, `.context/cdr/{NNNN}-{slug}.md` under its workpath, each numbered one past the highest; `CDR-FORMAT.md` beside this module is their template. `session.read_cdr_format`, `session.list_cdrs(session)`, and `session.write_cdr(session, slug, paths)` read the format, list the records, and write one; the instructions `session.record_decisions_session(session)` wrap an action's turn so records are offered as decisions are made.

*CallSessions* holds the sessions of every checkout the process serves, each made once and held by the checkout's top, as its one Repo is (`Sessions.of_project`), so a call naming a folder inside the checkout reaches the same sessions; it is how a tool call opens its sessions: `sessions.py` registers it with `SESSION_OPENING` (harness/agent_tools) when it is imported, so `call.session` is the session open in the call's project and `call.session_named(session_file)` the one a board command names, each the one object its sessions hold, and `SESSION_OPENING.saved_in(project)` the session open in a project for work that serves no call, such as a hook event (`HookPayload.session`) or a diagnostics probe, while the framework never imports this module. `SERVED_SESSIONS.forget_under(folder)` lets go of the sessions of every checkout inside a folder, which a spec's *ThrowawayProject* asks when it closes, so a run of many projects in one process does not keep each one's sessions, graphs, and practices to its end. `Session.from_file`, `PracticeSessionOutput.load`, `FileManager.load`, `FileComments.load`, and `FormatAlignment.load` take the call they serve and find their session through it, so session.py and the modules below it never import sessions.py, which imports them.

The MCP tools `sessions.current` and `sessions.switch` act on the project the call names. Every `session.*` tool acts on the session whose `session.json` its required `session` argument names (a path from the project): `session.close`, `session.show`, `session.choose_workpath`, `session.folder_files`, `session.workpath_files`, `session.read_file`, `session.write_file`, `session.file`, `session.mark_loop`, `session.read_loop`, `session.append_log`, `session.write_handoff`, `session.read_handoff_format`, `session.read_cdr_format`, `session.list_cdrs`, and `session.write_cdr`, and the instructions `session.handoff_session` and `session.record_decisions_session`; each finds its session and calls one operation on it or on its log, files, handoffs, or decision records. The file manager's and the file comments' tools are space/session/files's, the practices' and fidelities' tools space/session/practices's, the format alignment's tools (`format-alignment.*`) cdd_guidance/align's, and `session-diagnostics.session_diagnostics` cdd_guidance/diagnostics's. The commands `/current-session`, `/switch-session`, `/close-session`, `/mark-loop`, `/read-loop`, and `/append-log` call them, and the skills `space-session-handoff-session` and `space-session-record-decisions-session` run the two instructions.

- **Purpose:** Keep the state of one piece of work — where it works, which practices it uses and where they write, the files it works with, the log of what was done, the handoff the next agent resumes from, and the reasons behind hard-to-reverse choices — so any chat or tool can pick the work up from its folder.

## Constraint

Name the session work is for. Every `session.*` tool takes the session's `session.json` as its `session` argument and refuses an empty or missing one with `SessionNotFoundError`, so work asked for one ticket never lands in whichever session a chat has open; ask `sessions.current` for the open session's `session_file` when the user names none. Only `sessions.switch` changes the open session; a name no session has is refused with `UnknownSessionError`, naming the sessions there are, unless `create` is true, so a misspelt name never makes a session and a card nobody asked for. Only `sessions.current` and `ToolCall.session` read the open session. Read another session with `sessions.held.load`, `Sessions.with_file`, `Session.from_file(session, call)`, or `Sessions.named`, which do not open it. Write to a session's log through `session.log.by(chat)`, never by editing `session.log`. Draft a handoff or a decision record to a file and pass its path in `paths`; do not put its body on an MCP call. Offer a decision record only when all three criteria hold, write it as soon as the decision is made, and never invent or batch decisions. Write large or temporary outputs (graph JSON, probes, reports) under the session's work folder, not beside the work. Write into the record folder only what the board reads, `session.json` and the idea file, since every write there is committed on main. Specs that run actions open a *ThrowawayProject* (space/session/spec_support) and close it after each example. Keep the core free of the modules above it: a part that runs an action, a practice, or a tool, or that only the board reads, goes where it is used and reaches the session through the call, as format alignment and the progress cache do (`cdr/0002-the-session-splits-into-modules.md`).
