# space/session
*Session* is one named piece of work in a project — a board ticket's work, or `main`, which works on the whole repository — so every action, log line, handoff, and validation report lands in the folder of the work it belongs to. A session lives in `.sessions/{name}/`: its `session.json` (title, scope, parent, workpath, and practice roots), its `session.log`, its handoffs, and its validation reports. A closed session moves to `.sessions/_complete/{name}/`. The open session is saved in one place, `session` in the project's `.sessions/session.json` (through *WorkState*); `Session.current()` is the open session of the project the running call names, and the hook server reads the same record for each event, so a switch or a close reaches the hooks at once. Hooks write their logs under the open session's `logs/` folder (`Session.hook_log`).

The *workpath* is the folder a session works in; its practices write under it and its graph loads from it. An empty workpath is the whole repository. `Session.root` is that folder, worked out in one place: sketches, grill answers, partitions, each practice's folder, and the file manager all start from it.

*PracticeSessionOutput* is what one practice has in one session: whether it is on, the guideline it works with at its current fidelity and format, the folder it writes under, and its graph. `session.practice("stories")` returns it. Each fidelity of its guideline holds a *FidelitySessionOutput*: where that fidelity writes each format in the session, the files it declares there, and its reports folder.

A *Loop* is one context–generate–evaluate cycle marked in the session log, so the lines of one cycle can be read back together with the chat that produced them. *ChatPointer* names the chat a log line came from — its id, its transcript, and the transcript lines the line covers — so `session.read_loop` can put that chat's words back under the line.

A *handoff* is a compact account of a session — what it achieved, what was learned, and where the next agent starts — so a fresh agent can continue the work without rereading the whole chat. `session.write_handoff(session, paths)` writes each one as a new `handoff-{timestamp}.md` in the session's folder, and `Session.latest_handoff` finds the newest. The instructions `session.handoff_session(next_focus, session)` draft the handoff and call `session.write_handoff`.

A *Context Decision Record* (CDR) is a short, numbered markdown file that records a design choice a later reader would otherwise question: one that is hard to reverse, surprising without its context, and a real trade-off. *DecisionRecords* (`Session.decision_records`) are a session's records, `.context/cdr/{NNNN}-{slug}.md` under its workpath, each numbered one past the highest; `CDR-FORMAT.md` beside this module is their template. `session.read_cdr_format`, `session.list_cdrs(session)`, and `session.write_cdr(session, slug, paths)` read the format, list the records, and write one; the instructions `session.record_decisions_session(session)` wrap an action's turn so records are offered as decisions are made.

*ThrowawayProject* is an empty project a spec works in, so the actions a spec runs write to their own session log instead of the log of whoever is working in the repository.

Every `session.*` operation but `session.current` acts on the session its `session` argument names (a session.json path from the project; empty is the open session). The MCP tools are `session.current`, `session.switch`, `session.close`, `session.choose_workpath`, `session.files`, `session.folder_files`, `session.read_file`, `session.mark_loop`, `session.read_loop`, `session.append_log`, `session.write_handoff`, `session.read_cdr_format`, `session.list_cdrs`, and `session.write_cdr`, and the instructions `session.handoff_session` and `session.record_decisions_session`; per practice, `practice-session-output.enable`, `practice-session-output.choose_root`, and `practice-session-output.use_default_root`; and `session-diagnostics.session_diagnostics` probes the session log through the live MCP host. The commands `/current-session`, `/switch-session`, `/close-session`, `/mark-loop`, `/read-loop`, and `/append-log` call them, and the skills `space-session-handoff-session` and `space-session-record-decisions-session` run the two instructions.

- **Purpose:** Keep the state of one piece of work — where it works, which practices it uses and where they write, the log of what was done, the handoff the next agent resumes from, and the reasons behind hard-to-reverse choices — so any chat or tool can pick the work up from its folder.

## Constraint

Name the session work is for. Work asked for a named session — a board ticket's handoff, decision record, or validation — passes that session's `session.json` as the `session` argument, so it goes to that session, never to whichever session the chat has open, because a chat can be asked for another ticket's handoff; a session.json that is not there raises `SessionNotFoundError` instead of writing elsewhere. Read another session with `Session.load` or `Session.from_file`, which do not make it current; only `session.switch` changes the open session. Draft a handoff or a decision record to a file and pass its path in `paths`; do not put its body on an MCP call. Offer a decision record only when all three criteria hold, write it as soon as the decision is made, and never invent or batch decisions. Write large or temporary outputs (graph JSON, probes, reports) under the session's folder, not beside the work. Specs that run actions open a *ThrowawayProject* and close it after each example.
