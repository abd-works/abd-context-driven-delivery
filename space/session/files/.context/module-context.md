# space/session/files
The files a session works with: listed, read, and saved through a file manager that keeps a call inside the session's roots, shown file by file as the viewer shows them, commented on line by line, and browsed through the session's graph. The session's core (space/session) makes these objects with the session (`session.session_files`, `session.file(path)`, `session.file_comments`) and mixes *SessionExplorer*'s graph tools into *Session*; this module never imports the core back.

*SessionFiles* (`session_files.py`, `session.session_files`) are the files a session works with: the ones in its record folder and its work folder, and any file of its repository it reads. They are the one place a path a call names is checked: `existing(named)` answers the path once something is there, `from_root(named)` writes it from the session's root, as the session's graph names its files, and `in_root(path)` says whether a path lies under that root; each refuses with *NamedPathNotFoundError*, which names the path, the project it was read from, and the root when the root refused it, so the Validate, Grill, and Context Index actions never work on nothing and report it as a clean result; the files a practice declares are each fidelity's own, through its *FidelitySessionOutput* (space/session/practices), which searches the session's file manager named from the project's top with each declared path's glob (*DeclaredFile*, harness/guidance).

*FileManager* lists, reads, and saves the files under a session's roots — the folder each of its practices works in — so every application shows files the same way instead of each object growing a read operation of its own. `session.session_files.file_manager` is the session's, held in memory and made again only when its roots change; a tool call loads it with `FileManager.load(call=...)`, from the session open in the call's project (`call.session`). A session reads through two file managers because paths are named from two tops: its own, named from its workpath, which a page lists and reads, and one named from the project's top (*SessionFiles*), which reads and finds the files the board names that way. `sessions.file_manager` lists the folders anywhere in the checkout, named from its top, for the board's folder picker. *Folder* is a listed folder and its entries, folders first; *FolderEntry* is one entry with its path and size. *FileEntry* is a declared file with its path from the project, whether it exists, and whether the session's branch changed it (`is_changed`, which the board's changed-files filter reads; `SessionFiles.branch_changes.files()` asks git once a file is there). *FileText* is a file's path, its text, and the language a viewer shows it in, from its suffix. The MCP tools are `file-manager.list(folder)`, `file-manager.read(path)`, and `file-manager.write(path, text)`, which refuses a path outside the roots as reading does; a board command saves a ticket's file with `session.write_file(path, text)`, named from the project as `session.read_file` names it. A *FileText* says whether its file was there when it was read (`exists`), so a viewer says a listed file is gone instead of showing it empty.

*FileComments* (`file_comments.py`) are the comments a person writes on lines of a session's files in the Files app (`harness/files_app/`, its own module context), kept in `file-comments.json` in the session's work folder so they stay when a page reloads; `session.file_comments` is the session's, and a tool call loads it with `FileComments.load(session=...)`. *FileComment* is one comment on a *Range* of a file, with its text, anchored as `path:Lstart-Lend`, one per range; `add(path, start_line, end_line, text)` keeps what those lines hold when the comment is written. Its state is read from the chat it was sent to (`harness/chat`), never kept twice: `not_sent` until `Chat.queue` holds it, `sent` until the chat's turn that worked on it has ended, then `processed`; a message the chat failed to show leaves it not sent. `send(anchor, chat)` and `send_open(chat)` put the comments in the chat's prompt in one fill, each as `path:start-end: comment` and its lines marked `> n |`, with `session=<session.json>` last. The MCP tools are `file-comments.on(path)`, `file-comments.add`, `file-comments.remove(anchor)`, `file-comments.send(anchor, chat)`, `file-comments.send_open(chat)`, and `file-comments.clear_processed`; the board's TypeScript reaches them through the language adapter the installer deploys.

*SessionFile* (`session_file.py`) is a file of the session as the viewer shows it, from `session.file(path)`: its text and language, its comments, its *Folds*, and its *FileViolations*, each on a *Range* of its lines (`SessionFile.range(start_line, end_line)` returns a Range with the text those lines hold). Folds and violations come from the graph the session saved in its folder (`graph.json`), whose files are named from the session's root: a fold for each class (`class`) and each operation or property (`block`), the kinds the graph's source view folds on (`harness/graph/app/source/call-expansion.ts`); the viewer keeps which folds are open. A file the saved graph never read, or a session with no saved graph, has none. The viewer shows a file of at most `VIEWER_SHOWS_LINES` (30,000) lines; a longer one is refused with *FileTooLongToShowError*, which carries the file, its lines and that limit, because drawing it would freeze the page and lose the comments not yet sent. A page that filters its files sends its filters with the read, `session.file(path, paths=..., node_filter=...)`: the files it lists for the stages, practices and formats chosen, and the graph view's node filter, as `session.graph_trees` takes them. The session then answers only the callouts those filters show (*FileViewFilter*, `file_view_filter.py`, which asks the graph's own *Filter*): a link into a file of a practice turned off is left out, a file no fidelity declares or one that is not there always shows, and what a step invokes or observes is left out while the node filter leaves out that connector or node type. A read that sends neither holds every callout, so the decision is made once, in Python, for every page. *NodeSpans* (`node_spans.py`) asks a node's reading whether it is used from elsewhere (`is_used_from_elsewhere`), such as a story's example. *SessionExplorer* (`session_explorer.py`), mixed into *Session*, is the graph tools a page browsing the session's files calls (`graph_trees`, `graph_branch`, `graph_node_ranges`, `graph_members`), each reading the session's graph itself.

- **Purpose:** List, read, save, show, and comment on the files a session works with, the same way for every page, without letting a call reach a file outside the session's roots.
- **Seam (terms):** SessionFiles (`existing`, `from_root`, `in_root`), NamedPathNotFoundError, BranchChanges, FileManager, Folder (`folder_paths`), FolderEntry, FileEntry, FileText (`rendered_form`), FileStep, StepCallout, StoryTestCode, Publication, PathOutsideRootsError, SessionFile, Range, LineSpan, Fold, FileCallout, FileStep, FileChange, FileViolation, RuleReads, FileViewFilter, FileTooLongToShowError, `VIEWER_SHOWS_LINES`, FileComments, FileComment, FileCommentNotFoundError, CommentSending, NodeSpans, SessionExplorer (mixed into Session: `graph_trees`, `graph_branch`, `graph_node_ranges`, `graph_members`), `file-manager.list`, `file-manager.read`, `file-manager.write`, `file-comments.on`, `file-comments.add`, `file-comments.edit`, `file-comments.remove`, `file-comments.send`, `file-comments.send_open`, `file-comments.clear_processed`; `@language_adapter(language="typescript")` on *FileManager* and *FileComments*, whose clients are `@cdd/space/session/files/file-manager` and `@cdd/space/session/files/file-comments`.
- **Dependencies (one-way):** `harness/agent_tools`, `harness/installation` (`@language_adapter`, *JsonFile*), `harness/mcp`, `harness/chat` (*Chat*, whose messages say a comment's state), `harness/graph` (*Graph*, *SavedGraph*, *Filter*, the explorer), `harness/markdown`, `harness/git` (*Git*, which says which files a branch changed). It names the session's core (*Session*, *SessionGraph*, *SessionPractices*, *SessionCheckout*, *SessionPaths*) only for typing, since the core makes this module's objects: nothing of space/session, its practices, or its validation is imported at run time.

## Constraint

Name a file manager's paths from the session's workpath: a path outside the session's roots raises *PathOutsideRootsError*, so a caller cannot read the rest of the disk through a session, and `read` returns no text for a file that is gone, such as one deleted since a page listed it; check `FileText.text` rather than expecting an error.
