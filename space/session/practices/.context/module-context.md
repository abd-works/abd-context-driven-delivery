# space/session/practices
What each practice has in a session, and which of them the session's pages show. The session's core (space/session) makes these objects with the session and holds them (`session.session_practices`, `session.practice(name)`, `session.guidance`); this module never imports the core back, and names the session only for typing.

*PracticeSessionOutput* is what one practice has in one session: the session's one instance of the practice (`guidance`), whether it is on, and the folder it writes under. `session.practice("stories")` returns it. Its data also carries the practice's `short_name`, `colour` and `fidelity_slugs`, so a page such as the Files app draws a toggle for it in its colour and knows which of a stage's files are its own; `session.show()` answers the session with every practice, on or off, changing nothing. An action works on that same practice: it holds the fidelity its guidance names (`GuidanceAction.fidelity_of`) and never moves the practice's current fidelity, which stays the one the practice was made at, and gives the format it names to that fidelity, which keeps it; so another call on another fidelity of the same practice changes nothing it reads. The line it logs names that fidelity: it hands the log the fidelity's *FidelitySessionOutput*, the one the fidelity holds, whose `practice` answers the practice's name and folder and whose `fidelity` its name and format; the log takes no other kind, and a practice worked at no fidelity is named on no line. The practice works in the session through `PracticeGuidance.work_in`, which gives each of its fidelities, through `FidelityGuidance.work_in`, its *FidelitySessionOutput*: where that fidelity writes each format in the session, the files it declares there, the format it last used, and its reports folder. Where a practice writes is kept in one place, its session's `session.json` (`outputs`), else it is the practice's default: the folder the project's `.context/config.json` (`session.context_config`, the config of the checkout the session works in: its ticket's own worktree when it has one, whichever checkout's sessions read it, made again only when the session moves to another checkout) names for it, else the guidance's own default folder. A fidelity reads and saves its part of the practice's `session.json` through the practice's public `chosen_outputs`, `saved`, and `save`. The session makes its practices once, with its graph; a validate is logged for the call that ran it (`session.log.by(call.request.chat).validation(worked, violations)`, which a guidance action reaches as its `log`), so the line points at that call's chat. A root is chosen as a folder: `root_named(path)` reads the path from the repository and refuses an empty path or a file with *OutputRootRefused*, so the agent is never told to write a practice's files into a file; a folder that is not there yet is a root the practice writes into.

*SessionPractices* (`session_practices.py`, `session.session_practices`) are the session's one instance of each practice (`every`, `working`, `forget` when the workpath moves), made under the reentrant lock (`lock`) the session's *SessionGraph* is made under too. *ProposedRoots* (`proposed_roots.py`, `session_output.proposed_roots`: `holding(files)`, `named(names)`, `proposed(names)`; published as `fidelity-session-output.propose_roots`) are the folders a fidelity proposes for the pieces a ticket works on: the narrowest folder holding each piece, read from the fidelity's own declared outputs, so no practice is named in it. *FileListing* (`file_listing.py`, `session.guidance.listing(linked)`) applies the guidance selection and the fidelities a page's link names to each file a ticket or the session answers (`of_fidelity`, `of_root`, `of_folder`), and each *FileEntry* says `is_listed` and `is_session_work`, so the Files app filters by those and restates no rule. The session's sketch (`SessionPaths.is_sketch`) is listed whatever is selected, as a file of the session's own folder is: no fidelity declares it, it holds every practice's section, and its person reviews it next.

*GuidanceSelection* (`guidance_selection.py`, `session.guidance`, held by the session and read from its record on each ask) is the stages, practices, and format groups the chat bar and the Files app show and act on. It changes itself: `toggle(part, name)` (published as `session.toggle_guidance`) works out the selection one press leaves, `select(stages, practices, formats)` writes it in one change of the record and raises the version once (`changed`), and `wait_past(version)` answers a waiting page. Before anyone chose stages, it shows the stage the session's ticket stands in selected, which the board registers how to read (`GuidanceSelection.start_on_ticket_stage_with`, read once per answer). It writes the command an action runs on its fidelities (`command(action, fidelities)`, and `commands` for the fidelities selected): the one place a command and its `format=` are written, with the formats chosen for an action that takes them. *FormatGroup* is one group of formats, with the data fields the chat bar reads (`label`, `formats`, `offered`, `is_selected`).

- **Purpose:** Keep what each practice and each of its fidelities has in one session, where it writes, which files it declares and holds there, the folders it proposes, and the guidance selection a page shows and acts on, so every page and action asks the same objects.
- **Seam (terms):** PracticeSessionOutput, FidelitySessionOutput, WrittenFiles (`session_output.written`), FidelityFormats, ProposedRoots (`session_output.proposed_roots`), SessionPractices (`session.session_practices`), GuidanceSelection (`session.guidance`: `toggle`, `select`, `changed`, `wait_past`, `command`, `commands`, `covered`, `covered_stages`, `start_on_ticket_stage_with`), StageSelection, PracticeSelection, FormatGroup, UnknownSelectionPart, FileListing (`session.guidance.listing(linked)`), OutputRootRefused (`PracticeSessionOutput.root_named(path)`), FormatNotOfferedError, FidelityNotInPractice, `practice-session-output.enable`, `practice-session-output.choose_root`, `practice-session-output.use_default_root`, `fidelity-session-output.choose_root`, `fidelity-session-output.add_root`, `fidelity-session-output.propose_roots`, `fidelity-session-output.choose_format`; `@language_adapter(language="typescript")` on *PracticeSessionOutput* and *FidelitySessionOutput*, whose clients are `@cdd/space/session/practices/practice-session-output` and `@cdd/space/session/practices/fidelity-session-output`.
- **Dependencies (one-way):** `space/session/files` (*FileEntry*, *Publication*, and the kinds of file a practice publishes), `space/session/validation` (*ValidationReports*, a fidelity's reports), `harness/process` (*HeldForAnswer*, what a fidelity reads from the session's record, held for one answer), `harness/guidance` (*DeclaredFile*, *PracticeCatalogue*, *ActionCatalogue*, the stages), `harness/agent_tools`, `harness/installation`, `harness/mcp`, `harness/markdown` (*Format*), `harness/design_canvas` (*CanvasVersions*), `harness/whiteboard`. It names the session's core (*Session*, *SessionRecord*'s fields) only for typing, since the core makes this module's objects: nothing of the core is imported at run time, so the core imports this module and never the other way.

## Constraint

Read and change a practice's place in a session through the session's one instance of it (`session.practice(name)`), never a practice made apart from the session, so every call works on the same folders, formats, and graph. Write a fidelity's part of the record through its practice's `chosen_outputs`, `saved`, and `save`.
