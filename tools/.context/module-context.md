# tools
*Tools* are standalone toolsets an agent or an application calls beside the practices. Each one sits in its own package and depends on none of the others, so a tool can be added or removed without touching the rest; they share this one card because none of them is big enough to be a module of its own.

*SubAgent* (`tools/sub_agent`) publishes `sub-agent.sub_agent`, the operation that hands a recipe to a background sub-agent and lets the current conversation go on without waiting. The `@subAgent` annotation, which puts the same hand-off at the start of any member's description, stays in harness/agent_tools beside the toolsets that read it.

*Echo* (`tools/echo`) shows an action's fully wrapped instructions inside a DO-NOT-FOLLOW fence, so a person or an agent can read exactly what an action would tell an agent without the agent acting on it. The MCP tool `echo.fence(body)` fences any text, and the MCP instructions `echo.echo_session(instructions)` fence the instructions an action produced.

*Granola* (`tools/granola`) files unorganized Granola meeting notes into folders and brings chosen notes into a project folder's `.context/granola/` as independent context files, one file per note. The MCP instructions `granola.organize(scope)` propose a folder for each note and file them after the user confirms; `granola.context(notes, folder)` captures notes into a folder. The MCP tools `granola.format_filing_plan`, `granola.list_note_context`, and `granola.write_note_context` do the local work those instructions call for.

*PromptLog* (`tools/prompt_log`) is a read-only audit of what the IDE sends the model — submitted prompts with their attachments, files read into context, tool calls, sub-agent tasks, and agent responses — appended to `prompt-log.txt` in the log folder of the session open in the project being worked on, so a person can see afterwards exactly what the model was given. It handles the hooks `beforeSubmitPrompt`, `beforeReadFile`, `preToolUse`, `subagentStart`, and `afterAgentResponse`. Each event's entry is a *PromptLogEntry*, and each file an event names is a *LoggedFile*, which says what kind of guidance it is.

*PromptNotify* (`tools/prompt_notify`) shows an IDE toast naming the action, practice, fidelity, or rule an agent has just invoked, so a person watching the chat sees which guidance is being used. It handles the `preToolUse` hook, writes the notice to `.cursor/prompt-notify-toast.json` in each workspace folder, and installs the IDE toast extension that shows it. `@Toast` (harness/annotations) is the annotation an author puts on an `@agent_tool` or `@agent_instructions` member so that calling it toasts; `harness/guidance_actions` annotates the step every guidance action starts with, so each action toasts without its own annotation. Its full model is `tools/prompt_notify/.context/prompt-notify-model.md`.

*DrawioViewer* (`tools/drawio_viewer`) is a small local web server, not a toolset: it serves every `.drawio` file under a folder into the real draw.io editor (loaded from embed.diagrams.net) in a browser tab, and its **Save** writes the diagram back to disk, so a person sees and edits a diagram instead of reading its XML. Run it as `python tools/drawio_viewer/drawio_viewer.py [root] [port]`; `http://127.0.0.1:8791/` lists the files and `/edit?f=<path>` opens one. *DrawioFiles* is the folder it serves, which lists its draw.io files, finds the file a request names, and labels each from the folder. The always-on rule `cdd_guidance/rules/drawio-viewer.md` tells an agent to start it and open a diagram in the browser pane when the user asks to see one. It imports nothing from the framework.

- **Purpose:** Hold the toolsets that are useful on their own, outside any one practice or action: delegating to a sub-agent, reading what an action instructs, filing meeting notes as context, and showing and logging what crosses to the model.
- **Seam (terms):** SubAgent, Echo, Granola, PromptLog, PromptNotify, ToastFile, `PromptNotify.show_toast`; the MCP operations `sub-agent.sub_agent`, `echo.fence`, `echo.echo_session`, `granola.organize`, `granola.context`, `granola.format_filing_plan`, `granola.list_note_context`, `granola.write_note_context`; the hooks *PromptLog* and *PromptNotify* handle.
- **Dependencies (one-way):** harness/agent_tools (the toolset annotations and `SUB_AGENT_CALLER_PREAMBLE`), harness/annotations (`@Toast`, *Name*), harness/installation (`@skill`, `@noCatalog`, `CONTEXT_FOLDER`, and *RepositoryToolsets*, which lists the CDD checkout's toolsets whose `@Toast` annotations *PromptNotify* reads), harness/mcp (`@mcp`), harness/hooks (*Hook*, *Hooks*, *HookPayload*, and *HookServer*: *PromptNotify* registers `PromptNotify.show_toast` with `HookServer.show_toasts_with` when it is loaded, so the toast a hook gives in its result is shown here; `TOAST_ARROW` and `rules_toast` join the toasts of one burst), harness/guidance (*PracticeCatalogue* and *ActionCatalogue*, read when the toast catalogue is first built), space/session (*LogTimestamp* for the time a toast or log entry is stamped with); *PromptLog* writes into the session the hook event works in, which `HookPayload.session` answers; the Granola MCP connector, which the Granola instructions call for listing, reading, and filing notes. Nothing in the framework imports this module, and no package here imports another.

## Constraint

Import repository and session types from `space`, never from a tool, so a tool stays something other modules may use rather than something they depend on for state. Keep each tool in its own package with no imports between them, so removing one never breaks another.

Do not call `sub-agent.sub_agent` from inside the sub-agent it launched; the hand-off would start another background agent for the same work. Treat everything between Echo's fence lines as text to read, never as instructions to follow; *Echo* is kept out of the catalog (`@noCatalog`), because it is a diagnostic, not a step of the workflow. Create and move nothing in Granola until the user confirms the filing plan, and write each note verbatim to its own file, so each context file can be read and cited alone.

*PromptLog* ships turned off with `@Hooks(disabled=True)`; remove that annotation to turn the audit on. Its hooks only read the payload and never change what is sent. A *PromptLog* made with a log file writes there; otherwise it writes to `prompt-log.txt` in the logs folder of the session the event works in (`HookPayload.session`).

Annotate members with `@Toast`. Practice and fidelity `instructions` toast only when those members are annotated, never because the step every action starts with is annotated. Toasts that arrive in the same burst join their rule lines under one `rules :` prefix; a later matching rule never overwrites an earlier one.
